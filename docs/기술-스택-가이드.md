## 0. 한눈에

| 시점 | 배울 것 | 크기 |
|---|---|---|
| **지금** — 코드를 읽으려면 | TypeScript · **NestJS** · Prisma · PostgreSQL | 중간 (코드가 이미 있어 읽으며 익힌다) |
| **4단계** — 실시간 | **Socket.IO** · Redis(개념만) | 작음 |
| **5단계** — 앱 | **Dart · Flutter · Riverpod** + 주변 패키지 | **가장 큼** |

**가장 큰 덩어리는 Dart/Flutter다.** 서버는 4단계까지, 앱은 5단계 슬라이스 2까지 올라와 있는데,
앞으로 남은 작업의 무게가 앱 쪽에 크게 실려 있다(채널 · 메시지 · 소켓 · 오프라인 캐시).
여기에 쓰는 학습 시간의 값이 가장 크다.

> 앱 코드는 이제 읽을 것이 있다. `app/lib/features/shell/app_shell.dart` 의 폭 분기와
> `features/auth/auth_controller.dart` 의 상태 전이가 Flutter·Riverpod 을 이해하는
> 가장 빠른 두 지점이다.

## 1. 서버 — 지금 코드를 읽기 위한 것

### TypeScript
서버 전체가 TS다. 제네릭 · 유니온 타입 · `satisfies` 정도까지 읽을 수 있으면 충분하다.

### NestJS — **가장 중요**
이 프로젝트 코드의 뼈대다. 다섯 가지만 이해하면 전체 구조가 열린다.

| 개념 | 이 프로젝트에서 하는 일 |
|---|---|
| **모듈** | 기능 단위 묶음. [`app.module.ts`](../server/src/app.module.ts)가 루트 |
| **DI(의존성 주입)** | `constructor(private prisma: PrismaService)` — 직접 `new` 하지 않는다 |
| **컨트롤러** | HTTP 라우트. `@Get(':spaceId/channels')` |
| **가드** | 요청을 통과시킬지 결정. **이 프로젝트의 보안 전체가 여기 있다** |
| **파이프 · 데코레이터** | 입력 검증(DTO), `@CurrentUser()` 같은 값 주입 |

> **가드를 이해하면 이 프로젝트의 절반은 이해한 것이다.**
> [`space.guard.ts`](../server/src/spaces/guards/space.guard.ts)(40줄)부터 읽기를 권한다.
> URL의 `:spaceId`에 대해 요청자가 그 스페이스의 멤버인지 매 요청 확인하고,
> 아니면 404를 던진다. 멀티테넌시 격리가 통째로 이 파일에 걸려 있다.

### Prisma
ORM. 스키마 파일 하나가 DB 구조와 타입의 원본이다.

- **스키마 문법** — [`schema.prisma`](../server/prisma/schema.prisma) (26개 모델)
- **마이그레이션** — `migrate dev` / `migrate deploy`의 차이
- **쿼리 API** — `findMany` · `include` · `select` · `upsert`
- **`$transaction`** — 여러 쓰기를 한 덩어리로 (예: 메시지 수정 + 이력 남기기)
- **`$queryRaw`** — Prisma로 표현이 안 될 때. [안 읽은 수 계산](../server/src/channels/channels.service.ts)이 이 경우다

> **함정**: Prisma는 `String @id @default(uuid())`를 `uuid`가 아니라 **`text`** 컬럼으로 만든다.
> raw SQL에서 `::uuid`로 캐스팅하면 `operator does not exist: text = uuid`로 실패한다. 실제로 겪었다.

### PostgreSQL
SQL 기본에 더해:

- **인덱스** — 왜 `(channel_id, created_at)`에 거는지
- **외래키 · `onDelete`** — `Cascade` vs `SetNull`. 카테고리를 지워도 채널이 남는 이유
- **enum · 트랜잭션 · `NUMERIC`**
- **커서 페이지네이션** — `OFFSET`을 쓰지 않는 이유(뒤 페이지가 느려지고, 새 글이 오면 밀린다).
  [`pagination.dto.ts`](../server/src/common/dto/pagination.dto.ts)

### 인증 개념
라이브러리 사용법보다 **왜 그렇게 했는지**가 중요하다.

- **argon2** — 비밀번호 해시. 왜 SHA-256이 아닌가(느리게 만드는 게 목적)
- **JWT** — 액세스(15분) / 리프레시(7일) 분리
- **토큰 회전 + 재사용 탐지** — [`refresh-token.service.ts`](../server/src/auth/refresh-token.service.ts).
  리프레시할 때마다 새 토큰을 주고 이전 것을 죽인다. 죽은 토큰이 다시 오면 탈취로 보고 세션 전체를 끊는다

## 2. 4단계 — 실시간

분량이 작다. 새로 배우는 건 사실상 Socket.IO 하나다.

### Socket.IO
- **룸(room)** — 핵심 개념. 채널마다 룸을 만들고 그 룸에만 브로드캐스트한다
- **핸드셰이크 인증** — 연결할 때 JWT를 확인. 쿼리스트링이 아니라 `auth.token`으로만 받는다(액세스 로그에 토큰이 남지 않도록)
- **이벤트 설계** — `message:new` · `rooms:sync` 등. 목록은 [백엔드 설계 §5](./백엔드-설계.md)

### Redis
지금은 **개념만** 알면 된다. 서버를 여러 대로 늘렸을 때 소켓 이벤트를 인스턴스 간에 퍼뜨리는
어댑터로 쓴다. 1대로 돌리는 동안은 없어도 동작한다.

## 3. 5단계 — Flutter 앱 (가장 큰 덩어리)

전체 목록은 [앱 설계 §2](./앱-설계.md)에 있다. 여기서는 **배우는 순서**를 정리한다.

### 배우는 순서

**① Dart** — 언어
TypeScript를 안다면 문법 자체는 며칠이면 붙는다. 낯선 것: `Future`/`async`, `Stream`,
null safety(`?`, `!`, `late`), `sealed class`.

**② Flutter** — UI
- 위젯 트리, `StatelessWidget` / `StatefulWidget`
- 레이아웃: `Column` · `Row` · `Expanded` · `Flexible`
- **`ListView.builder`** — 긴 채팅 목록의 핵심. 화면에 보이는 것만 그린다
- 반응형 — 하나의 코드로 모바일/데스크톱 레이아웃 분기

> React를 써 보셨다면 사고방식이 닮아 있다(선언형 UI, 상태가 바뀌면 다시 그림).
> 큰 차이는 **HTML/CSS가 없고 전부 위젯**이라는 점이다.

**③ Riverpod** — 상태 관리
Flutter 다음으로 중요하다. 화면과 데이터를 잇는 축이라, 여기 구조가 앱 전체 구조가 된다.
`Provider` · `FutureProvider` · `StreamProvider` · `Notifier`.

**④ 나머지는 필요할 때**

| 패키지 | 역할 | 낯설 수 있는 점 |
|---|---|---|
| **go_router** | 라우팅 | 웹 URL·딥링크까지 함께 다룬다 |
| **dio** | HTTP | **인터셉터**로 401을 잡아 토큰을 자동 갱신 |
| **socket_io_client** | 실시간 | 서버와 같은 프로토콜 |
| **freezed** + json_serializable | 불변 모델 | **코드 생성기**(`build_runner`)를 돌린다. `.g.dart` 파일이 자동 생성되는 방식이 처음엔 낯설다 |
| **drift** | 로컬 SQLite | 6단계 오프라인 캐시. 역시 코드 생성 |
| **flutter_secure_storage** | 토큰 저장 | Keychain/Keystore |

## 4. 7단계 이후 — 그때 배우면 되는 것

| 기술 | 언제 | 비고 |
|---|---|---|
| S3 호환 스토리지 (MinIO · R2) | 첨부 | presigned URL 개념 |

| Jest · ESLint · GitHub Actions | 테스트·CI | **지금 전무하다.** 전환 계획 §5 |

## 5. 도구

- **Git** — 브랜치 · 커밋. 작업 브랜치는 `feat/pivot-nexus`
