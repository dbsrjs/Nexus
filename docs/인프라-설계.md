# Nexus — 인프라 설계서

> 작성: 2026-08-13 · **개정: 2026-09-23** — Redis 를 쓰지 않게 된 것(§2 · §4), PR 프록시 전환(§3), 보안 체크리스트 진행 상황(§6)을 반영했다. **배포는 아직 하지 않았다.**
> **전제: 포트폴리오로 운영하는 동안 월 비용 0원.** 이 제약이 아키텍처 선택의 1순위 기준이다.
> 관련: [백엔드 설계](./백엔드-설계.md) · [앱 설계](./앱-설계.md)

## 1. 가장 중요한 제약 — 상시 연결

Nexus는 실시간 채팅이 중심이라 **WebSocket 상시 연결**이 필수다. 그런데 대부분의 무료 PaaS는 트래픽이 없으면 인스턴스를 재우고(scale-to-zero), 깨어나는 데 수십 초가 걸린다.

채팅 앱에서 이건 치명적이다. 소켓이 끊기고, 포트폴리오 데모 링크를 처음 누른 사람이 흰 화면을 오래 본다.

> **결론: scale-to-zero 계열은 후보에서 제외한다. 상시 구동되는 VM 한 대를 확보하는 방향으로 간다.**

## 2. 구성

`server/docker-compose.yml`이 postgres 를 기본으로, redis · minio 를 프로필(`--profile redis` · `--profile s3`) 뒤에 정의하고 있다. **이 파일이 배포 구성의 기반이 된다** — 다만 지금 빌드는 **Postgres 하나만** 쓴다(§4).

```
              Cloudflare Tunnel  (HTTPS · 고정 IP 불필요 · 포트 개방 불필요)
                      │
        ┌─────────────┴──────────────┐
        │        VM (상시 구동)       │
        │  ┌──────────────────────┐  │
        │  │ NestJS               │  │
        │  │ PostgreSQL + pgvector│  │
        │  │  (데이터 · 벡터 · 큐) │  │
        │  └──────────────────────┘  │
        └─────────────┬──────────────┘
                      │
        ┌─────────────┴──────────────┐
        │  Cloudflare R2  (첨부 파일) │
        │  LLM API        (무료 티어) │
        └────────────────────────────┘

  Flutter Web  →  정적 호스팅 (Cloudflare Pages / GitHub Pages)
```

| 구성요소 | 선택 | 이유 |
|---|---|---|
| **서버 VM** | Oracle Cloud **Always Free** (ARM Ampere) | 무료 티어 중 사양이 압도적. 아래 4개 프로세스를 한 대에 올려도 여유가 있다 |
| **PostgreSQL** | 같은 VM의 Docker + **pgvector** | 외부 DB 서비스 불필요. RAG 인덱스도 여기 얹는다 |
| ~~**Redis**~~ | — | **쓰지 않는다** (§4) |
| **파일 저장** | **Cloudflare R2** | **egress 무료**가 결정적. 무기한 보관 정책과 궁합이 맞는다. `S3Driver` 는 배포 때 붙인다 — 지금 구현은 로컬 디스크 하나 |
| **HTTPS · 공개 URL** | **Cloudflare Tunnel** | 고정 IP · 인증서 · 방화벽 포트 개방이 전부 불필요. GitHub 웹훅 수신도 이걸로 해결 |
| **LLM · 임베딩** | 무료 티어 제공 provider | 인터페이스 뒤에 두고 언제든 교체 (백엔드 §8.2) |
| **Flutter 웹** | Cloudflare Pages 또는 GitHub Pages | 정적 파일이라 어디든 무료 |
| **CI** | GitHub Actions | 공개 저장소는 무제한 |
| **가동 감시** | UptimeRobot 등 무료 티어 | |

> **무료 티어 조건은 자주 바뀐다.** 위 서비스들의 현재 약관은 착수 시점에 직접 확인할 것. 특히 Oracle Cloud는 리전에 따라 ARM 인스턴스 재고가 없을 때가 있고, 계정 승인이 까다롭기로 알려져 있다.

### 대안 조합 (VM 확보 실패 시)

관리형 서비스를 조합하는 방식. Postgres·Redis·오브젝트 스토리지를 각각 무료 티어로 붙이고 서버만 별도 호스팅한다.

**단점이 분명하다** — 쿼터가 여러 서비스에 흩어져 관리 지점이 늘고, 무엇보다 **서버 호스팅의 슬립 여부를 개별 확인**해야 한다. §1의 제약이 그대로 살아 있다. 차선책으로만 둔다.

## 3. 무료 전제가 설계에 미친 영향

무료 제약은 단순한 배포 이슈가 아니라 **백엔드 설계를 바꿨다.**

| 설계 결정 | 무료 제약과의 관계 |
|---|---|
| **RAG 필수화** (`repo_index_chunks`) | 무료 LLM 티어는 토큰·요청 한도가 빡빡하다. 저장소를 통째로 넣는 방식은 **첫 질문에 하루치 쿼터를 태운다.** RAG는 "있으면 좋은 것"이 아니라 무료로 돌리기 위한 전제다 |
| **AI 응답 캐싱** (`ai_runs.prompt_hash`) | 동일 질의 재사용. 쿼터를 늘리는 가장 싼 방법 |
| **pgvector** (별도 벡터 DB 대신) | 인프라를 한 대 더 띄우면 무료 운영이 깨진다. 인덱싱 대상이 내 저장소 몇 개 수준이라 확장으로 충분 |
| **저장소 열람 = 프록시** (백엔드 §7.3) | 코드 사본을 저장하지 않으니 디스크·동기화 비용이 0 |
| ~~**PR = DB upsert**~~ → **PR 도 프록시** (11단계) | 사본이 어긋날 위험이 비용보다 컸다. 인증 상태 rate limit(시간당 5000회)에 개인 사용량으로는 닿지 않는다 |
| **큐 = Postgres 테이블** (12 · 13-1) | 인덱싱 · AI 큐를 `FOR UPDATE SKIP LOCKED` 로 DB 에 둬 Redis 를 띄우지 않는다 |
| **Cloudflare R2** | 다운로드 트래픽이 무료라 "오래 쌓아두고 가끔 꺼내 보는" 무기한 보관 패턴에 최적 |

## 4. Redis는 쓰지 않는다

처음 잡은 Redis 용도는 셋이었고, 지금은 전부 다른 곳이 맡는다.

| 용도 | 지금 |
|---|---|
| Socket.IO 멀티 인스턴스 fan-out | 인스턴스가 하나라 불필요. 기본 인메모리 어댑터. `redis-io.adapter.ts` 는 빌드에서 빼 두었다 |
| 프레즌스 | 아직 없다. 단일 인스턴스면 메모리로 충분하다 |
| AI · 인덱싱 작업 큐 | **Postgres 테이블**(`ai_runs` · 인덱싱 큐) + `FOR UPDATE SKIP LOCKED` 리스 |
| 프록시 캐시 | **두지 않는다**(10-3a) — 방금 push 한 것을 보려는 순간이 캐시가 옛것을 보이는 순간이다 |

> ~~코드는 처음부터 Redis가 있다는 전제로 짠다~~ → **뒤집었다(12단계).** 비용은 배포가
> 아니라 **새 PC 셋업**에서 났다 — 개발 PC 마다 띄워야 할 것이 하나 늘고, WSL 배포판과
> 함께 죽는 것이 하나 는다. 인스턴스를 늘려야 할 때 들인다.

## 5. 피할 수 없는 비용

**앱 스토어 배포만큼은 무료 경로가 없다.**

| 항목 | 비용 | 판단 |
|---|---|---|
| Apple App Store | **연 $99** | **쓰지 않는다.** 시뮬레이터 시연 영상으로 대체 |
| Google Play | **1회 $25** | **쓰지 않는다.** APK 직접 배포 |
| 커스텀 도메인 | 연 $10~15 | 보류. 무료 서브도메인으로 시작 |
| 데스크톱 코드 서명 | 연 $100~ | 쓰지 않는다. 미서명 배포(설치 시 경고) |

포트폴리오에서 평가되는 것은 대개 ① 라이브 데모 링크 ② 저장소 ③ 시연 영상이다. **Flutter 웹 배포 + APK 다운로드 링크 + 데스크톱 빌드 아티팩트**면 "단일 코드베이스 멀티 플랫폼"이라는 주장은 충분히 증명된다.

> 유료 전환이 필요해지는 시점은 **Phase 1에서 외부 사용자를 실제로 받을 때**다. 그때 도메인과 Play 등록($25 1회)부터 검토한다.

## 6. 공개 저장소이므로 반드시 지킬 것

포트폴리오는 저장소를 공개한다는 뜻이다. 아래는 협상 대상이 아니다.

- [x] `.env.example`에서 `change-me` 류의 값을 **전부 제거**한다. 필수 시크릿은 빈 값이고 `npm run env:setup` 이 PC 마다 새로 만든다
- [x] `JWT_SECRET` 미설정 시 **부팅을 실패**시킨다 (백엔드 §6, `resolveJwtSecrets()`)
- [ ] `docker-compose.yml`의 기본 비밀번호를 환경변수로 뺀다 — 개발용 `nexus` / `minioadmin` 이 남아 있다. **배포용 `docker-compose.prod.yml` 에서 해결한다**(§7)
- [x] CORS를 **환경변수 화이트리스트**로 제한한다 (`CORS_ORIGINS`, 비면 전부 차단)
- [x] 소켓 토큰의 **쿼리스트링 경로를 제거**한다 (`handshake.auth.token` 만)
- [x] provider OAuth 토큰과 LLM API 키는 **서버 밖으로 절대 나가지 않는다** — OAuth 토큰은 `OAUTH_TOKEN_KEY` 로 암호화 저장, GitHub 의 `download_url` 같은 토큰 필요 주소도 응답에서 뺀다
- [ ] 데모 스페이스에 실제 개인정보를 넣지 않는다. 시드 데이터로만 채운다 — 배포 때 확인

> 처음 다섯 항목은 [전환 계획 §3.5](./전환-계획.md)의 결함 목록과 겹치고, 비밀번호 하나를 빼면 전부 해결됐다.

## 7. 배포 절차 (착수 시 작성)

VM 확보 후 아래를 문서화한다. 지금은 항목만 잡아 둔다.

1. VM 프로비저닝 · SSH 키 · 방화벽
2. Docker · Compose 설치, `docker-compose.prod.yml` 작성 (기본 비밀번호 제거판)
3. Cloudflare Tunnel 연결 → 공개 HTTPS 엔드포인트 확보
4. R2 버킷 생성 · S3 호환 자격 증명 발급 · **수명주기 규칙 미설정 확인** (무기한 보관의 실질 보장)
5. GitHub Actions → 빌드 → VM 배포 파이프라인
6. Postgres 백업 (`pg_dump` → R2, 일 1회)
7. UptimeRobot 등록
