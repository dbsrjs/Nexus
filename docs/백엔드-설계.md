# ONE 워크스페이스 — 백엔드 설계서 (Phase 1)

> 사내 메신저 통합 솔루션의 서버/DB 설계. 프론트엔드(웹 · Electron · Capacitor)는 이미 구현됨.
> 이 문서는 구현 착수 전 **정렬용 기준 문서**다. 확정된 결정만 반영한다.

## 1. 확정된 기술 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| 백엔드 프레임워크 | **NestJS** (TypeScript) | 프론트와 동일 언어, 모듈 구조, WebSocket 내장 |
| 호스팅 | **사내 온프렘** | 소스·로그·파일이 사내망에만 머무름 |
| RDB | **PostgreSQL** | 사용자·채널·메시지·이슈·일지·권한 |
| 캐시/실시간 | **Redis** | 프레즌스, Socket.IO 어댑터(다중 인스턴스), 큐 |
| 파일 저장 | **MinIO** (S3 호환, 온프렘) | "영구 보관" 요구 — 만료 없음. 메타는 DB |
| 실시간 | **Socket.IO** | 채팅·알림·보드 라이브 |
| 인증 | **자체 이메일+비밀번호 + JWT** | SSO/LDAP는 미선택(추후 교체 가능하게) |
| AI | **보류** | 엔드포인트 스텁만. 코드 외부유출 이슈로 추후 결정 |
| 이슈 | **자체 구현** | Redmine 보류 → `IssueProvider` 인터페이스로 추상화해 추후 교체 |
| 외부 연동 | **GitLab(읽기 전용)** | 저장소·브랜치·커밋 동기화 |
| 공지 | **자체 구현** | 아지트 연동 미선택 |

## 2. 모듈 구조 (NestJS)

```
server/
├─ src/
│  ├─ auth/            # 로그인, JWT, 가드, 역할 데코레이터
│  ├─ users/           # 사용자, 프로필, 상태(온라인)
│  ├─ channels/        # 채널·DM, 멤버십, 채널별 권한
│  ├─ messages/        # 메시지 CRUD, 수정 이력, 실시간 게이트웨이
│  ├─ files/           # 업로드/다운로드, MinIO 연동, 영구 보관
│  ├─ issues/          # 자체 이슈 보드 (IssueProvider 추상화)
│  ├─ worklogs/        # 업무일지
│  ├─ attendance/      # 근태(출퇴근 체크인)
│  ├─ notices/         # 공지
│  ├─ notifications/   # 알림 + 실시간 푸시
│  ├─ permissions/     # 역할/채널 권한 정책(가드에서 사용)
│  ├─ gitlab/          # GitLab API 클라이언트(읽기 전용)
│  ├─ ai/              # 스텁(501 Not Implemented / 준비중 응답)
│  ├─ realtime/        # Socket.IO 게이트웨이 공통(인증, 룸)
│  └─ common/          # 예외필터, 인터셉터, 페이지네이션, config
├─ prisma/ (or typeorm)# 스키마/마이그레이션
└─ docker-compose.yml  # postgres + redis + minio (사내 서버 기동용)
```

ORM은 **Prisma** 권장(스키마-우선, 마이그레이션 명확). TypeORM도 가능.

## 4. REST API 계약 (주요)

> 모두 `/api` prefix, JWT Bearer. 페이지네이션은 `?cursor=&limit=`.

```
POST   /api/auth/login            { email, password } → { token, user }
POST   /api/auth/refresh
GET    /api/me

GET    /api/channels              내가 볼 수 있는 채널/DM (권한 필터링)
GET    /api/channels/:id/messages 커서 기반
POST   /api/channels/:id/messages { body } (can_send 가드)
PATCH  /api/messages/:id          { body } → 수정 이력 기록(본인만)
GET    /api/messages/:id/edits

POST   /api/channels/:id/files    multipart 업로드 → MinIO, files row
GET    /api/files/:id             다운로드(서명 URL 또는 스트리밍)

GET    /api/issues                ?status= 보드용 컬럼별
POST   /api/issues
PATCH  /api/issues/:id            상태/담당자 변경
POST   /api/issues/:id/comments

GET    /api/worklogs  · POST /api/worklogs
GET    /api/attendance · POST /api/attendance/check-in · POST /check-out

GET    /api/notices
GET    /api/notifications · POST /api/notifications/:id/read

GET    /api/admin/permissions     역할×채널 매트릭스 (admin 전용)
PUT    /api/admin/permissions/:channelId/:role { can_view, can_send }

GET    /api/gitlab/repos          GitLab 동기화된 저장소 목록
POST   /api/gitlab/sync           수동 동기화 트리거

POST   /api/ai/analyze            → 501 (스텁, "AI 준비 중")
```

## 5. 실시간 이벤트 (Socket.IO)

- 연결 시 JWT 인증 → 사용자가 속한 채널 룸(`channel:{id}`)에 join.
- 서버→클라 이벤트:
  - `message:new`, `message:edited`
  - `notification:new`
  - `issue:updated`
  - `presence:changed`
- 클라→서버: `typing`(선택), `read`(last_read_at 갱신).

## 6. 인증·권한 흐름

1. 이메일+비밀번호 → argon2 검증 → JWT(access 짧게 + refresh).
2. `RolesGuard`(전역 역할) + `ChannelPermissionGuard`(채널별 view/send) 데코레이터.
3. 디자인의 "권한 미리보기"는 프론트 전용 시뮬레이션 → 실제 서버는 로그인 사용자의 실제 역할로 강제.
4. admin만 권한 매트릭스 수정 가능.

## 7. GitLab 연동 (읽기 전용)

- 사내 GitLab의 Personal/Project Access Token을 서버 환경변수로 보관.
- 주기적(cron) 또는 수동 동기화로 `gitlab_repos` 갱신.
- AI 보류 상태이므로 **저장소 목록/브랜치/최근 커밋 표시**까지만. 코드 임베딩/분석은 AI 단계에서.

## 8. 보류·후속 (Phase 2+)

- **AI 코드 분석**: GitLab 코드 + 로그 → RAG → LLM. 코드 외부유출 정책 확정 후. 현재 프론트의 `genAI()`는 목업 유지.
- **Redmine 연동**: `IssueProvider`를 native→redmine으로 교체.
- **아지트 공지 연동**, **SSO/LDAP**.
- **모바일 푸시**: FCM(Android)/APNs(iOS) — Capacitor Push.
- **파일 바이러스 검사**, **감사 로그**, **백업 정책**(영구 보관 데이터).

## 9. 구현 순서 (제안)

1. 프로젝트 스캐폴드 + docker-compose(postgres/redis/minio) + Prisma 스키마 + 마이그레이션 + 시드(디자인 목업 데이터 이식).
2. auth + users + 권한 가드.
3. channels + messages + Socket.IO 실시간.
4. files(MinIO) 업로드/다운로드.
5. issues + worklogs + attendance + notices + notifications.
6. gitlab 동기화 + ai 스텁.
7. 프론트(www) 목업 → 실제 API 연동 교체.
