## 1. 기술 결정

| 항목 | 결정 | 이전 대비 |
|---|---|---|
| 프레임워크 | **NestJS 10** (TypeScript) | 유지 |
| RDB | **PostgreSQL** + Prisma | 유지 |
| 캐시 · 실시간 | **Redis** (프레즌스 · Socket.IO 어댑터 · 큐 · 프록시 캐시) | 유지 |
| 실시간 | **Socket.IO** | 유지 |
| 파일 저장 | **S3 호환 추상화** (개발: MinIO 컨테이너 / 운영: Cloudflare R2) | 온프렘 MinIO 고정 → **교체 가능** |
| 호스팅 | **클라우드 전제**, 온프렘 배포도 가능 | 온프렘 고정 → 변경 |
| 인증 | 이메일+비밀번호(argon2) + **회원가입** + **GitHub OAuth** | 가입 흐름 신설 |
| 테넌시 | **Space 단위 멀티테넌트** | 단일 테넌트 → **전면 변경** |
| 이슈 | 자체 구현 (`IssueProvider` 유지) + **스프린트 · 추정 · 정렬** | 단순 칸반 → 애자일 보드 |
| 저장소 연동 | **GitHub · GitLab** 웹훅 + 폴링 + **열람 프록시** | GitLab 읽기 전용 → 확장 |
| 코드 검색 | **pgvector** (같은 Postgres의 확장) | **신규** — AI 코드 질의의 전제 조건 |
| AI | **실제 기능** (외부 LLM API, RAG 경유) | 501 스텁 → **승격** |

> **왜 NestJS를 유지하는가**: TypeScript · PostgreSQL · Redis · Socket.IO 조합은 이 도메인에서 가장 보편적인 선택이고, 이미 동작하는 구현이 있다. 프레임워크를 바꿔서 얻는 것보다 잃는 것이 크다.

> **왜 pgvector인가**: 별도 벡터 DB(Pinecone · Qdrant)를 띄우면 인프라가 한 대 늘고 무료 운영이 깨진다. 인덱싱 대상이 내 저장소 몇 개 수준이라 Postgres 확장으로 충분하다. 자세한 근거는 [인프라 설계서](./인프라-설계.md).

## 2. 멀티테넌시 — 가장 중요한 변경

이전 스키마는 채널 목록이 전역이고 사용자 역할이 전역 enum이었다. 조직이 하나라는 전제였다. **Space를 도입해 모든 데이터에 테넌트 경계를 긋는다.**

```
Space (테넌트 루트)
 ├─ SpaceMember   (User × Space, 역할은 여기에)
 ├─ Invite
 ├─ Category
 │   └─ Channel
 │       ├─ ChannelMember       (읽음 마커)
 │       ├─ ChannelPermission   (역할별 view/send)
 │       └─ Message
 │           ├─ Message (parentId — 스레드 답글)
 │           ├─ MessageEdit
 │           ├─ Reaction
 │           ├─ Mention
 │           └─ Attachment
 ├─ Sprint
 ├─ IssueLabel
 ├─ Issue → IssueComment
 ├─ Repo  → RepoEvent · PullRequest · RepoIndexChunk
 └─ AiRun
```

### 격리 규칙 (반드시 지킨다)

1. **테넌트 소속 테이블은 예외 없이 `spaceId` 컬럼을 갖는다.** 부모를 타고 유추 가능해도 비정규화해서 직접 들고 있는다 — 모든 쿼리의 `WHERE`에 강제로 넣기 위함이다.
2. 모든 서비스 메서드는 `spaceId`를 **첫 인자로** 받는다. 옵션이 아니다.
3. `SpaceGuard`가 URL의 `:spaceId`에 대한 요청자의 멤버십을 검증하고 `req.spaceMember`에 실어 준다. 컨트롤러는 이후 신뢰한다.
4. Phase 2 착수 전, **"A 스페이스 사용자가 B 스페이스 리소스에 접근하면 404"** 를 모든 엔드포인트에 대해 확인하는 통합 테스트를 둔다.

## 3. 데이터 모델

`id`는 uuid, `created_at`/`updated_at`은 공통이므로 표기 생략.

### 계정 · 테넌트

**users** — 전역 계정
`email unique, password_hash(nullable — OAuth 전용 계정), name, avatar_url, global_status(online/away/offline)`

**oauth_accounts** — 소셜 로그인 연결
`user_id FK, provider(github/gitlab), provider_user_id, access_token(암호화), UNIQUE(provider, provider_user_id)`

> 저장소 연동에 쓸 토큰을 여기서 함께 확보한다. GitHub 로그인 → 저장소 연결이 추가 인증 없이 이어진다.

**refresh_tokens** — 리프레시 토큰 회전 · 재사용 탐지
`user_id FK, family_id, token_hash unique, expires_at, revoked_at, replaced_by_id, user_agent, ip`
인덱스 `(user_id)`, `(family_id)`

> §6이 요구하는 "회전 + 재사용 탐지"는 **상태 저장 없이 성립하지 않는다.** JWT만으로는 이미 쓴 리프레시 토큰을 무효화할 방법이 없다.
> 한 번의 로그인이 하나의 `family`를 만든다. 회전할 때마다 이전 행을 `revoked_at` 으로 닫고 같은 family 로 새 행을 만든다. **이미 닫힌 토큰이 다시 제시되면 탈취로 보고 family 전체를 무효화**한다 — 정상 클라이언트는 회전된 토큰을 다시 쓰지 않는다.
> 원문이 아니라 SHA-256 해시를 저장한다. DB가 유출돼도 토큰이 즉시 쓰이지는 않는다.

**spaces**
`slug unique, name, icon_url, owner_id FK, plan enum(free|pro) default free, storage_used_bytes bigint default 0, storage_quota_bytes bigint null`

> `storage_used_bytes`는 첨부 업로드·삭제와 **같은 트랜잭션 안에서** 증감시킨다. `storage_quota_bytes`가 `null`이면 무제한이고, 이것이 Phase 0·1의 기본값이다. (스토리지 정책은 아래 참조)

**space_members**
`space_id FK, user_id FK, role enum(owner|admin|member|guest), nickname, joined_at` · PK `(space_id, user_id)`

**invites**
`space_id FK, code unique, created_by FK, role(가입 시 부여), expires_at, max_uses, use_count`

### 채널 · 메시지

**categories**
`space_id FK, name, position`

**channels**
`space_id FK, category_id FK null, key, name, topic, kind enum(text|dm), is_private, position` · UNIQUE `(space_id, key)`

**channel_members**
`channel_id FK, user_id FK, last_read_at, last_read_message_id, muted` · PK `(channel_id, user_id)`

**channel_permissions**
`channel_id FK, role, can_view, can_send` · PK `(channel_id, role)`

**messages**
`space_id FK, channel_id FK, author_id FK, body, parent_id FK null(스레드), reply_count, last_reply_at, quoted_message_id FK null(답장), pinned, edited_at, deleted_at`
인덱스: `(channel_id, created_at)`, `(parent_id)`

> `parent_id`가 `null`이면 채널 최상위 메시지, 값이 있으면 그 메시지의 스레드 답글이다. 채널 리스트는 `parent_id IS NULL`만 조회한다.
>
> `quoted_message_id`는 **다른 축**이다(답장/인용, 7-3). 스레드 답글은 타임라인에서 빠지지만 답장은 남는다 — 그래서 `parent_id`를 재사용할 수 없다. 둘을 함께 쓸 수도 있다(스레드 안에서 특정 답글을 인용). 인용은 **한 겹만** 펼쳐 요약(`id · body · authorName · deleted`)으로 내려보내며, 같은 채널의 메시지만 인용할 수 있다.

**message_edits** — 수정 전 본문 이력
`message_id FK, prev_body, edited_at`

**reactions**
`message_id FK, user_id FK, emoji` · PK `(message_id, user_id, emoji)`

**mentions**
`message_id FK, user_id FK null, type enum(user|channel|everyone)`
인덱스 `(user_id, message_id)` — 읽지 않은 멘션 뱃지 계산용

### 첨부 · 스토리지 정책

**attachments** (구 `files`)
`space_id FK, channel_id FK, message_id FK null, uploader_id FK, name, ext, mime, size_bytes, storage_key, width, height`
인덱스 `(space_id, created_at)`, `(channel_id)`

#### 무기한 보관 — 제품 특성으로 유지한다

**Nexus는 업로드된 파일을 만료시키지 않는다.** 이전 스키마의 `retained` 불리언은 "만료가 기본이고 예외적으로 보관"이라는 의미라 방향이 반대였다. 플래그는 제거하되 **정책 자체는 강화**해서 아래로 못 박는다.

| 상황 | 첨부 처리 |
|---|---|
| 메시지 소프트 삭제(`deleted_at`) | **유지.** 본문만 가려지고 파일은 남는다 |
| 메시지 하드 삭제 | 첨부도 삭제 |
| 채널 삭제 | **유지.** `channel_id`는 남기고 스페이스 파일 목록에서 계속 접근한다 |
| 스페이스 삭제 | 30일 유예 후 오브젝트 스토리지에서 일괄 삭제 |
| 오브젝트 스토리지 | **수명주기 규칙(lifecycle rule)을 설정하지 않는다.** 이것이 "무기한"의 실질적 보장이다 |

- 업로드는 `message_id = null` 상태로 먼저 생성되고, 메시지 전송이 성공하면 연결된다. 연결되지 못한 고아 첨부는 **24시간 뒤 정리**한다. 이것이 시스템의 **유일한 자동 삭제**다.
- 쿼터 검사는 `storage_quota_bytes IS NOT NULL`일 때만 수행한다. Phase 2 전까지는 코드 경로 자체를 타지 않는다.

### 이슈 · 애자일 보드

**issues**
`space_id FK, key(SPACE-138), title, description, status enum(backlog|doing|review|done), priority enum(low|mid|high), assignee_id FK null, sprint_id FK null, parent_id FK null, story_points int null, position numeric, source enum(native|github|gitlab), external_id, origin_message_id FK null, closed_at`
UNIQUE `(space_id, key)` · 인덱스 `(space_id, status, position)`, `(sprint_id)`

> - **`position`** — 칸반 카드의 정렬 순서. 이게 없으면 드래그 앤 드롭이 성립하지 않는다. `numeric`으로 두고 두 카드 사이에 넣을 때 중간값을 부여하면 재정렬 쓰기가 **1건**으로 끝난다. 간격이 소진되면 해당 컬럼만 재채번한다.
> - **`parent_id`** — 에픽 → 스토리 **1단계**만. 임의 깊이 트리는 만들지 않는다.
> - **`closed_at`** — 번다운 차트의 유일한 입력. 상태 전이 이력 테이블은 두지 않는다.
> - **`origin_message_id`** — "대화 → 이슈"의 역방향 링크.

**issue_labels** — 이전의 `label` 문자열 1개를 대체
`space_id FK, name, color` · UNIQUE `(space_id, name)`

**issue_label_links**
`issue_id FK, label_id FK` · PK `(issue_id, label_id)`

**sprints**
`space_id FK, name, goal, starts_at, ends_at, state enum(planned|active|closed)`

> 스페이스당 `active` 스프린트는 **1개**로 제한한다. `sprint_id IS NULL`인 이슈의 집합이 곧 백로그다.

**issue_comments**
`issue_id FK, author_id FK, body`

> **의도적으로 만들지 않는 것**: 커스텀 보드 컬럼(`status`는 enum 4종 고정), 상태 전이 이력, 워크플로 자동화 규칙, 벨로시티 자동 계산. 혼자 쓰는 Phase 0에서 비용 대비 가치가 없다. 컬럼 커스터마이즈는 Phase 2에 `board_columns`로 승격할 여지만 남긴다.

### 저장소 연동

**repos**
`space_id FK, provider enum(github|gitlab), external_project_id, name, full_path, default_branch, linked_channel_id FK null, webhook_secret, synced_at, indexed_at, indexed_commit_sha`

**repo_events** — 채널 피드로 흘려보낸 **이벤트 로그** (append-only)
`repo_id FK, type(push|pr|issue|release), payload jsonb, message_id FK null, occurred_at`

**pull_requests** — PR의 **현재 상태** (이벤트로 upsert)
`space_id FK, repo_id FK, number, title, body, state enum(open|merged|closed), draft, author_login, author_avatar_url, source_branch, target_branch, additions, deletions, changed_files, comment_count, review_state enum(pending|approved|changes_requested) null, external_url, opened_at, merged_at, closed_at`
UNIQUE `(repo_id, number)` · 인덱스 `(space_id, state)`

> **`repo_events`만으로는 PR 목록을 만들 수 없다.** 이벤트 로그는 append-only라 같은 PR의 open → review → merge가 각각 별개 행으로 쌓일 뿐, "지금 열려 있는 PR"을 질의할 방법이 없다. 웹훅 수신 시 `repo_events` 적재와 **별도로** 이 테이블을 upsert한다.
> diff 본문과 리뷰 코멘트는 **저장하지 않는다.** 조회 시점에 provider API로 프록시한다(§7).

**repo_index_chunks** — AI 코드 질의용 벡터 인덱스
`repo_id FK, path, lang, start_line, end_line, content text, embedding vector(768), commit_sha`
인덱스: `embedding`에 HNSW, `(repo_id, path)`

> AI 코드 질의(§8)는 **이 테이블 없이 성립하지 않는다.** 저장소를 통째로 프롬프트에 넣는 것은 토큰 한도상 불가능하며, 무료 LLM 티어에서는 질문 한 번에 하루치 쿼터가 소진된다.

### 알림 · AI

**notifications**
`space_id FK, user_id FK, type, payload jsonb, read` · 인덱스 `(user_id, read)`

**ai_runs** — 비동기 작업 상태 + 사용량 추적
`space_id FK, user_id FK, kind(summarize|ask|draft_issue), state enum(queued|running|done|failed), prompt_hash, prompt_tokens, completion_tokens, model, result jsonb, error, created_at, finished_at`
인덱스 `(space_id, created_at)`, `(prompt_hash)`

> `prompt_hash` — 동일 질의의 결과를 재사용하기 위한 캐시 키. 무료 LLM 티어를 오래 쓰는 데 가장 효과가 큰 한 수다.

### 제거되는 테이블

`attendance`, `worklogs`, `notices`, `gitlab_repos`(→ `repos`로 대체)

## 4. REST API 계약

모두 `/api` prefix. 인증은 Bearer JWT. 페이지네이션은 `?cursor=&limit=`.

### 인증 · 계정 (스페이스 무관)
```
POST   /api/auth/signup             { email, password, name }
POST   /api/auth/login              → { accessToken, refreshToken, user }
POST   /api/auth/refresh
POST   /api/auth/logout
GET    /api/auth/github             GitHub OAuth 시작
GET    /api/auth/github/callback
GET    /api/me
PATCH  /api/me
```

> **전역 사용자 목록(`GET /api/users`)은 두지 않는다.** 멀티테넌트에서 전역 디렉터리는 다른 스페이스의 사용자까지 노출하는 경로다. 사람 목록은 `GET /api/spaces/:spaceId/members` 로만 얻는다.
>
> `client: 'web'` 으로 호출하면 리프레시 토큰을 `HttpOnly` 쿠키로만 내려보내고 응답 바디에서 뺀다. 바디로도 함께 주면 `HttpOnly` 로 얻는 이점이 사라진다. 네이티브는 보안 저장소를 쓰므로 바디로 받는다.

### 스페이스
```
GET    /api/spaces                  내가 속한 스페이스 목록
POST   /api/spaces                  { name, slug }
GET    /api/spaces/:spaceId
PATCH  /api/spaces/:spaceId         (admin+)
GET    /api/spaces/:spaceId/members
PATCH  /api/spaces/:spaceId/members/:userId   역할 변경 (admin+)
DELETE /api/spaces/:spaceId/members/:userId   추방 (admin+)
POST   /api/spaces/:spaceId/invites           초대 코드 발급
POST   /api/invites/:code/accept              초대 수락 (스페이스 밖에서 호출)
```

### 채널 · 메시지
> 이하 모두 `/api/spaces/:spaceId` 하위. `SpaceGuard` 적용.

```
GET    /api/spaces/:spaceId/categories
GET    /api/spaces/:spaceId/channels          내가 볼 수 있는 채널 (권한 필터)
POST   /api/spaces/:spaceId/channels
PATCH  /api/spaces/:spaceId/channels/:id
GET    /api/spaces/:spaceId/channels/:id/messages     ?cursor= (parent_id IS NULL)
POST   /api/spaces/:spaceId/channels/:id/messages     { body, parentId? }
POST   /api/spaces/:spaceId/channels/:id/read         { lastReadMessageId }
PATCH  /api/spaces/:spaceId/messages/:id              본인만

```

> `DELETE /messages/:id` 는 **소프트 삭제**다. 본문만 가려지고 행과 첨부는 남는다. 삭제된 메시지는 목록에서 빼지 않고 본문을 빈 문자열로 바꿔 내려보낸다 — 빼 버리면 클라이언트가 이미 그린 메시지를 지울 근거가 없어 화면에 남는다. 작성자 본인 또는 admin 이상이 지울 수 있다.
>
> **읽음 기준 시각은 클라이언트 시계가 아니라 `lastReadMessageId` 가 가리키는 메시지의 `created_at`** 이다. 기기 시계가 틀어져 있어도 읽음 위치가 어긋나지 않는다. 뒤로 되돌리지도 않는다 — 여러 기기의 읽음이 엇갈려 들어와도 더 최근 위치가 유지된다.

## 6. 인증 · 권한

### 토큰
- access(15분) + refresh(7일). refresh는 회전(rotation)시키고 재사용을 탐지한다.
- 웹 클라이언트에는 refresh를 `HttpOnly` 쿠키로 내려 XSS 노출을 줄인다. 네이티브는 보안 저장소를 쓰므로 응답 바디로 준다.
- **시크릿 하드코딩 폴백(`'dev-insecure-secret'`)을 전부 제거하고**, 부팅 시 `JWT_SECRET` 미설정이면 프로세스를 중단시킨다. 조용히 약한 키로 뜨는 것보다 낫다.
- `.env.example`에서 `change-me` 류의 값을 제거한다. **저장소를 공개할 것이므로** 그대로 복사돼 배포되는 경로를 원천 차단한다.

### 가드 체인
```
JwtAuthGuard          전역. @Public()으로만 예외
  └ SpaceGuard        :spaceId 멤버십 검증 → req.spaceMember 주입
      └ SpaceRoleGuard         @MinRole('admin') 등
      └ ChannelPermissionGuard @ChannelAction('send') 등
```

역할 서열: `guest < member < admin < owner`. `owner`는 스페이스당 1명, 이전 불가 상태에서 탈퇴할 수 없다.

### 채널 가시성

이전 구현은 "채널 멤버이거나, 전역 역할에 `can_view` 권한 **행이 있으면** 볼 수 있다"였다. 권한 행이 없으면 아무도 못 보는 구조라 **새로 만든 채널이 아무에게도 보이지 않는 것이 기본값**이었다. 기준을 `channels.is_private`로 바꾼다.

| 채널 | 볼 수 있는 사람 | 보낼 수 있는 사람 |
|---|---|---|
| `is_private = false` | 스페이스 멤버 전원 | 볼 수 있으면 보낼 수 있다 |
| `is_private = true` | `channel_members` 에 있는 사람만 | 같음 |

`channel_permissions` 행은 이 기본값을 **덮어쓰는 예외**로만 쓴다 — 특정 역할에게 `can_view=false`(가리기) 또는 `can_send=false`(읽기 전용)를 걸 때. 행이 없으면 위 표가 적용된다.

접근이 거부될 때 응답 코드가 다르다. **볼 수 없으면 404**(채널의 존재 자체를 숨긴다), **볼 수는 있는데 보낼 수 없으면 403**(이미 존재를 아는 상태다).

### CORS
이전의 무조건 `enableCors()`를 **환경변수 화이트리스트**로 바꾼다. Flutter 웹 배포 도메인만 허용한다. 네이티브 앱은 CORS 대상이 아니다.

## 7. 저장소 연동

`GitProvider` 인터페이스로 GitHub/GitLab 차이를 흡수한다. 기존 `IssueProvider`와 같은 패턴이다.

### 7.1 연결
1. GitHub OAuth로 얻은 토큰(`oauth_accounts.access_token`)으로 사용자의 저장소 목록을 조회한다.
2. 저장소를 채널에 연결하면 서버가 해당 provider에 **웹훅을 등록**하고 `webhook_secret`을 저장한다.
3. 웹훅을 등록할 수 없는 환경(사내망 등)을 위해 폴링 폴백을 유지한다.

### 7.2 이벤트 수신
`POST /api/webhooks/:provider/:repoId`가 이벤트를 받아 **HMAC 서명을 검증**한 뒤 세 가지를 한 트랜잭션에서 처리한다.

1. `repo_events`에 원본 페이로드 적재 (감사 · 재처리용)
2. PR 관련 이벤트면 `pull_requests`를 **upsert** — 이게 "PR 확인" 화면의 데이터 소스다
3. 연결된 채널에 시스템 메시지로 게시하고 `repo:event` · `pr:updated` emit

### 7.3 열람 (프록시)
브랜치 · 트리 · 파일 · 커밋 · diff는 **provider API를 그대로 프록시**하고 Redis에 짧게 캐싱한다. 코드 사본을 DB에 두지 않는다.

- 토큰은 서버가 보관한 OAuth 토큰을 쓴다. **클라이언트에 provider 토큰을 절대 내려보내지 않는다.**
- provider rate limit을 초과하면 429를 그대로 전달하되 `Retry-After`를 붙인다.
- 바이너리·대용량 파일은 크기 임계값을 넘으면 본문 대신 메타데이터만 반환한다.

### 7.4 인덱싱 (AI용)
1. 저장소 연결 직후, 그리고 default 브랜치에 push 웹훅이 올 때 인덱싱 작업을 **큐에 넣는다.**
2. 워커가 트리를 순회하며 텍스트 파일만 골라 **함수·클래스 경계 우선, 실패 시 고정 라인 수**로 청킹한다.
3. 각 청크를 임베딩해 `repo_index_chunks`에 저장한다. `commit_sha`를 함께 기록해 **변경된 파일만 재인덱싱**한다.
4. `repos.indexed_at` · `indexed_commit_sha`를 갱신한다.

> 인덱싱은 별도 서브시스템에 가깝다. §10 구현 순서에서 AI 단계에 몰아넣지 말고 **저장소 단계에서 미리 착수**한다.

## 8. AI

이전에는 사내 코드 유출 우려로 501 스텁이었다. 개인 프로젝트에서는 그 제약이 없으므로 실제 기능으로 만든다.

| 기능 | 입력 컨텍스트 | RAG 필요 |
|---|---|---|
| 대화 요약 | 채널 최근 메시지 N개 | ✗ |
| 이슈 초안 | 선택한 메시지들 → 제목·설명·라벨 제안 | ✗ |
| **코드 질의** | 질문 + **`repo_index_chunks`에서 검색한 상위 K개 청크** | **✓** |

### 8.1 코드 질의 파이프라인

```
질문
 → 임베딩
 → repo_index_chunks 벡터 검색 (repo_id 필터, 상위 K개)
 → 경로·라인 번호와 함께 프롬프트 조립
 → LLM 호출
 → 인용(파일 경로 + 라인)을 포함한 답변
```

- **인용을 반드시 포함한다.** 답변에 근거 파일과 라인이 없으면 코드 질의로서 쓸모가 없다.
- 채널 컨텍스트와 함께 물으면(`channelId` + `repoId`) 대화 메시지와 코드 청크를 함께 넣는다. 이것이 기획서 §6-3의 "맥락을 아는 AI"다.

### 8.2 운영 규칙

- 호출은 **Redis 큐를 거쳐 비동기 처리**하고 결과를 소켓(`ai:run:done`)으로 밀어 준다. LLM 응답 지연이 HTTP 타임아웃을 물지 않게 한다.
- 모든 호출을 `ai_runs`에 토큰 수와 함께 기록한다. 서비스화 시 스페이스별 한도의 근거가 된다.
- **동일 프롬프트는 `prompt_hash`로 캐싱해 재사용**한다. 무료 LLM 티어에서 쿼터를 아끼는 가장 효과적인 수단이다.
- **API 키는 서버에만 둔다.** 클라이언트가 LLM을 직접 호출하는 경로는 만들지 않는다.
- LLM·임베딩 provider는 인터페이스 뒤에 둔다. 무료 티어를 갈아타야 할 수 있다.
