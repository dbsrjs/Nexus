# Nexus — 디자인 시스템

> 작성: 2026-08-13
> 화면 구조·라우팅은 [앱 설계서](./앱-설계.md), 제품 성격은 [제품 기획서](./제품-기획.md) 참조.
> 이 문서는 **시각 언어**만 정의한다. 레이아웃 골격은 앱 설계서 §4가 소유한다.

## 1. 성격

**조용하고 밀도 높은 작업 도구.**

내 코드 · 이슈 · 대화가 주인공이고 UI는 배경으로 물러난다. 하루 종일 켜 두는 도구라 장시간 사용 피로도를 최우선으로 본다. 스크린샷에서 화려한 것보다 8시간 뒤에도 편한 쪽을 택한다.

이 성격에서 따라 나오는 세 가지 규칙:

1. **채도를 아낀다.** 화면에서 채도가 높은 것은 지금 주의를 끌어야 하는 것뿐이다. **배경은 중성이다.**
2. **그림자를 쓰지 않는다.** 깊이는 배경 명도와 1px 구분선으로만 만든다.
3. **선은 거의 보이지 않아야 한다.** 구분선이 눈에 띄면 그건 구분선이 아니라 격자다.
4. **모션을 짧게 한다.** 매일 수백 번 보는 전환에 화려함은 비용이다.

## 2. 색

### 2.1 파생 원리

출처는 4색 팔레트([colorhunt.co/palette/27374d526d829db2bfdde6ed](https://colorhunt.co/palette/27374d526d829db2bfdde6ed))다.

**색상(hue)은 하나도 바꾸지 않는다. 채도만 양쪽 극단으로 민다.**

| 원본 | 조작 | 결과 |
|---|---|---|
| `#27374D` (215° · S 33%) | 채도 33% → **4%** ▼ | 중성 램프 3단 |
| `#9DB2BF` (203° · S 21%) | 채도 21% → **48%** ▲ | 액센트 |
| `#DDE6ED` | 변경 없음 | 본문 텍스트 |
| `#526D82` | 두 토큰으로 분리 | `--divider` · `--border-strong` |

> **왜 배경에서 파랑을 빼는가.** 초기안은 배경도 텍스트도 액센트도 전부 203~215°였다. 그러니 정작 "선택됨"과 "멘션"이 배경에 묻혔다. **배경을 중성으로 돌리면 화면에 존재하는 유일한 색이 액센트가 되어 훨씬 강하게 읽힌다.** 파랑을 빼는 것이 파랑을 살리는 방법이다. 부수 효과로 아바타·시맨틱 색도 덜 탁해진다 — 파란 배경이 모든 색을 한 번씩 물들이고 있었다.

### 2.2 표면 — 중성 램프

| 토큰 | 값 | 역할 | `bg-base` 대비 |
|---|---|---|---|
| `--bg-base` | `#121314` | 앱 배경, 메시지 영역 | — |
| `--bg-surface` | `#1C1D1F` | 사이드바, 채널 목록, 우측 패널 | — |
| `--bg-elevated` | `#282A2C` | 카드, 입력창, 호버, 선택 | 1.3 : 1 |
| `--text-secondary` | `#9DA0A4` | 타임스탬프, 메타데이터, 플레이스홀더 | 7.1 : 1 |
| `--text-primary` | `#DDE6ED` ★ | 본문, 메시지, 제목 | **14.7 : 1** |

★ = 원본 팔레트 색 그대로

본문 14.7:1, 보조 7.1:1로 **둘 다 WCAG AAA**를 통과한다. 정보 밀도가 높을수록 이 여유가 중요하다.

### 2.3 선 — 한 토큰이 하던 두 일을 쪼갠다

| 토큰 | 값 | 용도 | 대비 |
|---|---|---|---|
| `--divider` | `rgba(221,230,237,.10)` | 구조 구분선. **거의 보이지 않아야 한다** | 1.3 : 1 |
| `--border-strong` | `#63676B` | 비활성 아이콘, 입력 테두리, 칩 | 3.3 : 1 |

> **초기안의 설계 오류.** `--border` 하나가 구분선과 아이콘을 겸했다. 아이콘은 읽혀야 하니 3:1이 필요한데, 한 값으로 묶으니 **구분선까지 2.95:1로 끌려 올라갔다.** 다크 UI의 미묘한 구분선은 1.3~1.8:1이 적정이니 두 배 이상이었고, "그림자 대신 테두리" 규칙까지 겹쳐 화면이 선으로 짜인 격자가 됐다.

### 2.4 액센트

| 토큰 | 값 | 용도 |
|---|---|---|
| `--accent` | `#77AECF` | 선택 상태, 포커스 링, 링크, 주요 버튼 |
| `--accent-subtle` | `rgba(119,174,207,.13)` | 선택된 채널 배경, 멘션 하이라이트 |
| `--accent-press` | `#5197C2` | 눌림 상태 |

원본 `#9DB2BF`의 채도를 올린 값이다. 같은 203°라 팔레트에서 벗어나지 않는다. `bg-base` 대비 **7.7:1(AAA)** 이며, 보조 텍스트(L 63%)보다 밝아 **위계가 바로 선다.**

> **초기안(`#5BB1E6`, 채도 74%)에서 내렸다.** 거의 검정에 가까운 배경 위에서 채도 70%대 색은 강조가 아니라 네온으로 읽힌다.

### 2.5 시맨틱

| 토큰 | 값 | 채도 | 용도 |
|---|---|---|---|
| `--success` | `#74B48F` | 30% | 빌드 성공, 이슈 done |
| `--warning` | `#D3B069` | 55% | 우선순위 high, 리뷰 대기 |
| `--danger` | `#D47D7D` | 50% | 빌드 실패, 삭제, 오류 |
| `--merged` | `#A18ECC` | 38% | PR merged |

**채도를 중성 램프와 어울리는 대역까지 눌렀다.** 색상(hue)은 관례를 지키되 채도만 절반 안팎으로 내려, 다섯 색이 서로 다른 팔레트에서 온 것처럼 보이지 않게 한다.

> **왜 이게 중요한가.** "액센트는 화면에서 유일하게 채도가 높은 것"이라는 원칙을 세워놓고 그 옆에 채도 70~95%짜리 시맨틱 4색을 얹으면 원칙이 무너진다. 고채도 색이 다섯 개가 되는 순간 강조는 사라지고 화면 전체가 발광한다.

여전히 **면적은 좁게** 쓴다 — 배경 채움이 아니라 점 · 테두리 · 텍스트로만.

### 2.6 아바타

| 토큰 | 값 | 색상 |
|---|---|---|
| `--avatar-1` | `#90A8C1` | 210° |
| `--avatar-2` | `#9C90C1` | 255° |
| `--avatar-3` | `#C190C1` | 300° |
| `--avatar-4` | `#C1909C` | 345° |
| `--avatar-5` | `#C1A890` | 30° |
| `--avatar-6` | `#B4C190` | 75° |
| `--avatar-7` | `#90C1A0` | 140° |
| `--avatar-8` | `#90C1C1` | 180° |

**8색 전부 채도 28% · 명도 66%로 고정하고 색상만 균등 분배한다.** 명도가 같아서 이니셜 글자(`--bg-base`)의 대비가 8색 모두 **7:1 이상(AAA)** 으로 일정하다.

배정은 `hash(userId) % 8`. 결정론적이라 같은 사람은 어느 화면에서든 같은 색으로 보인다.

> **왜 채도를 시맨틱보다 낮게 까는가.** 시맨틱은 30~55%다. 아바타를 그 대역에 두면 이전처럼 `--warning`(#D3B069)과 탠 계열 아바타가 혼동된다. 28%로 한 단 낮춰 두면 **"채도가 낮으면 사람, 높으면 상태"** 라는 규칙이 생겨 구조적으로 겹치지 않는다.

### 2.7 라이트 모드

같은 원리를 뒤집는다. 배경은 중성, 액센트만 색을 갖는다.

| 토큰 | 라이트 값 |
|---|---|
| `--bg-base` | `#EFF0F1` |
| `--bg-surface` | `#F7F8F8` |
| `--bg-elevated` | `#FFFFFF` |
| `--divider` | `rgba(18,19,20,.11)` |
| `--border-strong` | `#A8ABAE` |
| `--text-secondary` | `#5E6165` |
| `--text-primary` | `#27374D` ★ |
| `--accent` | `#326C8F` |

본문(`#27374D` — 원본 팔레트 색)이 대비 10.5:1로 성립한다. 액센트는 색상·채도를 유지한 채 명도만 낮춘 값이다.

> **아직 렌더 검증을 하지 않았다.** 값만 정의된 상태이며, 실제 화면에 적용해 층위가 보이는지 확인해야 한다.

## 3. 타이포그래피

| 용도 | 서체 | 이유 |
|---|---|---|
| UI · 본문 | **Pretendard** | 한글 대응이 핵심. Inter 계열 메트릭이라 라틴도 자연스럽고 무료 |
| 코드 · 메타 | **JetBrains Mono** | 코드블록, 브랜치명, 커밋 해시, PR 번호, 타임스탬프 |

### 스케일 — 밀도 우선

| 토큰 | px | 용도 |
|---|---|---|
| `--text-2xs` | 11 | 뱃지, 타임스탬프 |
| `--text-xs` | 12 | 메타데이터, 캡션 |
| `--text-sm` | 13 | 채널명, 보조 UI |
| `--text-base` | 14 | **본문 · 메시지 기본** |
| `--text-md` | 16 | 카드 제목 |
| `--text-lg` | 20 | 화면 제목 |
| `--text-xl` | 24 | 빈 상태 헤드라인 |

행간: 본문 1.5 · UI 1.3. 자간: 기본 0, 11~12px에만 `0.01em`.

> **타임스탬프 · 브랜치명 · 커밋 해시에 모노스페이스를 쓰는 것**이 이 시스템의 시그니처다. "개발자를 위한 도구"라는 주장이 장식이 아니라 활자에서 드러난다.

## 4. 간격 · 형태 · 깊이 · 모션

### 간격 — 4px 그리드
`2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 48`

### Radius
| 토큰 | 값 | 대상 |
|---|---|---|
| `--r-sm` | 4px | 버튼, 입력, 칩 |
| `--r-md` | 6px | 카드, 패널 |
| `--r-full` | 9999px | 아바타, 뱃지, 리액션 |

각진 편이 밀도와 맞는다. 8px 이상은 쓰지 않는다.

### 깊이
**그림자를 쓰지 않는다.** 다크 배경에서 거의 보이지 않으면서 렌더링 비용만 든다.

```
층위 = 배경 3단계 (base → surface → elevated) + 1px --divider
```

오버레이(모달 · 드롭다운)만 예외적으로 `rgba(0,0,0,.5)` 백드롭을 쓴다.

### 모션
| 토큰 | 값 | 대상 |
|---|---|---|
| `--motion-micro` | 120ms ease-out | 호버, 포커스, 체크 |
| `--motion-panel` | 180ms ease-out | 패널 열림, 드로어, 모달 |

`prefers-reduced-motion`에서는 전부 0ms로 떨어뜨린다.

## 6. 접근성 기준

- 본문 대비 **7:1(AAA)** 이상, 보조 텍스트 **4.5:1(AA)** 이상을 지킨다
- **색만으로 상태를 전달하지 않는다.** PR 상태 · 우선순위 · 빌드 결과는 색 + 아이콘/텍스트를 함께 쓴다 (색각 이상 대응)
- 포커스 링은 `--accent` 2px + 2px 오프셋. 키보드 탐색에서 절대 생략하지 않는다
- 터치 타깃 최소 44×44px (모바일). 밀도가 높아도 이 하한은 지킨다

## 7. 산출물

Claude Design 디자인 시스템 프로젝트로 관리한다. 로컬 소스는 `design-system/`.

```
design-system/
├─ tokens.css                 전 토큰 (다크 · 라이트)
├─ foundations/               color · typography · spacing
├─ components/                컴포넌트별 프리뷰
└─ screens/                   채널 데스크톱 · 모바일
```

각 프리뷰는 **자기완결 HTML**이다(토큰 인라인). Flutter 구현 시 `core/theme.dart`가 `tokens.css`의 값을 그대로 옮겨 담는다 — 두 곳의 값이 어긋나지 않도록 **토큰 이름을 동일하게** 유지한다.
