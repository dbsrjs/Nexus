### 완성된 REST 계약

```
POST   /api/me/connections/github/start   → { authorizeUrl }   인증 필요 · 미설정이면 503
GET    /api/auth/github/callback          @Public · 언제나 200 HTML
GET    /api/me/connections                → [{ provider, login, avatarUrl, connectedAt }]
DELETE /api/me/connections/github         → 204 (멱등)
```

소켓 이벤트 **`oauth:connected`** — 페이로드 `{ provider: 'github', login }`,
개인 룸(`user:{userId}`)으로만 간다.

## 2. 다른 PC 에서 이어받는 절차

### 2.1 브랜치

```bash
git fetch && git checkout feat/github-oauth
```

### 2.2 DB · 서버 (CLAUDE.md §1 과 같다)

```bash

npm --prefix server run prisma:deploy

```

**마이그레이션은 10-2a 에서 하나도 늘지 않았다.** 스키마를 건드리지 않았다
(`webhook_external_id` 는 10-2b 다).

### 2.3 `.env` — **이 PC 에만 있던 것이라 새 PC 에서 다시 채워야 한다**

`server/.env` 에 아래 여섯 줄이 필요하다. `.env` 는 git 에 올라가지 않는다.

```
GITHUB_CLIENT_ID=check-oauth-client
GITHUB_CLIENT_SECRET=check-oauth-secret
GITHUB_CALLBACK_URL=http://127.0.0.1:3000/api/auth/github/callback
GITHUB_OAUTH_BASE=http://127.0.0.1:4599
GITHUB_API_BASE=http://127.0.0.1:4599
OAUTH_TOKEN_KEY=<아래 명령으로 만든 값>
```

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

**이 값들은 계약 검증용 가짜 GitHub 을 가리킨다.** 진짜 GitHub 에 붙일 때는
`GITHUB_OAUTH_BASE` · `GITHUB_API_BASE` 를 **비우고**(기본값이 진짜 GitHub 이다)
`GITHUB_CLIENT_ID` · `SECRET` 을 실제 OAuth App 값으로 바꾼다.

**`GITHUB_CALLBACK_URL` 과 `PUBLIC_BASE_URL` 은 다른 주소다.** 콜백은 사람의
브라우저가 오므로 `localhost` 로 충분하고, 웹훅(10-2b)은 GitHub 서버가 오므로
터널이어야 한다. 합치지 말 것.

### 2.4 계약 검증을 돌려 상태를 확인한다

```bash
npm run server:dev
```

```bash
npm run check:oauth
```

`통과 38 · 실패 0` 이면 서버 층이 그대로다. **`.env` 를 채우고 서버를 재시작한
뒤에** 돌려야 한다 — 미설정 상태로 돌리면 503 분기 1개만 확인하고 나머지를
건너뛴다(그때는 스크립트가 그 사정을 출력한다).

**진짜 GitHub 설정으로는 이 검증이 돌지 않는다.** `GITHUB_OAUTH_BASE` ·
`GITHUB_API_BASE` 가 비어 있으면 스크립트가 띄운 가짜 GitHub(4599)이 아니라
진짜 github.com 으로 나간다. 두 값을 오가며 쓰는 것이 정상이다 — **검증할 때는
4599, 실제로 연결할 때는 빈 값.** 바꾸면 서버를 재시작해야 반영된다.

## 4. 되돌리면 안 되는 결정들

리뷰가 잡아 고친 것들이다. **왜 그렇게 돼 있는지 모르고 되돌리면 같은 구멍이
다시 열린다.**

| 자리 | 규칙 | 이유 |
|---|---|---|
| `oauth-callback.controller.ts` | `completeGithub()` 을 **try/catch 로 통째 감싼다** | 이 라우트는 `@Public()` 이라 브라우저가 인증 없이 읽는다. 전역 필터가 `HttpException` 이 아닌 `Error` 의 `message` 를 응답에 그대로 싣는데, Prisma 의 P1001 은 **DB 호스트·포트**를 담는다 |
| `oauth.service.ts` 의 `tokenKeyOrNull()` | `resolveOauthTokenKey()` 의 **throw 를 `null` 로 접는다**(로그는 남긴다) | 감싸지 않으면 잘못 설정된 서버에서 공개 콜백이 500 으로 **키가 몇 바이트인지** 알려 준다 |
| `oauth.service.ts` 의 `list()` | `where` 에 **`provider: github` 을 반드시 넣는다** | 없으면 `gitlab` 행이 생기는 순간 **그 토큰이 api.github.com 으로 나간다**. `disconnect()` · `githubTokenFor()` 는 원래부터 좁히고 있었다 |
| `completeGithub()` | `deleteMany` + `upsert` 를 **한 트랜잭션**으로 — 사용자당 연결 하나 | 스키마에 `@@unique([userId, provider])` 가 없어, 없으면 한 사용자에게 행이 둘 생기고 `githubTokenFor()` 가 **어느 토큰을 줄지 DB 가 정한다** |
| `ConnectionView.connectedAt` | **"마지막으로 연결한 때"** 다 | 위 규칙 때문에 재연결이 언제나 `create` 로 떨어진다. 의도된 동작이다 |
| `oauth-state.ts` | `purpose` 를 **반드시 검사한다** | 안 보면 같은 시크릿으로 서명된 다른 용도 토큰이 `state` 로 통한다 |
| `token-crypto.spec.ts` | 변조 지점은 **각 파트의 첫 글자** | 마지막 글자는 base64url 패딩 비트라 `A→B` 가 **디코딩 결과를 바꾸지 않는다**. 원래 코드가 25% 확률로 실패했고, 통과할 때도 변조를 검증하지 못했다 |
| `github-oauth.client.ts` | 단위 테스트를 **두지 않는다** | 세 메서드가 전부 네트워크 호출이다. 스텁으로 덮으면 CLAUDE.md §6 의 실수를 반복한다 — 이 갈래는 `check:oauth` 가 실제 HTTP 로 태운다 |

## 5. 확인한 것과 확인하지 못한 것

**확인한 것**

- `npm run check:oauth` **38개** — start · authorizeUrl 구성 · 위조/변조/누락 `state`
  거부 · 콜백이 **어떤 실패에서도 200 HTML** · 실패·성공 페이지에 내부 정보(키 이름 ·
  포트 · `prisma`)가 없음 · 연결 · 목록에 **토큰이 없음** · code 재사용 거부 ·
  테넌트 격리 · 재연결에 행이 늘지 않음 · 해제 · 해제 멱등
- **미설정 503 분기**: `OAUTH_TOKEN_KEY` 를 비우고 재시작하니 **서버는 정상 부팅**했고
  `start()` 만 503 이었다. `.env` 복원 후 38개 재통과까지 확인
- 서버 단위 138개 · typecheck · lint
- **진짜 GitHub 으로의 종단 확인 (2026-08-21).** OAuth App 을 등록하고
  `GITHUB_OAUTH_BASE` · `GITHUB_API_BASE` 를 비운 채 확인했다 —
  `start` 가 **진짜 github.com** authorizeUrl 을 주고, 사람이 승인하자 콜백이
  성공 HTML 을 그렸으며, `GET /me/connections` 에 실제 계정(`login` ·
  `avatarUrl` · `connectedAt`)이 잡혔다. **DB 의 `access_token` 은
  `v1.<IV>.<암호문>.<태그>` 4파트**로, 평문 `gho_…` 이 아니다.
  `scope` 는 `repo`(10-2b 가 쓴다)

**확인하지 못한 것**

- **`oauth:connected` 소켓 이벤트의 실제 수신.** 서버가 쏘는 것은 계약 검증이
  덮지만, 앱이 받아 화면을 바꾸는 것은 Task 9 가 있어야 볼 수 있다
- **앱 화면 전체.** Task 9 가 아직 없다
- 콜백 `try/catch` 가 **런타임에서** 실패 HTML 로 접는 것 — 코드 읽기와 리뷰로만
  확인했다. 그 경로를 태우려면 유효한 `state` 를 쥔 채 DB 를 내려야 한다
