# 17 DM · 프레즌스 · 타이핑 — 설계

> 2026-10-05. 출발점은 [제품 기획 §5.1-c](../../제품-기획.md) «17». 16단계로 두 번째 사람이
> 들어올 수 있게 됐다 — 이제 그 사람과 1:1 로 말하고, 지금 있는지 · 쓰는 중인지를 본다.

두 조각으로 나눈다. 각각 서버에서 화면까지 끝나야 완료다(CLAUDE.md §5).

| 조각 | 범위 |
|---|---|
| **17-1 DM** | 스페이스 안 1:1 DM 열기 · 목록 · 대화(기존 채널 화면 그대로) · 상대가 나간 DM |
| **17-2 프레즌스 · 타이핑** | 온라인 · 자리비움 · 오프라인 표시 · 「입력 중」 표시 |

---

## 0. 정한 것

### 17-1 DM

| # | 결정 | 이유 |
|---|---|---|
| D1 | **DM 은 `kind = dm` · `isPrivate = true` 인 채널 하나 + `channel_members` 두 행**이다. 새 테이블을 두지 않는다 | 스키마에 자리가 있다(제품 기획 §5.1-c). 비공개 채널이라 **가시성 판정(`channelAccess`)이 그대로 「명단만 본다」로 맞는다** — 메시지 · 리액션 · 스레드 · 답장 · 핀 · 첨부 · 읽음 · 멘션 · 음소거 · AI · 대화→이슈가 전부 손대지 않고 DM 에서 돈다 |
| D2 | **유일성은 `key` 가 지킨다** — `dm:<작은 id>:<큰 id>`. 기존 `@@unique([spaceId, key])` 가 같은 두 사람의 DM 이 둘 생기는 것을 DB 에서 막는다. 마이그레이션이 없다 | 채널 key DTO 는 `:` 를 받지 않아(`^[a-z0-9-]+$`) 사람이 만든 채널과 겹칠 수 없다 — 누군가 미리 그 key 로 채널을 만들어 DM 을 가로채는 길이 없다. 동시에 둘이 열면 한쪽이 P2002 를 받고 다시 읽는다 |
| D3 | **`POST /api/spaces/:spaceId/dms { userId }` 하나로 연다** — 있으면 그것, 없으면 만든다(200 · 같은 모양). 상대가 스페이스 멤버가 아니면 404, 자기 자신이면 400 | 「열기」와 「만들기」를 앱이 가를 이유가 없다. 자기 DM(메모장)은 범위 밖 |
| D4 | 열 때 **두 사람의 `channel_members` 행을 upsert** 한다. 새로 만들었거나 행이 새로 생긴 사람에게 `rooms:invalidate { reason: 'dm.opened' }` | 스페이스를 나갔다 다시 들어온 사람은 행이 지워져 있다(16-1 `dropMembership`). 같은 DM 을 다시 살린다 — key 에 두 id 가 있으니 상대를 잃지 않는다 |
| D5 | **역할과 무관하게 스페이스 멤버면 누구나 DM 을 연다**(guest 포함) | 1:1 은 여럿에게 번지지 않는다(§3-9). 슬랙도 손님이 DM 을 쓴다 |
| D6 | 채널 목록 응답에 **`kind` · `dmUserId`(상대, DM 만) · `lastMessageAt`** 을 더한다. drift `cached_channels` 에 세 컬럼(`schemaVersion` 19) | 사이드바가 DM 을 따로 묶고 최근 대화 순으로 줄 세운다. 상대는 받는 사람마다 다르지만 목록은 원래 사람마다 따로 받는다(16단계 D26 과 같다) |
| D7 | **채널 구조 API 는 DM 을 없는 채널로 본다(404)** — `PATCH` 채널 · 참여(`join`) · 명단(`members`) · 권한(`permissions`) · 저장소 연결의 `linkedChannelId` | DM 은 이름 · 주제 · 공개 여부 · 명단 · 역할 권한이 뜻이 없다. 400 대신 404 인 이유: 관리자도 남의 DM 이 있다는 것을 알 수 없어야 한다(§3-4) |
| D8 | **상대가 스페이스를 떠난 DM 은 읽기 전용이다**(`canSend = false`). 판정은 `channelAccess()` 의 입력 하나(`dmPeerPresent`)로 더한다 | 받을 사람이 없는 곳에 쓴 글은 18단계 알림도 갈 데가 없다. 대화는 남긴다(무기한 보관). 판정은 한 곳 규칙(16단계 검토)을 지킨다 |
| D9 | DM 은 **`name` 을 `"DM"` 으로 저장**하고 앱은 쓰지 않는다 — 화면은 상대 이름을 멤버 목록에서 찾는다. 못 찾으면 「나간 사람」 | 보는 사람마다 이름이 달라 하나로 저장할 수 없다. 개명도 저절로 따라온다 |
| D10 | 사이드바에 **「다이렉트 메시지」 묶음**을 채널 묶음 아래 둔다 — 최근 메시지 순, **메시지가 없는 DM 은 숨긴다(지금 열린 것은 예외)**. 묶음 머리 「+」 가 멤버 고르기 창을 연다 | 열기만 하고 말을 안 한 DM 이 상대 목록에 빈 줄로 뜨지 않게. 서버는 숨기지 않는다 — 고르는 것은 화면의 일이다 |
| D11 | 진입로는 셋 — 사이드바 「+」, **스페이스 설정 · 멤버 목록의 「메시지」**, 멤버 고르기 창 | 사람을 보는 자리에서 바로 말을 건다. 메시지 작성자 프로필 팝오버는 범위 밖 |
| D12 | DM 대화 화면은 **채널 화면 그대로** — 머리 줄만 `#이름` 대신 상대 아바타 · 이름(17-2 에서 프레즌스 점), 채널 설정 버튼을 감춘다. 주소도 같다(`/s/:spaceId/c/:channelId`) | 머무는 곳은 셸 안(§3-13). 새 화면을 두면 채널 화면이 받은 기능을 다시 붙여야 한다 |
| D13 | 저장소 고르기 · 채널 만들기의 카테고리 묶음 등 **채널을 고르는 자리에서 DM 을 뺀다** | 웹훅이 DM 에 게시될 이유가 없다 |

### 17-2 프레즌스 · 타이핑

| # | 결정 | 이유 |
|---|---|---|
| D14 | 상태는 **온라인 · 자리비움 · 오프라인** 셋. **소켓 연결에서 계산하고 저장하지 않는다**(서버 메모리 `PresenceService`). `users.global_status` 는 쓰지 않는다 | 「지금 있는가」는 연결이 진실이다. DB 에 쓰면 서버가 죽을 때 모두가 「온라인」으로 굳는다. 다중 인스턴스가 되면 Redis 로 옮긴다(`redis-io.adapter` 와 같은 때) — §5 빚 |
| D15 | 사용자 하나의 상태 = 소켓 중 하나라도 `online` 이면 온라인, 소켓은 있는데 모두 `away` 면 자리비움, 소켓이 없으면 오프라인 | 여러 기기를 쓴다. 휴대폰이 잠겨도 데스크톱 앞에 있으면 있는 것이다 |
| D16 | 앱은 **`presence:set { status: 'online' \| 'away' }`** 를 보낸다 — 앱이 앞에 없거나(생명주기 `resumed` 아님) **10분 동안 입력이 없으면** `away` | 슬랙과 같은 기준. 연결만 보면 켜 둔 채 자리를 뜬 사람이 늘 온라인이다 |
| D17 | 마지막 소켓이 끊기면 **5초 기다린 뒤** 오프라인으로 알린다. 그 안에 다시 붙으면 알리지 않는다 | 새로고침 · 네트워크 순간 끊김 · 토큰 갱신 재연결마다 점이 깜빡이지 않게 |
| D18 | 바뀌면 **`presence:changed { userId, status }` 를 그 사람의 스페이스 룸마다** 보낸다 | 함께 쓰는 스페이스 밖으로 온라인 여부가 새지 않는다(제품 기획 §5.1-c). 모두에게 같은 값이다(§3-6) |
| D19 | 처음 값은 **`GET /api/spaces/:spaceId/presence` → `{ users: { [userId]: 'online' \| 'away' } }`** (오프라인은 싣지 않는다). 앱은 스페이스에 들어갈 때 · 소켓이 다시 붙을 때 · `member:*` 때 다시 받는다 | 이벤트만으로는 앱을 켠 순간의 상태를 모른다. 끊겨 있는 동안 놓친 변화도 이것으로 맞춘다 |
| D20 | 프레즌스 점은 **DM 줄 · DM 머리 줄 · 멤버 목록(스페이스 설정 · 멤버 고르기 창)** 에만 둔다. 메시지 작성자 아바타에는 두지 않는다 | 대화 목록이 점으로 시끄러워진다. 「이 사람에게 지금 말을 걸까」를 정하는 자리에만 |
| D21 | 타이핑은 **`typing { spaceId, channelId, parentId? }` 를 입력이 바뀌는 동안 3초에 한 번** 보낸다. 저장하지 않는다 | 실시간 최소 스펙의 자리 그대로. 글자마다 보내면 낭비다 |
| D22 | 서버는 **보낼 수 있는 사람만**(`canSend`) 받아 **채널 룸의 나머지 소켓에** `typing { spaceId, channelId, parentId, userId }` 로 넘긴다. 같은 소켓 · 같은 채널은 1초 안의 반복을 버린다 | 읽기 전용 채널에서 「입력 중」이 뜨면 거짓말이다. 판정은 `ChannelsService` 한 곳. 1초 상한은 고친 클라이언트가 DB 를 두드리는 것을 막는다 |
| D23 | 앱은 받은 지 **6초** 지나거나 **그 사람의 새 메시지가 오면** 지운다. 별도의 「멈춤」 이벤트는 두지 않는다 | 보낸 뒤에 「입력 중」이 남지 않게 하는 것은 새 메시지로 충분하다. 지운 입력은 6초 안에 사라진다 |
| D24 | 표시는 **입력창 바로 위 한 줄** — 「가나 님이 입력 중…」 · 「가나, 다라 님이 입력 중…」 · 셋 이상은 「여러 명이 입력 중…」. 스레드는 `parentId` 가 같은 것만 | 디스코드와 같은 자리. 줄이 없을 때도 높이를 비워 두면 메시지가 들썩이지 않는다 |

## 1. API

```
POST /api/spaces/:spaceId/dms                 { userId }   → 200 ChannelListItem   (17-1, 스페이스 멤버 누구나)
GET  /api/spaces/:spaceId/channels                         → ChannelListItem 에 kind · dmUserId · lastMessageAt  (17-1)
GET  /api/spaces/:spaceId/presence                         → 200 { users: { [userId]: 'online' | 'away' } }      (17-2)
```

| 조건 | 응답 |
|---|---|
| DM 열기: 상대가 이 스페이스 멤버가 아님 · 없는 id | 404 |
| DM 열기: 자기 자신 | 400 |
| DM 에 `PATCH` 채널 · `join` · 명단 · 권한 · 저장소 연결 | 404 |
| 상대가 나간 DM 에 메시지 보내기 | 403(볼 수는 있다 — 기존 `assertCanSend`) |

### 실시간

| 이벤트 | 방향 · 룸 | 페이로드 | 조각 |
|---|---|---|---|
| `rooms:invalidate` | 서버 → 그 사용자 | `{ reason: 'dm.opened' }` | 17-1 |
| `presence:set` | 앱 → 서버 | `{ status: 'online' \| 'away' }` → ack `{ ok }` | 17-2 |
| `presence:changed` | 서버 → 스페이스 | `{ userId, status: 'online' \| 'away' \| 'offline' }` | 17-2 |
| `typing` | 앱 → 서버 | `{ spaceId, channelId, parentId? }` → ack `{ ok }` | 17-2 |
| `typing` | 서버 → 채널(보낸 소켓 제외) | `{ spaceId, channelId, parentId: string \| null, userId }` | 17-2 |

## 2. 판정 — `channelAccess()` 에 하나를 더한다

```ts
channelAccess({ isPrivate, isMember, perm, dmPeerPresent })
  view = isPrivate ? isMember : (perm?.canView ?? true)
  send = view && (perm?.canSend ?? true) && (dmPeerPresent ?? true)
```

`dmPeerPresent` 는 DM 일 때만 넘긴다 — key 에서 상대 id 를 읽어 스페이스 멤버인지 본다. DM 에는 권한
행을 만들 수 없으므로(D7) `perm` 은 늘 null 이다.

## 4. 검증

- **`npm run check:dm`**(17-1) — 열기 멱등 · 같은 두 사람 동시 열기 하나 · 자기 자신 400 · 비멤버 404 ·
  셋째 사람(관리자 포함)이 DM 을 못 봄(목록 · 메시지 · 소켓) · 구조 API 404 · 나간 상대 → 읽기 전용 403 ·
  다시 들어오면 같은 DM 이 살아남 · 채널 목록의 `kind` · `dmUserId` · `lastMessageAt`
- **`npm run check:presence`**(17-2) — 연결 → 온라인 이벤트 · 함께 쓰지 않는 사람은 못 받음 · 두 소켓 중
  하나만 away 면 온라인 · 둘 다 away 면 자리비움 · 끊김 → 5초 뒤 오프라인 · 그 안의 재연결은 이벤트 없음 ·
  처음 값 REST · 타이핑 전달 · 보낸 소켓 제외 · 볼 수 없는 사람 못 받음 · 읽기 전용 채널 거부 · 1초 상한
- 새 ★ 케이스는 코드를 되돌려 빨개지는지 본다(CLAUDE.md §5 빚)
- 서버 단위: `channelAccess` 의 `dmPeerPresent` · `dmKey` · 프레즌스 집계(순수 함수)
- 앱: 위젯 테스트(DM 묶음 · 빈 DM 숨김 · 머리 줄 · 타이핑 줄 문구) + `app:flow` 에 DM 열기 · 보내기
- 화면: Windows 두 계정(design@ · visual-b@) · 웹 · Android 는 조각 경계에서

## 5. 범위에서 뺀 것

| 뺀 것 | 이유 |
|---|---|
| 그룹 DM(셋 이상) | 비공개 채널이 그 일을 한다 |
| 자기 DM(메모장) | 필요해지면 key 규칙을 그대로 쓴다(`dm:a:a`) |
| 직접 고르는 상태(「방해 금지」 · 상태 메시지) | `users.global_status` 자리는 남긴다. 18단계 알림과 함께 볼 일 |
| 마지막 접속 시각 | 저장하지 않는다는 D14 와 어긋난다 |
| DM 숨기기 · 닫기 | 메시지가 없으면 저절로 숨는다(D10). 대화가 있는 DM 을 치우는 기능은 필요해질 때 |
| 메시지 작성자 프로필 팝오버 | D11 |
