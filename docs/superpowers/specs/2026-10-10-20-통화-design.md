## 1. 정한 것 — 서버

| # | 결정 | 이유 |
|---|---|---|
| V1 | **범위는 음성 채널 + 화면 공유. 카메라 · 녹음 · DM 통화 · 종단 간 암호화는 뺀다** | 보스 결정(2026-10-10). 개발자 허브의 쓰임은 「같이 코드 보며 말하기」다. 카메라는 토큰에서 막는다(V5) — 앱을 고쳐도 올릴 수 없다 |
| V2 | **미디어는 LiveKit(SFU, Apache 2.0)을 VM 에 직접 띄워 나른다.** WebRTC 를 직접 짜지 않고, LiveKit Cloud 도 쓰지 않는다 | 디스코드도 미디어는 별도 SFU 가 맡고 메인 게이트웨이는 「어느 서버에 무슨 토큰으로」만 준다 — 같은 모양이다. 직접 짜면 플랫폼 넷의 캡처 · 코덱 · 재연결을 떠안는다. Cloud 가 아닌 것은 보스 결정(VM 에 같이 둔다) |
| V3 | 설정은 `LIVEKIT_URL` · `LIVEKIT_API_KEY` · `LIVEKIT_API_SECRET`(+ 선택 `LIVEKIT_API_URL`). **셋 다 비면 통화가 꺼지고 나머지는 그대로 돈다. 일부만 차면 부팅을 멈춘다.** 시크릿 32자 미만도 멈춘다 | AI(`LLM_PROVIDER`)와 같은 규칙. 반쯤 켜진 통화는 「참여하기」를 누른 순간에야 실패한다. `URL` 은 **앱이** 붙는 주소, `API_URL` 은 **서버가** 부르는 주소 — 배포에서 둘이 다르다(터널 호스트 · 컨테이너 안 주소) |
| V4 | **음성 채널은 `Channel.kind = voice` 다.** 새 테이블을 만들지 않는다. 룸 이름은 `<spaceId>:<channelId>` | 채널이면 가시성 · 비공개 명단 · 역할별 권한 · 카테고리 · 정렬을 그대로 받는다. 권한은 **볼 수 있으면 듣기, 보낼 수 있으면 말하기 · 화면 공유**로 옮긴다 — 읽기 전용 채널 = 듣기만. 룸 이름에 스페이스를 넣는 것은 웹훅 · 룸 목록에서 거꾸로 읽을 때 스페이스까지 대조하려는 것이다 |
| V5 | **LiveKit SDK 를 들이지 않는다.** 접속 토큰 · 서버 API(Twirp) · 웹훅 서명 셋 다 HS256 JWT 와 JSON POST 라 `@nestjs/jwt` 와 `fetch` 로 짠다. 토큰은 마이크 · 화면 공유 · 화면 소리만 허락하고 데이터 채널 · 메타데이터를 막는다 | 판단 #8(직접 만들 수 있으면 패키지를 들이지 않는다). 실제 LiveKit v1.9.1 에 대고 확인했다. 웹훅은 `Authorization` 의 JWT 가 원문 바이트의 SHA-256 을 싣는다 — **원문으로 검증한다**(판단 #14 와 같은 이유). 그 본문의 `Content-Type` 이 `application/webhook+json` 이라 그 형식만 받는 JSON 파서를 따로 건다(§2 함정) |
| V6 | **통화 중인 사람의 원본은 LiveKit 의 참가자 목록이다.** 웹훅은 「그 룸을 다시 물어라」는 신호로만 쓰고, 30초마다 전체를 다시 맞춘다. 상태는 **서버 메모리**에 두고 `voice:state {channelId, userIds}` 를 채널 룸으로 보낸다(그 채널의 전체 명단). JOINED · ACTIVE 만 센다 | LiveKit 은 웹훅 전달을 보장하지 않는다 — 순서 · 누락에 흔들리지 않으려면 사건을 쌓지 말고 원본을 다시 읽는다. 메모리인 것은 프레즌스와 같은 판단(17-2) — 재시작하면 부팅 때 다시 센다. 채널 룸에는 볼 수 있는 사람만 있으니 명단이 새지 않는다 |
| V7 | **권한은 들어갈 때 한 번만 검사되므로 서버가 따라간다.** 볼 수 없게 되면(내보내기 · 나가기 · 비공개 전환 · 명단에서 빠짐 · 역할 가림) `RealtimeEmitter.evict` 에 건 갈고리가 그 채널을 다시 판정해 `RemoveParticipant` 로 내보낸다. 보내기 권한이 바뀌면 `permissions` 가 `UpdateParticipant` 로 말하기를 끈다 | 볼 수 없게 되는 경로는 이미 전부 `evict` 를 지난다 — 경로마다 통화 코드를 넣지 않고 한 곳에 건다. **역할이 바뀌어 보내기만 달라지는 경우는 30초 맞추기에 기댄다**(spaces → voice 순환 의존을 만들지 않으려고) — 알려진 지연이다 |

## 2. 정한 것 — 앱

| # | 결정 | 이유 |
|---|---|---|
| A1 | **통화는 뿌리 provider 가 붙든다**(`voiceSessionProvider`, `main.dart`) | 화면이 붙들면 채널을 옮기거나 설정 창에 다녀오는 순간 구독자가 0 이 되어 연결이 닫힌다(§2 Riverpod 3 함정) |
| A2 | **채널 주소 하나(`c/:channelId`)가 종류에 따라 통화 화면 / 대화로 갈린다** | 사이드바 선택 · 딥링크 · 알림 이동이 다 채널 주소를 쓴다. 주소가 갈리면 그 셋이 모두 종류를 알아야 한다 |
| A3 | 음성 채널을 누르면 **들어가지 않고 화면만 연다** — 「참여하기」를 눌러야 마이크가 열린다 | 디스코드는 누르면 바로 들어가지만, 누가 있는지 보려고 눌렀다가 마이크가 열리는 쪽이 더 나쁘다. 웹은 사람의 누름 안에서 소리 재생을 열어야 해서(자동 재생 정책) 버튼 하나가 둘 다 맡는다 |
| A4 | 들어가면 **마이크를 켠 채로** 시작한다. 권한 거부 · 장치 없음은 통화를 깨지 않고 듣기만 하게 둔다 | 디스코드와 같다. 마이크 실패는 복구 가능한 실패다 — 권한을 고치고 버튼을 다시 누르면 된다 |
| A5 | 한 번에 한 통화. 다른 음성 채널에 들어가면 앞의 것에서 나온다. 스페이스를 옮겨도 통화는 이어진다(통화 줄이 채널 이름을 들고 다닌다) | 디스코드와 같다 |
| A6 | **미디어는 `VoiceEngine` 뒤에 숨긴다**(`LiveKitVoiceEngine` · 테스트의 가짜) | flutter_webrtc 는 테스트 환경에 플랫폼 구현이 없다. 앱 흐름(app:flow)이 통화를 만지지 않으면 플러그인을 부르지 않는다 — 연결은 「참여하기」에서 처음 만든다 |
| A7 | 통화가 내 뜻과 달리 끝나면(내보내짐 · 끊김) 그 채널 화면에 한 줄로 까닭을 남긴다 | 조용히 사라지면 고장으로 읽힌다 |
| A8 | 음성 채널에는 **메시지를 보이지 않는다**(서버는 막지 않는다) | 디스코드의 「음성 채널 채팅」은 범위 밖이다. 서버를 막지 않은 것은 나중에 열 때 마이그레이션 없이 열려고 |
