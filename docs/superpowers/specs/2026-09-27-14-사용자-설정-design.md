# 14 사용자 설정 — 설계

> **✅ 완료 — 14단계.** 경과는 [진행 기록](../../진행-기록.md) 의 그 단계 절.

> 2026-09-27. 출발점은 [제품 기획 §5.1-a](../../제품-기획.md). 디스코드식 설정 창 하나에
> 표시 이름 · 프로필 사진 · 비밀번호 변경 · 알림(채널 음소거) · 화면(테마)을 모은다.

## 0. 정한 것

| # | 결정 | 이유 |
|---|---|---|
| D1 | 설정 창은 **셸 밖 라우트 `/settings/:section`** 이다. 섹션은 `account`(내 계정) · `password`(비밀번호) · `notifications`(알림) · `appearance`(화면) | 머무는 곳이 아니라 잠깐 들어갔다 나오는 곳이다(CLAUDE.md §3-13 — 덮어서 연다). 스페이스에 묶이지 않는다 |
| D2 | 데스크톱 · 태블릿은 **왼쪽 목록 + 오른쪽 내용**, 모바일은 **목록 → 섹션**. 폭 분기는 `app_shell.dart` 에 둔 `SettingsFrame` 한 곳 | 반응형 분기를 흩지 않는 규칙(§3 앱 규칙). 설정 화면 안쪽은 자기 폭을 모른다 |
| D3 | 진입은 **계정 메뉴의 「설정」** 하나. 계정 메뉴의 테마 항목은 설정 창 「화면」으로 옮긴다 | 같은 설정이 두 곳에 있으면 어느 쪽이 진짜인지 묻게 된다 |
| D4 | **표시 이름은 기존 `PATCH /api/me { name }`** 을 쓰고, 바뀌면 **`user:updated`** 를 그 사용자가 속한 스페이스 룸마다 보낸다 | 이름은 받는 사람마다 같은 값이라 브로드캐스트해도 된다(§3-6). 받은 앱은 drift 의 작성자명을 고친다 — 화면은 drift 만 본다 |
| D5 | 프로필 사진은 **`PUT /api/me/avatar`(multipart `file`)** · **`DELETE /api/me/avatar`** · 열람은 **`GET /api/users/:userId/avatar`** | 첨부는 `SpaceGuard` 로 지키지만 아바타는 **사용자 단위**다. 서명 URL 을 발급하지 않는 규칙(8-1)은 그대로 — 열람도 서버를 지난다 |
| D6 | 아바타를 **볼 수 있는 사람은 본인과 스페이스를 하나라도 함께 쓰는 사람**. 아니면(없는 사람 · 사진 없음 포함) **404** | §3-4(볼 수 없으면 404). 스페이스 밖 사람은 존재 여부도 알 수 없어야 한다 |
| D7 | 올린 사진은 **`sharp` 로 256×256 가운데 자르기 · WebP** 로 바꿔 저장한다. 원본은 두지 않는다. 입력은 PNG · JPEG · WebP · GIF(첫 프레임), **5MB 이하** | 아바타가 쓰이는 가장 큰 자리가 설정 미리보기(96px)다. 원본을 두면 저장소만 늘고 쓸 곳이 없다. 자르기 화면은 두지 않는다(패키지를 들이지 않는다 — §3-8) |
| D8 | `users.avatar_url` 에는 **앱이 부를 경로 `/users/<id>/avatar?v=<버전>`** 을, 새 컬럼 **`avatar_key`** 에는 저장소 키를 둔다 | 메시지 · 이슈 · 댓글 · 멤버 응답이 이미 `avatarUrl` 을 싣는다 — 컬럼의 뜻만 바꾸면 그 다섯 곳을 고치지 않는다. 버전이 주소에 있어 바꾸면 캐시가 저절로 갈린다 |
| D9 | `UpdateMeDto` 의 **`avatarUrl`(임의 URL)을 걷는다.** 마이그레이션이 기존 값을 비운다 | 아무 주소나 넣게 두면 앱이 그 주소를 부른다 — 추적 픽셀이 된다. 앱은 지금까지 이 값을 그린 적이 없어 비워도 보이는 것이 바뀌지 않는다 |
| D10 | 사진을 바꾸는 순서는 **저장소 쓰기 → DB → 옛 파일 지우기** | 되돌릴 수 없는 쪽을 나중에(§3-3). DB 가 실패하면 새 파일만 남고, 옛 파일 지우기가 실패해도 화면은 멀쩡하다(로그만 남긴다) |
| D11 | 비밀번호 변경은 **`POST /api/auth/password { currentPassword, newPassword, client? }`** | 토큰을 새로 내주므로 웹의 리프레시 쿠키(`path: /api/auth`)를 같은 자리에서 다룬다. 로그인과 같은 응답 모양이다 |
| D12 | **틀린 현재 비밀번호는 400** | 401 은 앱 인터셉터가 리프레시로 오인하고(제품 기획 §5.1-a), 403 은 앱이 404 와 같은 실패로 접는다(`classifyDioException`). 새 비밀번호의 길이 · 현재와 같음은 앱이 먼저 막으므로 400 이 오면 현재 비밀번호다 |
| D13 | 바꾸면 **그 사용자의 리프레시 토큰을 전부 끊고, 요청한 기기에는 새 세션을 준다** | 다른 기기는 액세스 토큰이 만료되는 대로(최대 15분) 로그인 화면으로 간다. 요청한 기기만 끊기지 않는다 |
| D14 | 새 비밀번호는 **가입과 같은 10~128자**, 현재와 같으면 400 | 규칙이 두 벌이면 어긋난다 |
| D15 | 음소거는 **`PUT /api/spaces/:spaceId/channels/:channelId/mute { muted }`** — 멱등. 볼 수 없는 채널은 404 | 권한은 열람이다(§3-9 — 남에게 번지지 않는 내 설정). 공개 채널은 `channel_members` 행이 없을 수 있어 **upsert** 한다(7-4 의 LEFT JOIN 과 같은 사정) |
| D16 | 음소거하면 **내 다른 기기**에 `channel:muted` 를 보낸다(사용자 룸) | 받는 사람마다 다른 값이라 스페이스 룸에 싣지 않는다(§3-6) |
| D17 | 음소거의 **지금 효과는 채널 목록뿐**이다 — 이름을 흐리게, **안 읽은 굵기 · 뱃지를 끈다. 멘션 뱃지는 남긴다** | 디스코드와 같다. 나를 부른 것은 음소거해도 놓치면 안 된다. 알림을 막는 효과는 18단계가 알림을 만들 때 더한다 — 동작하지 않는 스위치를 두지 않는다는 규칙과 어긋나지 않게, 설정 창에는 「목록에서 흐리게 · 안 읽음 표시 끄기」 라고 지금 효과를 그대로 적는다 |
| D18 | 알림 섹션은 **스페이스 하나를 골라 그 채널들**을 보인다. 기본은 설정을 연 스페이스(`?space=`) | 채널은 스페이스마다 있다. 스페이스를 넘나드는 한 목록은 이름이 겹친다 |
| D19 | 아바타는 새 위젯 **`UserAvatar`** 가 그린다 — 사진이 있으면 인증 헤더를 붙인 `Image.network`, 없거나 실패하면 지금의 이니셜 | 첨부 미리보기와 같은 방식(`authHeaders`). 실패해도 자리가 비지 않는다. `NexusAvatar` 는 스페이스 아이콘 · 이니셜로 남는다 |
| D20 | drift 는 **`cached_channels.muted` 한 컬럼**만 는다(`schemaVersion` 17). 작성자 사진 · 이름은 이미 있는 칸을 고친다 | 캐시는 통째 재생성이라 옮길 것이 없다. 전송 큐 스키마는 건드리지 않는다 |

## 1. API

```
PATCH  /api/me                      { name }              → 200 PublicUser   (기존. avatarUrl 을 받지 않는다)
PUT    /api/me/avatar               multipart file        → 200 PublicUser
DELETE /api/me/avatar                                     → 200 PublicUser
GET    /api/users/:userId/avatar                          → 200 image/webp | 404
POST   /api/auth/password           { currentPassword, newPassword, client? }
                                                          → 200 { accessToken, refreshToken? }
PUT    /api/spaces/:spaceId/channels/:channelId/mute  { muted } → 200 { channelId, muted }
```

| 조건 | 응답 |
|---|---|
| 아바타 파일이 없음 · 이미지가 아님 · `sharp` 가 못 읽음 | 400 |
| 아바타 파일 5MB 초과 | 413(multer 한도 — 첨부와 같다) |
| 아바타: 본인도 아니고 함께 쓰는 스페이스도 없음 · 사진 없음 · 없는 사용자 | 404 |
| 비밀번호: 현재가 틀림 · 비밀번호 없는 계정 | 400 |
| 비밀번호: 새 것이 10자 미만 · 128자 초과 · 현재와 같음 | 400 |
| 음소거: 볼 수 없는 채널 · 다른 스페이스의 채널 | 404 |

### 실시간

| 이벤트 | 룸 | 페이로드 |
|---|---|---|
| `user:updated` | 그 사용자가 속한 스페이스 룸 전부 + 본인 사용자 룸 | `{ userId, name, avatarUrl }` |
| `channel:muted` | 본인 사용자 룸 | `{ spaceId, channelId, muted }` |

`user:updated` 는 이름과 사진 어느 쪽이 바뀌어도 **둘 다** 싣는다 — 받는 쪽이 무엇이
바뀌었는지 가리지 않고 덮어쓰면 된다.

### 아바타 응답 헤더

`Content-Type: image/webp` · `Cache-Control: private, max-age=31536000, immutable`.
주소에 버전이 있어 바뀌면 다른 주소다. `private` 는 공유 캐시(프록시)에 남지 않게 한다.

## 2. 저장

```sql
ALTER TABLE users ADD COLUMN avatar_key TEXT;
UPDATE users SET avatar_url = NULL;   -- D9. 앱이 한 번도 그리지 않은 임의 URL
```

- 키: `avatars/<userId>/<uuid>.webp`. 버전 `v` 는 uuid 앞 8자
- 아바타 행을 따로 두지 않는다 — 사용자당 하나이고 이력이 필요 없다
- 사용자 삭제 기능이 없어 파일 정리 경로도 지금은 없다(배포 전 사용자 삭제를 만들 때 함께)

## 3. 앱

### 설정 창

```
/settings/:section?space=<spaceId>
  SettingsFrame (app_shell.dart) ── 데스크톱 · 태블릿: [목록 220px | 내용]
                                 └─ 모바일: /settings = 목록, /settings/:section = 내용 + 뒤로
```

| 섹션 | 내용 |
|---|---|
| 내 계정 | 사진(96px 미리보기 · 「사진 바꾸기」 · 「사진 지우기」) · 표시 이름(저장 버튼, 1~50자) · 이메일(읽기 전용) |
| 비밀번호 | 현재 · 새 비밀번호 · 새 비밀번호 확인. 새 것이 10자 미만 · 128자 초과 · 현재와 같음 · 확인과 다름이면 보내지 않는다 |
| 알림 | 스페이스 고르기 → 채널마다 음소거 스위치. 설명: 「음소거한 채널은 목록에서 흐리게 보이고 안 읽음 표시가 꺼집니다. 나를 부른 멘션은 그대로 보입니다」 |
| 화면 | 테마 — 시스템 설정 · 라이트 · 다크 |

목록 맨 아래에 로그아웃. 데스크톱은 **Esc** 와 오른쪽 위 닫기 버튼으로 나간다(디스코드).
닫으면 들어오기 전 화면으로 돌아간다(`pop`, 없으면 `/spaces`).

### 반영

| 무엇이 | 어디를 고치나 |
|---|---|
| 내 이름 · 사진(응답) | `AuthSignedIn.user` · `AuthStorage.writeUser` · 아래 drift 전부 |
| `user:updated`(남 · 내 다른 기기) | drift `cached_messages` · `outbox_messages` 의 작성자명 · 사진, `cached_issues` 의 담당자명 · 사진, `spaceMembersProvider` 무효화. 내 것이면 인증 상태도 |
| 음소거(응답 · `channel:muted`) | drift `cached_channels.muted` |
| 비밀번호(응답) | `ApiClient` 가 새 토큰 쌍을 저장 |

`SocketEvent` 가 `sealed` 라 `UserUpdated` · `ChannelMuted` 를 더하면 `socket_controller.dart`
의 `switch` 도 함께 고친다(§2 함정).

### 실패 문구

앱이 자기 문구를 쓴다(§3 앱 규칙). 비밀번호 `badRequest` → 「현재 비밀번호가 맞지 않습니다」,
아바타 `tooLarge` → 「5MB 이하 사진만 올릴 수 있습니다」, 아바타 `badRequest` → 「이미지 파일만
올릴 수 있습니다」, `network` → 「서버에 닿지 않습니다」.

## 4. 범위에서 뺀 것

| 무엇 | 이유 |
|---|---|
| 사진 자르기 · 위치 조정 화면 | 패키지 없이 만들기엔 크고, 가운데 자르기로 대부분 충분하다. 요구가 생기면 |
| 이메일 변경 | 확인 메일을 보낼 수단이 없다 |
| 계정 삭제 | 스페이스 소유권 이전 · 메시지 처리 규칙이 먼저다. 배포 전에 |
| 다른 기기 소켓 즉시 끊기 | 비밀번호를 바꿔도 다른 기기의 소켓은 다음 재연결까지 붙어 있다(액세스 토큰 15분). 즉시 끊으려면 세션을 소켓에 묶어야 한다 — 18단계 알림 · «마지막» 보안 점검 때 |
| 로그인 · 비밀번호 변경 시도 횟수 제한 | 인증 전체에 없다. 한 곳만 막으면 의미가 없어 «마지막» 배포 준비에서 함께 |
| 푸시 · 데스크톱 알림 스위치 | «마지막» 단계가 알림을 만들 때 「알림」 섹션에 더한다 |
| 스페이스별 표시 이름(닉네임) | 디스코드에는 있지만 개인 개발자 도구에 필요하지 않다 |

## 5. 검증

### `check:settings` (새 계약 검증)

실서버 · 실DB · 실소켓. 자체 계정 셋(alice · bob 은 스페이스를 함께 쓰고 carol 은 남).

- 이름: 바꾸면 응답에 반영 · bob 에게 `user:updated` 도착 · carol 에게 안 감 · 이후 메시지 작성자명이 새 이름 · 빈 이름 400 · 51자 400 · `avatarUrl` 을 보내면 400(D9)
- 사진: PNG 올리기 200 · `avatarUrl` 이 `/users/<id>/avatar?v=` 꼴 · bob 이 받으면 200 `image/webp` 이고 **256×256**(WebP 헤더로 확인) · 본인 200 · carol 404 · 없는 사용자 404 · 다시 올리면 `v` 가 바뀜 · 옛 주소도 새 사진(버전은 캐시 키일 뿐) · 이미지 아닌 파일 400 · 5MB 초과 413 · 지우면 `avatarUrl` null · 지운 뒤 404 · 메시지 응답의 작성자 `avatarUrl` 이 같은 값 · `user:updated` 가 bob 에게
- 비밀번호: 틀린 현재 400 · 9자 400 · 현재와 같음 400 · 성공 200 새 토큰 · **옛 리프레시 토큰 401** · 새 리프레시 토큰은 리프레시됨 · 옛 비밀번호 로그인 401 · 새 비밀번호 로그인 200
- 음소거: 켜기 200 · 채널 목록에 `muted: true` · 두 번 켜도 200(멱등) · 끄기 · 비공개 채널(멤버 아님) 404 · 다른 스페이스 id 로 404 · 내 두 번째 소켓에 `channel:muted` · bob 에게 안 감 · **음소거가 읽음 위치를 바꾸지 않는다**(upsert 가 `last_read_*` 를 덮지 않음)

### 단위

- 아바타 가공 함수(256 · WebP · 투명 PNG · 가로로 긴 사진 가운데 자르기)
- 아바타 열람 판정(본인 · 공유 스페이스 · 남)
- 비밀번호 변경 서비스(틀림 · 같음 · 성공 시 전부 끊고 새 family)

### 앱

- `user:updated` 를 drift 에 반영(메시지 · 큐 · 이슈) — 인메모리 drift
- 음소거 컬럼 · 채널 목록 표시(흐림 · 안 읽음 끔 · 멘션 유지) 위젯 테스트
- 설정 창 — 비밀번호 폼의 앱 쪽 검증(짧음 · 확인 불일치 시 API 를 부르지 않음)
- **`app:flow` 에 설정 창을 더한다** — 설정 열기 → 이름 바꾸기 → 채널의 내 메시지 작성자명이 바뀜 → 테마 바꾸기 → 닫기

### 화면 확인

Windows 로 네 섹션 · 사진 올리기(실제 파일) · 좁은 창(모바일 폭)에서 목록 → 섹션 흐름.
