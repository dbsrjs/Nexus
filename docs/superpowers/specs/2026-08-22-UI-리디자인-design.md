# UI 리디자인 — 토큰 층과 셸 통합 설계

2026-08-22

시각 결과물은 [디자인 캔버스](https://claude.ai/code/artifact/daaa8d16-8f3c-48f0-9b6c-419737f522e2)에
있다(10화면 + 방향 참고 3장). 이 문서는 **그것을 코드로 옮길 때의 판단**만 적는다.

## 1. 문제 — 둘이고, 성격이 다르다

**(가) 토큰 층이 얕다.** `theme.dart` 에 `CardTheme` · `AppBarTheme` ·
`ChipTheme` · `ListTileTheme` 이 **하나도 없다**. 카드 5곳이 Material 기본값
(12px 라운드 + 그림자)으로 뜨고, 앱바도 기본값이다. 디자인 시스템을 만들어
놓고 그 위에 Material 기본값이 얹혀 있는 상태다.

거기에 타이포 램프가 13 · 14 · 16 에 몰려 있어 본문과 메타가 같은 무게로
읽힌다. 라운드도 4 · 6 뿐이라 카드와 칩이 구분되지 않는다.

**그리고 폰트가 갈라져 있다.** `fontFamily` 를 `ThemeData` 에 넘기지 않고
`body()` · `ui()` 안에서 스타일마다 개별로 넣었다. 그래서 `textTheme` 에
적지 않은 스타일은 그 폰트를 못 받는다 — 코드가 실제로 쓰는
**`titleSmall`(12곳) · `labelMedium`(6곳)이 정의돼 있지 않아 18곳이 시스템
기본 폰트로 그려진다.** 한 화면에 폰트가 둘 섞여 있다는 뜻이고, "안 예뻐"에
직접 기여하는 종류다. 눈으로는 원인을 짚기 어렵고 코드를 읽어야만 보인다.

**(나) 껍데기가 둘이다.** `router.dart` 는 `AppShell` 로 `c/:channelId`
하나만 감싼다. 이슈 · 스프린트 · 파일 · 저장소는 `Scaffold + AppBar` 전체
화면이라, 보드를 열면 스페이스도 채널도 사라진다.

이것은 실수가 아니라 적힌 판단이다 — *"셸 위에 덮어서 연다 — 대화의
곁가지라 돌아오는 길이 분명한 편이 낫다."* **그 전제 하나에만 이의를 단다:
이슈 보드와 스프린트는 곁가지가 아니라 나란한 주 기능이다.**

## 2. 목업을 토큰에 맞춘다 — 반대가 아니다

캔버스에 14.5 · 15.5 · 10.5px 같은 **반 단계**를 썼다. 손으로 그리다 나온
값이고 토큰 스케일에는 없다. `tokens.css` 헤더가 *"Flutter core/theme.dart 는
이 파일의 토큰 이름을 그대로 따른다"* 고 약속하고 있으므로, **틀린 쪽은
목업이다.**

반 단계를 스케일에 밀어 넣지 않는다. 진짜로 빠진 것 하나만 더한다.

| | 지금 | 바꾼 뒤 | 왜 |
|---|---|---|---|
| `--text-body` | **없음** | **15px** | 14 다음이 16이라 본문 읽기 크기가 없다. 메시지 · 이슈 본문 · 댓글이 여기 온다 |
| `--leading-body` | 1.5 | **1.6** | 한글 본문에서 1.5 는 빽빽하다 |
| `--r-md` | 6px | **8px** | 카드 · 입력창 · 버튼. 6은 딱딱하고 12(Material 기본)는 코드·표에서 겹친다 |
| `--r-sm` | 4px | 4px (유지) | 인라인 코드 · 작은 배지 |
| 그 밖의 크기 | — | 유지 | 이름 14 · 화면 제목 16 · 메타 11 로 **스냅한다** |

`--r-md` 를 바꾸면 토큰을 쓰는 **19곳이 자동으로 따라온다.** 토큰을 안 쓰고
숫자를 박은 **11곳**은 손으로 고친다(§4).

## 3. 없던 컴포넌트 테마를 만든다

이 조각의 값어치 대부분이 여기 있다. 네 개를 더한다.

- **`CardTheme`** — 배경 `bgSurface`, 라운드 `r-md`, **`elevation: 0`**,
  테두리 없음. 그림자를 쓰지 않는 이유는 이 팔레트가 표면 셋(`base` ·
  `surface` · `elevated`)으로 깊이를 표현하도록 만들어져 있기 때문이다.
  그림자를 얹으면 두 체계가 겹쳐 탁해진다
- **`AppBarTheme`** — 배경 `bgBase`, `elevation: 0`, `scrolledUnderElevation: 0`,
  제목 16/600. 지금은 스크롤하면 Material 이 색을 바꿔 헤더가 혼자 떠 보인다
- **`ChipTheme`** — 라운드 `full`, 배경 `bgElevated`, 테두리 없음, 라벨 12.
  라벨 칩만 자기 색을 얹는다(`label_widgets.dart` 의 규칙 유지)
- **`ListTileTheme`** — 라운드 `r-md`, 선택 시 `accent-subtle`.
  목록이 많은 앱이라 이것 하나가 저장소 · 파일 · 스페이스 화면에 다 걸린다

## 4. 토큰을 안 쓰는 11곳

`BorderRadius.circular(6|8|12|3|999)` 가 박혀 있다. 전부 토큰으로 바꾼다.

| 파일 | 개수 | 처리 |
|---|---:|---|
| `chat_screen.dart` | 6 | 6·8 → `r-md`, 12 → `r-md`, 8 → `r-md` |
| `markdown_body.dart` | 3 | 3 → `r-sm`, 6 → `r-md` |
| `channel_list.dart` | 2 | 999 → `r-full` |

**값을 그대로 두고 토큰만 씌우지 않는다.** 지금 6 · 8 · 12 가 섞여 있는 것
자체가 문제이므로 전부 `r-md`(8)로 모은다.

## 5. 셸 통합 — 라우트가 진실의 원천이라는 전제를 지킨다

`app_shell.dart` 의 주석이 못 박아 두었다 — *"본문을 탭으로 갈아 끼우면
'라우트가 진실의 원천'이라는 이 셸의 전제가 깨진다."* **그 전제를 지키면서
셸을 유지하는 방법이 `ShellRoute` 다.**

`go_router` 의 `ShellRoute` 는 자식 라우트를 그리는 동안 셸을 마운트한 채로
둔다. 라우트는 여전히 진실의 원천이고, 셸만 다시 만들어지지 않는다.

```
ShellRoute(builder: (_, __, child) => AppShell(child: child))
  └ /s/:spaceId/c/:channelId      대화        ← 셸 안
  └ /s/:spaceId/issues            이슈 보드    ← 셸 안 (새로)
  └ /s/:spaceId/issues/:key       이슈 상세    ← 셸 안 (새로)
  └ /s/:spaceId/sprints           스프린트     ← 셸 안 (새로)
  └ /s/:spaceId/files             파일        ← 셸 안 (새로)
  └ /s/:spaceId/repos             저장소 목록  ← 셸 안 (새로)
  └ /s/:spaceId/repos/:id/browse  저장소 열람  ← 셸 안 (새로)

셸 밖(덮어서 연다) — 그대로 둔다
  └ …/c/:channelId/t/:messageId   스레드
  └ …/repo-events/:eventId        커밋 목록
  └ …/repos/:id/commits[/:sha]    커밋 목록 · 상세
```

**가르는 기준: 한 번 가서 머무는 곳은 셸 안, 보고 돌아오는 곳은 덮어서.**
스레드와 커밋은 특정 메시지·특정 저장소에서 파고드는 것이라 돌아오는 길이
분명해야 한다 — 원래 판단이 맞다.

**`AppShell` 이 `child` 를 받게 된다.** 지금은 `channelId` 를 받아 본문을
스스로 고르는데, `ShellRoute` 아래에서는 무엇을 그릴지 라우터가 정한다.
`_syncRoute()` 가 하던 일(스페이스·채널 id 를 컨트롤러에 싣기)은 남는다 —
다만 채널 id 는 대화 라우트에서만 채워진다.

## 6. 두 번째 판에 `작업` 섹션

`channel_pane.dart` 에 섹션 하나를 더한다 — 이슈 보드 · 스프린트 · 파일.
저장소 섹션은 이미 있다. **구조를 새로 만드는 것이 아니라 있던 것을 끝까지
쓰는 것이다.**

모바일 하단 탭도 같은 갈래로 맞춘다(대화 · 이슈 · 저장소 · 파일).
지금 `_onTab(1)` 이 `context.push('/issues')` 로 덮어서 여는데, 셸 안으로
들어오므로 `go` 로 바뀐다.

## 7. 범위 밖

| 뺀 것 | 이유 |
|---|---|
| 화면별 세부 재작업 | 이 조각은 **토큰 층과 구조**다. 목업의 화면별 디테일(보드 카드 취소선, 커밋 행 배치 등)은 그 뒤에 화면마다 따로 |
| GitHub 로그인 | 사용자가 뒤로 미뤘다. state 의 userId 필수 · scope · 세션 전달 경로 세 결정이 먼저다 |
| 라이트 모드 재점검 | 토큰이 뒤집히므로 따라오지만, 눈으로 확인하는 것은 별도 |
| 드래그로 이슈 이동 | 9-1 에서 미룬 그대로 |
