# 서버 통합 테스트 층을 CI 에 태운다 — 설계

2026-08-21

## 1. 문제

계약 검증 스크립트 11종(4,765줄 · **398 + 41 케이스**)이 **CI 에서 한 번도 돌지
않는다.** `.github/workflows/ci.yml` 의 서버 잡은 `lint · build · test(단위 160개)
· check:migrations` 만 돌리고 **DB 가 아예 없다.**

그래서 이 층은 사람이 `db:up` 과 `server:dev` 를 띄우고 명령을 직접 타이핑할
때만 돈다. 컨트롤러 · 서비스 · 스키마 · 직렬화를 덮는 것이 이 스크립트들뿐인데,
그것이 도는지 여부가 사람의 기억에 달려 있다.

**CLAUDE.md §6 이 말하는 두 버그(BigInt 직렬화 · raw SQL `::uuid` 캐스팅)가 살던
자리가 정확히 이 층이다.** 단위 테스트는 Prisma 를 스텁으로 바꾸므로 그 둘을
잡을 수 없었고, 실제 DB 를 붙이자마자 나왔다.

## 2. 실측 — 설계의 축 하나를 지웠다

작업 전에 11개를 실제로 돌려 쟀다(실서버 · 실DB, 이 PC).

| 스크립트 | 시간 | 케이스 |
|---|---:|---:|
| `check:issues` | 5.7s | 89 |
| `check:threads` | 3.4s | 25 |
| `check:reactions` | 3.4s | 24 |
| `check:pins` | 3.3s | 20 |
| `check:quotes` | 1.7s | 17 |
| `check:attachments` | 1.4s | 43 |
| `check:browse` | 1.3s | 56 |
| `check:mentions` | 1.2s | 18 |
| `check:oauth` | 1.1s | 76 |
| `check:repos` | 1.1s | 30 |
| `check:migrations` | 0.8s | — |
| **합계** | **~25초** | **398** |
| `check:realtime` | 미측정 | 41 |

**전체가 30초 안쪽이다.** "가벼운 것만 push 마다, 무거운 것은 nightly" 같은
계층을 만들 이유가 없다 — **전부 매번 돌린다.** 재지 않았다면 이 계층을
설계하느라 시간을 썼을 것이고, 그것이 이 문서에서 가장 값싸게 얻은 결정이다.

`check:realtime` 만 못 쟀다. 시드가 기존 계정의 비밀번호를 덮어쓰지 않아
(`upsert` 의 `update` 가 `name` 만 건드린다) 이 PC 에서는 그 값을 알 수 없다.
**CI 는 DB 가 매번 새것이라 `SEED_PASSWORD` 를 고정하면 그대로 돈다** — 로컬보다
CI 가 쉬운 유일한 항목이다.

## 3. 접근 — 러너가 아니라 배치를 먼저 고친다

세 가지를 놓고 골랐다.

- **A. 스크립트를 그대로 CI 에 태운다.** 코드를 안 고치고 398 케이스가 즉시
  push 마다 돈다. 손으로 짠 `check()` 는 그대로 남는다
- **B. Jest e2e(supertest + Nest Testing 모듈)로 다시 쓴다.** 프레임워크가
  assertion · 격리 · 리포팅을 맡는다
- **C. A 를 먼저, 러너 교체는 다음 조각으로** ← **채택**

**B 를 고르지 않은 이유는 그것이 덮는 범위를 좁히기 때문이다.** Nest Testing
모듈은 `main.ts` 를 타지 않는다. `enableBigIntSerialization()` · `rawBody: true` ·
전역 파이프 · 전역 예외 필터가 전부 거기 있고, §1 이 말한 그 BigInt 버그가
정확히 그 자리에서 났다. 10-3a 에서 잡은 `Retry-After` 결함도 **전역 예외 필터가
본문을 다시 빚으면서** 커스텀 필드를 버린 것이었다 — 필터를 타지 않는 테스트로는
영영 안 보인다.

즉 **바꾸고 싶은 것은 검증 방식이 아니라 러너다.** 진짜로 부팅한 서버에 밖에서
HTTP · 소켓으로 붙는 지금 구조는 이 프로젝트에서 실제로 버그를 잡아 왔다.
그 강점은 지키고, 약점(손으로 짠 `check()`, 거짓 통과를 구조적으로 못 막는 것)만
다음 조각에서 프레임워크로 바꾼다.

## 4. CI 잡 구조

### 4.1 별도 잡으로 둔다

`ci.yml` 에 **`서버 통합` 잡**을 더한다. 기존 `서버` 잡과 **병렬**이고 합치지
않는다. 근거는 그 파일 맨 위 주석에 이미 있다 — *"한쪽이 깨져도 다른 쪽 결과를
봐야 원인을 좁힐 수 있다."* 순수 로직이 깨진 것과 DB · 직렬화가 깨진 것은
**다른 신호이고, 고치는 사람도 보는 곳이 다르다.**

### 4.2 단계

```
services:
  postgres: pgvector/pgvector:pg16      ← 순정 postgres 는 init 마이그레이션이
                                          CREATE EXTENSION "vector" 에서 죽는다
steps:
  npm ci
  prisma:generate                       ← Prisma Client 는 생성물이라 저장소에 없다
  prisma:deploy
  db:seed  (SEED_PASSWORD 고정)          ← check:realtime 이 이 계정으로 로그인한다
  npm run build
  node dist/main &                      ← 빌드본을 띄운다. start:dev 가 아니다
  준비될 때까지 폴링                      ← 고정 sleep 금지
  check:migrations
  check:realtime -- $SEED_PASSWORD
  check:reactions · threads · quotes · mentions · pins
  check:attachments · issues · repos · oauth · browse
  (실패 시) 서버 로그 덤프                ← if: failure()
```

**`dist/main` 을 띄우는 것이 이 층의 존재 이유다**(§3). 개발용 watch 모드가
아니라 배포와 같은 진입점을 태운다.

**준비 대기는 폴링이다.** 고정 `sleep` 은 느린 러너에서 먼저 깨지고, 빠른
러너에서는 시간을 버린다.

### 4.3 환경변수는 워크플로에 그대로 적는다

`secrets` 를 쓰지 않는다. 값이 전부 **검증 전용 가짜**이기 때문이다.

| 키 | 값 | 왜 가짜여도 되나 |
|---|---|---|
| `GITHUB_OAUTH_BASE` · `GITHUB_API_BASE` | `http://127.0.0.1:4599` | 스크립트가 그 포트에 가짜 GitHub 을 띄운다 |
| `GITHUB_CLIENT_ID` · `SECRET` | `check-…` | 가짜 GitHub 이 값을 검사하지 않는다 |
| `PUBLIC_BASE_URL` | `http://127.0.0.1:3000` | 가짜 GitHub 이 훅 URL 을 검사하지 않는다 |
| `JWT_SECRET` · `OAUTH_TOKEN_KEY` | CI 전용 고정값 | 이 DB 는 잡이 끝나면 사라진다 |

`secrets` 에 넣으면 **포크에서 온 PR 이 조용히 못 돌고**, 새 PC 에서 재현도
안 된다. 그리고 가짜값을 `secrets` 에 두는 것 자체가 "여기 진짜 비밀이 있다"는
잘못된 신호가 되어, 나중에 누군가 그 자리에 진짜 키를 넣게 만든다.
**공개 저장소에 진짜 키를 적지 않는다는 원칙과 충돌하지 않는다** — 이 값들은
비밀이 아니다.

### 4.4 실패했을 때 읽히게 한다

**실패 시 백그라운드 서버의 stdout 을 덤프한다**(`if: failure()`).

이것을 설계에 넣은 이유는 오늘 그대로 겪었기 때문이다. `.env` 에
`PUBLIC_BASE_URL` 이 없어 `check:browse` 가 **37개 실패**로 무너졌는데, 화면에
보인 것은 빨간 줄 37개였고 원인은 그중 첫 줄의 400 응답 본문 안에만 있었다.
CI 에서는 그 원문마저 안 보이면 빨간 X 를 보고도 원인을 못 찾는다.

## 5. 전제조건을 한 줄로 말한다

### 5.1 진짜 원인은 `.env` 가 아니다

오늘 37개가 무너진 진짜 이유는 설정이 아니라 **스크립트가 준비 단계(setup)의
실패를 케이스 실패로 취급한 것**이다.

```
FAIL  저장소 준비 {"statusCode":400,"message":"서버의 공개 주소(PUBLIC_BASE_URL)가 없어…"}
FAIL  브랜치 200 400
FAIL  두 건이 온다
… 34줄 더
```

첫 줄은 "케이스 하나가 틀렸다"가 아니라 **"더 볼 것이 없다"**는 뜻이다. 준비가
안 됐으면 뒤의 케이스들은 검증한 것이 아니라 **검증하지 못한 것**인데, 지금
출력은 둘을 구분하지 못한다.

### 5.2 공용 헬퍼

`server/scripts/lib/preflight.mjs` 하나를 둔다.

- **`reachable(base)`** — 서버가 안 떠 있으면 한 줄로 안내하고 중단한다.
  **서버가 필요한 11개**가 맨 위에서 부른다(각 한 줄). `check:migrations` 는
  DB 도 서버도 없이 도는 정적 검사라 대상이 아니다
- **`setup(name, res, hint)`** — 준비 단계 호출이 실패하면 `check()` 로 세지
  않고 **즉시 중단**한다. 서버가 준 메시지 원문과 힌트를 함께 찍는다
- 알려진 실패에 힌트를 붙인다. 예: `PUBLIC_BASE_URL` 400 →
  *"docs/10-2a-인수인계.md §2.3 을 볼 것 — 계약 검증에서는 아무 http 주소면 된다"*

**중단도 종료 코드 1 이다.** CI 는 빨간 X + 읽히는 한 줄을 받는다.

이번 조각에서 `setup()` 을 적용하는 곳은 **오늘 실제로 무너진 둘**
(`check:browse` · `check:oauth`)이다. 나머지는 자기 계정을 스스로 만들어
전제조건이 없다 — 넓히지 않는다.

### 5.3 `.env.example`

`PUBLIC_BASE_URL` 은 이미 있지만 값이 비어 있고, 주석은 *"비워 두면 자동
등록만 400"* 이라고만 말한다. 사실이지만 **계약 검증이 통째로 무너진다는 말은
없다.** 그 한 줄을 더한다. 값은 비운 채로 둔다 — 빈 값도 정당한 설정이다.

## 6. 범위 밖 — 그리고 이유

| 뺀 것 | 이유 |
|---|---|
| `STORAGE_DRIVER=s3` 2회차(MinIO) | 배포 전 수동 확인 항목이다. 서비스 컨테이너를 하나 더 늘릴 값이 아직 없다 |
| `check:oauth` 의 **미설정 503 분기** | env 를 비운 채 서버를 한 번 더 띄워야 한다. 그 자리에 있던 결함 둘은 이미 고쳐졌고 단위 테스트(`oauth.config.spec` · `token-crypto.spec`)가 덮는다 |
| 손으로 짠 `check()` → 프레임워크 | **C 의 2조각.** 이번 조각은 배치까지다 |
| 앱(Flutter) 통합 테스트 | 다른 층이다. 앱 잡은 그대로 둔다 |

## 7. 성공 기준

1. **push 마다** `서버 통합` 잡이 돌고, 439 케이스(398 + realtime 41)가 통과한다
2. 스크립트 하나를 일부러 깨뜨리면 **CI 가 빨갛게 되고**, 로그에서 어느
   케이스인지 읽힌다
3. `PUBLIC_BASE_URL` 을 지우면 **37줄이 아니라 한 줄**로 원인이 나온다
4. 로컬에서 서버를 안 띄우고 `check:pins` 를 돌리면 한 줄로 안내가 나온다
5. 기존 `서버` · `앱` 잡의 동작이 바뀌지 않는다

## 8. 위험

| 위험 | 대응 |
|---|---|
| 백그라운드 서버가 CI 에서 뜨지 않는데 원인이 안 보인다 | §4.4 의 로그 덤프. 폴링에 상한을 두고 초과 시 로그를 찍고 실패 |
| 스크립트가 서로의 데이터를 밟는다 | 지금도 같은 DB 에서 순차로 돌고 있고 각자 `Date.now()` 로 격리한다. CI 는 DB 가 매번 새것이라 오히려 로컬보다 깨끗하다 |
| `check:realtime` 이 CI 에서만 깨진다 | 이 PC 에서 못 재는 유일한 항목이다. 1조각 검증에서 **CI 로그로 직접 확인한다** |
| 30초가 나중에 5분이 된다 | 그때 §2 를 다시 재고 계층을 만든다. **지금 만들지 않는다** |
