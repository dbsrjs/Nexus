# 계약 검증 스크립트의 공용 하네스 — 설계

2026-08-21

## 1. 문제 — 그리고 문제가 아닌 것

계약 검증 스크립트 11종에 **같은 함수가 11벌씩 복사돼 있다.** 하나를 고치면
열 곳이 뒤처지고, 주소가 바뀌면 열한 곳을 고쳐야 한다.

| 헬퍼 | 복사본 | 실태 |
|---|---:|---|
| `api()` | 11 | 2판본 — `browse` 것만 **`headers` 를 더 준다** |
| `check()` | 11 | 2판본 — **표시만 다름**(`OK/FAIL` vs `✅/❌`) |
| `signup()` | 10 | 구조 동일, **리터럴 3개만 다름** |
| `waitFor()` | 6 | **전부 동일** |
| `connect()` (소켓) | 6 | 2판본 — realtime 것이 **상위집합** |
| `BASE` · `WS` · `stamp` | 11 | 전부 동일 |

**러너를 바꾸는 조각이 아니다.** CLAUDE.md 의 빚 항목은 "손으로 짠 `check()` 가
거짓 통과를 구조적으로 막지 못한다"고 적었고, 그것이 러너를 바꾸면 막힌다는
뜻으로 읽힌다. **그렇지 않다.** 10-2b 에서 겪은 `undefined === undefined` 는
`assert.strictEqual(undefined, undefined)` 로 바꿔도 그대로 통과한다. 그것은
러너의 문제가 아니라 **단언 규율**의 문제이고, 그 케이스는 이미 손으로
고쳐져 있다(`!!manual.json?.id && …`).

그래서 이 조각이 사는 것은 **중복 제거 하나**다. 프레임워크 도입은 범위 밖이다.

## 2. 조사에서 나온 것 — 합쳤으면 버그가 됐을 자리

**`check-browse.mjs` 의 `connect()` 는 이름만 같고 다른 함수다.** 소켓 연결이
아니라 **GitHub 계정 연결**이다.

```js
async function connect(token, seed) {          // browse
  const started = await api('POST', '/me/connections/github/start', { token });
  …
}
```

이름만 보고 `lib/socket.mjs` 로 접었으면 그대로 버그가 됐다. **헬퍼를 합치기
전에 판본을 실제로 비교한 것이 이 조각에서 가장 값이 컸다.**

`connect()` 의 나머지 두 판본은 실제로 갈라져 있는데, realtime 것이 상위집합이다.

```js
auth: { token }                                   // 5벌
auth: token === undefined ? {} : { token }        // realtime — 토큰 없는 연결을 시험한다
```

토큰이 있을 때 둘의 동작은 같고, 없을 때만 realtime 것이 옳다. **상위집합으로
통일한다.**

### 2.1 비교 도구 자체가 틀릴 수 있다 — 실제로 틀렸다

처음 판본을 셀 때 쓴 스크립트가 **함수 본문의 `{` 대신 매개변수 구조분해의
`{ token, body }` 를 잡아** 서명 조각만 해시했다. 그래서 `api()` 가 "11벌 전부
동일"로 나왔는데 **사실이 아니었다.**

```js
return { status: res.status, json };                    // 10벌
return { status: res.status, json, headers: res.headers };  // browse
```

`browse` 는 429 의 `Retry-After` 를 **헤더로** 확인한다 — 전역 예외 필터가
본문을 일정한 봉투로 다시 빚어 커스텀 필드가 살아남지 못하기 때문이다
(10-3a 에서 잡은 결함). 그 한 줄을 놓친 채 합쳤더니 그 케이스가 깨졌고,
**케이스 수 관문이 그것을 잡았다.**

`connect()` 때와 같은 원칙으로 **상위집합**을 취한다 — 공용 `api()` 가
`headers` 를 함께 준다. 쓰지 않는 쪽은 무시하면 된다.

## 3. 모듈 구성

```
server/scripts/lib/
  preflight.mjs   (이미 있음) requireServer · abortUnless · hintFor · PreflightAbort
  checks.mjs      check · summary
  api.mjs         BASE · stamp · api · signup
  socket.mjs      WS · connect · waitFor
```

**한 파일로 모으지 않는다.** `socket.mjs` 만 `socket.io-client` 를 import 하므로,
소켓을 쓰지 않는 다섯(`attachments` · `mentions` · `oauth` · `repos` · `browse`)이
그것을 로드하지 않는다. 그리고 HTTP · 소켓 · 보고가 한 파일에 섞이는 것은
지금 걷어내려는 모양 그 자체다.

`BASE` · `WS` 를 모듈 안에 두는 것이 핵심이다 — **주소를 아는 곳이 하나여야
한다.** 앱의 `core/env.dart` 규칙과 같은 판단이다.

## 4. `check()` 의 상태

`check()` 는 `pass` · `fail` 을 들고 있어 순수 함수가 아니다. **각 스크립트가
자기 프로세스라 모듈 수준 상태로 충분하다** — 프로세스마다 모듈이 새로
로드되므로 격리가 공짜다. 팩토리(`createChecker()`)를 만들 이유가 없다.

```js
export function check(name, ok, detail = '') { … }   // OK / FAIL
export function summary() { … }                      // "통과 N · 실패 N" + exitCode
```

표시는 **`OK` / `FAIL`** 로 통일한다(지금 7벌이 쓰는 쪽이고 grep 이 쉽다).
집계 줄은 **`통과 N · 실패 N`** 으로 통일한다(10벌이 쓰는 쪽. realtime 만
`/` 를 쓴다).

**꼬리 정리는 각 스크립트에 남긴다.** `browse` · `oauth` 는 가짜 서버를 닫아야
하고 `realtime` 은 소켓을 끊어야 하는데, 그 순서는 Windows libuv 의
`UV_HANDLE_CLOSING` 때문에 조심스럽게 짜여 있다. `summary()` 는 집계와 종료
코드만 맡고 **정리에 관여하지 않는다.**

## 5. `signup()` 매개변수화 — 이름이 짐을 지고 있다

10벌이 이메일 접두사 · 비밀번호 · 이름 셋만 다르다. 몸통 15줄은 같다.

```js
// signup('pin', 'a') → pin-a-<stamp>@example.com / check-pin-1234 / pin검증a
export async function signup(prefix, tag, name = `${prefix}검증${tag}`) { … }
```

**이름을 기계적으로 바꾸면 안 된다.** `check-mentions.mjs` 는 계정 이름을
**단언에 쓴다.**

```js
mentioning.json.mentions[0].name === '멘션검증b'
await send(alice.token, { body: '@멘션검증b 이건 그냥 텍스트다' })
```

이름이 그 스크립트에서는 장식이 아니라 **입력이자 기대값**이다. 그래서
`name` 을 세 번째 인자로 열어 두고, **`check-mentions.mjs` 는 자기 이름을
명시적으로 넘긴다**(`signup('mention', tag, `멘션검증${tag}`)`). 나머지 아홉은
이름이 어디에도 쓰이지 않으므로 기본값을 받는다.

기본값이 한글(`pin검증a`)인 것은 지금 모양을 유지하기 위함이다. 계정 이름은
slug 가 되지 않아 10-2b 의 한글 slug 함정과는 무관하다 — **그 함정은 스페이스
이름에서 났고, 그쪽은 이 조각이 건드리지 않는다.**

`stamp` 도 `api.mjs` 가 들고 있게 한다 — 지금은 11벌이 각자 `Date.now()` 를
부른다. 한 프로세스 안에서 값이 하나여야 한다는 뜻이 모듈로 표현된다.

## 6. 건드리지 않는 것

| | 이유 |
|---|---|
| 케이스와 단언 내용 | 한 줄도 고치지 않는다. 이 조각은 검증의 내용이 아니라 모양을 바꾼다 |
| 각 스크립트의 꼬리 정리 순서 | §4 — libuv 문제 때문에 그 자리에 있다 |
| `check-migrations.mjs` | DB 도 서버도 없이 도는 정적 검사다. 헬퍼를 쓰지 않는다 |
| `check-browse.mjs` 의 `connect()` | §2 — 다른 함수다. **`connectGithub()` 으로 이름만 바꿔** 다시 헷갈리지 않게 한다 |

## 7. 회귀 관문

**케이스 수가 그대로여야 한다.** 이 조각에 이보다 나은 관문이 없다 — 내용을
안 고치므로 수가 바뀌면 그것이 곧 결함이다.

```
browse 56 · oauth 76 · issues 89 · attachments 43 · repos 30
threads 25 · reactions 24 · pins 20 · mentions 18 · quotes 17
```

**`check:realtime` 41 은 이 PC 에서 못 돈다** — 시드가 기존 계정의 비밀번호를
덮어쓰지 않아 값을 알 수 없다. CI 로그로 확인한다. 그 스크립트의 조기 종료
경로가 전부 `process.exit(1)` 이라 **종료 코드 0 은 41개를 다 돌고 실패가 0
이었을 때만 가능하다.**

## 8. 성공 기준

1. 열 개 스크립트의 케이스 수가 **위 값과 정확히 같다**
2. `check:realtime` 이 CI 에서 통과한다
3. 헬퍼 중복이 없다 — `api` · `signup` · `connect` · `waitFor` · `check` 의
   정의가 각각 **한 곳에만** 있다
4. `BASE` · `WS` · `stamp` 를 선언하는 곳이 각각 하나다
5. 서버를 끈 채 돌리면 여전히 한 줄로 안내한다(10-3 이후 붙인 preflight 유지)
6. CI 의 `서버 통합` 잡이 초록이다

## 9. 범위 밖

| 뺀 것 | 이유 |
|---|---|
| 러너 교체(node:test · Jest) | §1 — 이번에 사는 것은 중복 제거다 |
| 단언 규율 장치 | 러너와 무관한 별개 문제다. 필요성이 다시 드러날 때 한다 |
| 케이스 추가 | 모양을 바꾸는 조각에 내용을 섞지 않는다 |
