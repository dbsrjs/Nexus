# 19 AI 기록 — 설계

> 2026-10-07. [13-3 AI 멀티턴 설계](2026-09-23-13-3-ai-멀티턴-design.md) 가 범위에서 뺀
> 「지난 대화 목록 · 다시 열기」(13-3 D10 · §6)를 연다. 13-3 의 `parentRunId` 사슬 ·
> `POST /ai/ask` · 캐시 · 패널의 문답 목록은 그대로이고 이 문서는 그 위에 얹는다.
> 결정은 사용자가 맡겼다(질문 없이 정하고 결정 목록으로 알린다).

## 0. 무엇이 바뀌나

| | 13-3 | 19 |
|---|---|---|
| 문답 사슬 | 패널을 닫으면 화면에서 사라진다(서버 행은 남는다) | 패널의 **「지난 대화」** 에서 다시 연다 |
| 다시 연 사슬 | — | 마지막 답 아래에서 **그대로 이어 묻는다** |
| 서버 | `GET .../ai/runs/:runId` 하나 | 목록 · 사슬 읽기 두 경로를 더한다 |

### 정한 것

| # | 결정 | 이유 |
|---|---|---|
| D1 | **「지난 대화」는 AI 패널 안에 둔다.** 셸에 새 갈래(라우트 · 탭)를 만들지 않는다 | ① AI 를 여는 곳(채널 · 저장소)이 이미 패널이다 — 기록도 거기서 찾는다 ② 모바일 탭은 이미 다섯이다 — 여섯째를 만들거나 「대화」 탭에 묶으면 탭 표시가 틀린다 ③ 패널 안이면 다시 연 답을 **지금 연 채널에 「채널에 붙이기」** 할 수 있다 — 셸 화면에서 열면 붙일 채널이 없다. 판단 #13 의 「머무는 곳」이 아니라 패널의 한 모드다 |
| D2 | 목록의 한 줄 = **사슬 하나**(뿌리 문답 단위). 행의 id 는 뿌리 `runId` 다 | 18 이전에 적어 둔 출발점(«사슬의 뿌리 단위로 묶어 보인다») 그대로. 사슬을 가리키는 새 id 를 만들지 않는다 |
| D3 | **스키마를 바꾸지 않는다.** 사슬은 재귀 CTE 로 `parent_run_id` 를 따라 내려간다 | 사슬은 최대 10 문답(13-3 D5)이고 개인의 기록이라 행 수가 작다. 뿌리 id 를 비정규화하면 마이그레이션 · 백필 · 적재 코드가 함께 바뀐다 — 얻는 것은 인덱스 하나다. 느려지면 그때 `root_run_id` 를 더한다 |
| D4 | 사슬의 **끝(tip)은 그 사슬에서 가장 늦게 끝난 `done` 문답**이다. 보이는 사슬 = 뿌리에서 끝까지의 경로 | 사슬은 엄밀히는 나무다 — 실패한 질문을 다시 보내면 같은 부모에 형제가 생기고(13-3 §5), 두 기기에서 이어 물어도 갈린다. 실패 · 대기 중인 문답은 보이지 않는다(답이 없다). 「가장 최근에 받은 답」이 사람이 기억하는 대화다 |
| D5 | 목록 정렬은 **끝 문답이 끝난 시각 내림차순**(`coalesce(finished_at, created_at)`, 같으면 뿌리 id) | 다시 열어 이어 물은 대화가 맨 위로 온다. 캐시 적중은 새 답이 아니라 순서를 바꾸지 않는다 |
| D6 | **본인 것만.** 남의 사슬 id 는 404 | 13-1 · 13-3 D7 그대로(「같은 스페이스라도 남의 질문과 답을 읽을 이유가 없다」) |
| D7 | **뿌리의 채널을 지금 볼 수 없으면 목록에서 빼고 열면 404** | 답은 그 채널의 대화로 만든 것이다. 18단계 알림함과 같은 규칙(「비공개 명단에서 빠지면 그 채널의 본문도 더는 보이면 안 된다」). 행은 지우지 않는다 — 다시 들어오면 다시 보인다. 판정은 `ChannelsService.viewableChannelIds()` 한 곳(§2 함정 — 가시성을 Prisma `where` 로 다시 쓰지 않는다) |
| D8 | 기록 읽기는 **LLM 설정과 무관하다** — 미설정이어도 503 이 아니다 | 이미 받은 답을 읽는 데 모델이 필요 없다. 이어 묻기를 보내야 503 이 난다(13-1 그대로) |
| D9 | 목록 항목은 **질문 · 끝 답 미리보기 · 근거 · 문답 수 · 시각**. 미리보기는 서버가 끝 답 원문(마크다운) 앞 200자를 자르고 앱이 평문화한다 | 사슬 전체를 목록에 싣지 않는다. 평문화는 이미 앱에 있다(`shared/markdown` — 알림함과 같은 길) |
| D10 | 근거는 **id 만** 보낸다(`channelId` · `messageIds` · `repoId`). 이름은 앱이 이미 가진 목록(채널 캐시 · 저장소 목록)에서 찾는다 | 서버가 이름을 실으면 판정이 한 겹 더 생긴다. 앱이 모르는 이름이면 일반 이름(「채널」 · 「저장소」)을 쓴다 |
| D11 | 다시 연 사슬의 칩은 **고른 메시지 칩**(`MessagesContext`)과 저장소 칩으로 되살린다 | 13-2 는 「채널 최근 대화」도 실제로 읽은 `messageIds` 를 저장한다 — 둘을 구별할 기록이 없다. 그 답은 바로 그 메시지들로 만든 것이라 「다시 묻기」도 같은 메시지로 가는 편이 일관된다 |
| D12 | 다시 연 패널의 「채널에 붙이기」 · 「이슈 만들기」는 **패널을 연 자리의 것**을 쓴다 | D1 의 결과. 채널에서 연 패널이면 그 채널에 붙이고, 저장소 화면에서 열었으면 버튼이 없다(13-2 그대로) |
| D13 | 목록은 **캐시하지 않는다**(drift 에 넣지 않는다) · 커서 페이지(`?cursor=&limit=`, 기본 20) · 「더 보기」 버튼 | AI 결과를 drift 에 넣지 않는 13-1 의 예외 그대로. 패널 안이라 무한 스크롤보다 버튼이 낫다(목록이 패널 높이를 넘지 않게) |
| D14 | 지우기는 **두지 않는다** | 제품의 「무기한 보관」(메시지 소프트 삭제)과 같은 쪽이다. 부모 삭제가 이미 cascade 라 나중에 뿌리 `DELETE` 하나로 더할 수 있다 |

## 1. API

```
GET /api/spaces/:spaceId/ai/threads?cursor=&limit=
→ 200 {
  items: [{
    rootRunId: string,
    kind: 'summarize' | 'ask' | 'draft_issue',   // 뿌리의 종류
    question: string | null,                      // 뿌리의 지시문. 프리셋이면 null
    preset: 'summary' | 'issue' | null,           // 13-1 행(지시문 없음)은 'summary'
    turnCount: number,                            // 뿌리에서 끝까지 (1~10)
    lastAt: string,                               // 끝 문답이 끝난 시각
    preview: string,                              // 끝 답 원문 앞 200자(이슈 초안은 제목)
    context: { channelId: string | null, messageCount: number | null, repoId: string | null },
  }],
  nextCursor: string | null,                      // 다음 페이지의 기준이 되는 rootRunId
}

GET /api/spaces/:spaceId/ai/threads/:rootRunId
→ 200 {
  rootRunId: string,
  context: { channelId: string | null, messageIds: string[] | null, repoId: string | null },
  turns: [{                                       // 뿌리부터 끝까지
    ...getRun 과 같은 모양(runId · kind · state · result · model · fallback · parentRunId ·
       promptTokens · completionTokens · createdAt · finishedAt),
    instruction: string | null,
    preset: 'summary' | 'issue' | null,
  }],
}
```

| 조건 | 응답 |
|---|---|
| 남의 사슬 · 다른 스페이스 · 없는 id | 404 |
| 뿌리가 아닌 문답의 id(`parentRunId` 가 있다) | 404 — 사슬은 뿌리로만 연다 |
| 뿌리가 `done` 이 아님(대기 · 실패) | 404 — 목록에도 없다 |
| 뿌리의 채널을 지금 볼 수 없음 | 404 · 목록에서 빠짐 |
| 커서가 가리키는 사슬이 목록에 없음 | 빈 페이지 |
| `cursor` 가 문자열이 아님 · `limit` 범위 밖 | 400 (`PaginationDto`) |

`@MinRole` 을 걸지 않는다(판단 #9 — 읽기 라우트). `SpaceGuard` 는 컨트롤러에 이미 있다.

## 2. 서버

새 파일 `ai/ai-history.service.ts`(`AiHistoryService`) — `ai.service.ts` 가 이미 524줄이고,
읽기만 하는 일이라 적재 · 워커와 의존이 겹치지 않는다(Prisma · `ChannelsService` 만 쓴다).

### 사슬 끝 찾기 — 재귀 CTE 하나

```sql
WITH RECURSIVE roots AS (
  SELECT id FROM ai_runs
  WHERE space_id = $space AND user_id = $user AND parent_run_id IS NULL AND state = 'done'
    AND (input->>'channelId' IS NULL OR input->>'channelId' = ANY($viewable))
    [AND id = $rootRunId]                       -- 사슬 하나를 열 때
), t AS (
  SELECT r.id, r.id AS root_id, ARRAY[r.id] AS path, coalesce(r.finished_at, r.created_at) AS at
  FROM ai_runs r JOIN roots USING (id)
  UNION ALL
  SELECT c.id, t.root_id, t.path || c.id, coalesce(c.finished_at, c.created_at)
  FROM ai_runs c JOIN t ON c.parent_run_id = t.id
  WHERE c.state = 'done' AND c.space_id = $space AND cardinality(t.path) < 10
), tips AS (
  SELECT DISTINCT ON (root_id) root_id, id AS tip_id, path, at
  FROM t ORDER BY root_id, at DESC, id DESC
)
SELECT … FROM tips
WHERE $cursor IS NULL OR (at, root_id) < (SELECT at, root_id FROM tips WHERE root_id = $cursor)
ORDER BY at DESC, root_id DESC
LIMIT $limit + 1
```

- `path` 가 곧 보이는 사슬이다 — 사슬을 열 때 다시 거슬러 오르지 않는다
- **`now()` 를 쓰지 않는다**(시각 비교가 없다 — `check:sql-time` 대상 아님). id 를 `::uuid` 로 캐스팅하지 않는다(§3)
- `cardinality(t.path) < 10` 은 13-3 D5 의 상한이 지켜지지 않은 행이 있어도 끝없이 돌지 않게 하는 울타리다
- 그 뒤 뿌리 · 끝 행을 Prisma `findMany({ id: { in } , spaceId, userId })` 로 읽어 항목을 만든다(쿼리 셋)

### 순수 함수 `ai/ai-history.ts`

- `rootQuestionOf(input)` — `{ question, preset }`. 13-1 행(`instruction` 없음)은 `preset: 'summary'`. `ai.service.ts` 의 `rootRequestOf()` 를 이리로 옮겨 둘이 같은 것을 쓴다
- `previewOf(kind, result)` — 이슈 초안은 제목, 나머지는 `markdown` 앞 200자. 없으면 빈 문자열
- `contextOf(input)` — 목록용(`messageCount`)과 사슬용(`messageIds`) 두 모양

### `getRun` 모양 공유

`getRun` 의 select 와 `{ runId, …, id: undefined }` 변환을 `ai/run-view.ts`(`RUN_VIEW_SELECT` · `toRunView()`)로 뺀다. 사슬 읽기가 같은 모양을 써야 앱의 `AiRun.fromJson` 하나로 읽는다.

## 3. 앱

### 패널의 세 모드

```
입력  ──「지난 대화」──▶  목록  ──행 누름──▶  문답(13-3 의 목록 화면)
  ▲                        │                    │
  └────「새 질문」──────────┘                    └─「다시 묻기」→ 입력(되살린 칩으로)
```

- 입력 화면의 프리셋 줄 오른쪽에 ghost 버튼 **「지난 대화」**. 문답 화면 · 기다리는 중에는 없다(대화 중에 옮겨 가면 진행 중인 답을 버린 것처럼 보인다)
- 목록 화면: 머리 줄에 「← 새 질문」(입력으로, 원래 칩 그대로). 항목은 `NxRow` —
  제목 = 질문(프리셋이면 「요약」 · 「이슈 초안」), 아래 줄 = 미리보기 한 줄, 끝 = `#채널 · 문답 3 · 3시간 전`.
  비면 「지난 대화가 없습니다」. 실패면 문구 + 「다시 시도」. 다음 페이지가 있으면 「더 보기」
- 행을 누르면 그 행에 스피너 → `GET threads/:id` → 칩을 되살리고(D11) `_turns` 를 채워 문답 화면으로.
  실패하면 토스트(「대화를 열지 못했습니다」)와 목록에 머문다. 404 면 그 행을 목록에서 뺀다
- 다시 연 사슬은 **새로 묻는 사슬과 같은 코드를 탄다** — 이어 묻기의 부모는 `_turns.last` 다
- 패널 상태 `_sent` 에 기대던 저장소 · 원문 메시지 판정은 `_contexts` 하나로 읽는다(보낸 뒤 칩은 바뀌지 않는다 — 문답 화면의 칩은 읽기 전용)

## 5. 검증

### `check:ai` — `[19 AI 기록]` 갈래

| 케이스 |
|---|
| 처음엔 빈 목록 · `nextCursor: null` |
| 질문 → 이어 묻기 뒤 목록 한 줄: `turnCount 2` · 질문 · 미리보기가 끝 답 앞부분 · `context.channelId` · `messageCount` |
| 사슬 열기: `turns` 두 개가 뿌리부터 · 각 `instruction` · 끝의 `parentRunId` 가 뿌리 |
| 같은 부모에 다른 질문 둘(가지) → 늦은 쪽이 끝 · `turnCount` 2 · 열면 늦은 질문 |
| 다시 연 끝에 이어 묻기 → 그 사슬이 목록 맨 위로 · `turnCount` 3 |
| 정렬: 두 사슬 중 나중에 답을 받은 것이 위 · `limit=1` 커서로 둘째 페이지 · 끝은 `null` |
| 프리셋 요약 사슬 → `question: null` · `preset: 'summary'` |
| 실패한 뿌리는 목록에 없고 열면 404 |
| 다른 사용자: 목록에 없음 · 열면 404. 다른 스페이스 경로로 열면 404 |
| 뿌리 아닌 id 로 열면 404 |
| 비공개 채널 명단에서 빠지면 목록에서 빠지고 열면 404 · 다시 넣으면 다시 보임 |

새 케이스는 코드를 일부러 망가뜨려(정렬 뒤집기 · 가시성 필터 빼기 · 사용자 조건 빼기) 빨개지는지 한 번 본다(§5 빚의 규율).

### 단위

`rootQuestionOf`(13-1 행 · 프리셋 · 지시문) · `previewOf`(이슈 초안 · 200자 자르기 · 결과 없음) · `contextOf`.

### 앱

위젯 — 「지난 대화」로 목록 · 빈 목록 · 실패와 다시 시도 · 「더 보기」가 다음 커서로 · 행을 누르면 문답 둘이 보이고 칩이 되살아남 · 이어 묻기의 `parentRunId` 가 끝 문답 · 열기 실패 토스트 · 「새 질문」이 원래 칩으로.

**앱 통합 흐름(`app:flow`)에 AI 를 더한다** — 지금 흐름은 AI 패널을 한 번도 열지 않는다. 채널에서 AI → 자유 질문 → 이어 묻기 → 닫기 → 다시 열어 「지난 대화」 → 그 사슬을 열어 문답 둘. CI 서버는 `LLM_PROVIDER=fake` 라 결정적이다.

### 실제 태우기

실제 Gemini 로 사슬 하나를 만들고 패널을 닫았다가 「지난 대화」로 열어 이어 묻는다(Windows 앱).
