# 마크다운 — 설계

> 2026-08-21. 사용자가 글을 쓰는 **모든 곳**에 마크다운을 넣는다 — 채팅 ·
> 이슈 본문 · 이슈 댓글. Discord 를 기준으로 삼되 이 앱의 제약에 맞춘다.

지금은 본문이 평문이다. `**굵게**` 를 치면 별표가 그대로 보인다.

---

## 0. 가장 어려운 지점 — 멘션과 한 본문을 나눠 갖는다

본문에는 이미 `<@uuid>` 가 박혀 있고, 그것을 이름으로 바꿔 그리는 렌더러가
따로 있다([mention_text.dart](../../../app/lib/features/chat/mention_text.dart)).

**한 본문을 두 파서가 각자 쪼개면 위치가 어긋난다.** 마크다운 파서가 먼저
쪼개면 `<@uuid>` 가 조각 경계에 걸릴 수 있고, 멘션이 먼저 쪼개면 그 결과
안에서 `**` 를 다시 찾아야 한다.

**그래서 파서를 하나로 합친다.** 멘션은 **인라인 토큰의 한 종류**가 된다 —
볼드 · 코드 · 링크와 같은 층에서 다뤄진다.

**기존 멘션 테스트 34개가 계약이다.** `buildMentionSpans()` 는 새 인라인
파서를 부르는 얇은 어댑터로 남기고, 그 34개가 **고치지 않고 그대로 통과**하는
것을 첫 관문으로 삼는다. 잘 도는 기능을 갈아엎으면서 회귀를 눈으로만 확인하지
않겠다는 뜻이다.

---

## 1. 문법 범위

| 층 | 넣는 것 |
|---|---|
| **블록** | 코드블록(```` ```언어 ````) · 인용(`>`) · 목록(`-` · `1.`) · 제목(`#`~`###`) · **표** |
| **인라인** | `**볼드**` · `*이탤릭*`(`_이탤릭_`) · `~~취소선~~` · `` `코드` `` · `\|\|스포일러\|\|` · 링크 · **멘션** |

**인라인끼리 중첩한다**(볼드 안 이탤릭). **코드 안에서는 서식을 해석하지
않는다** — `` `**a**` `` 는 별표째로 보여야 한다. 그것이 인라인 코드의 존재
이유다.

**이미지는 넣지 않는다.** 첨부가 이미 그 자리를 맡고 있고(8-2 · 8-3), 마크다운
이미지를 허용하면 **남의 서버 주소를 본문에 박는 길**이 열려 추적 픽셀이 된다.

**블록 중첩도 넣지 않는다**(인용 안의 목록 등). 한 겹이면 파서가 줄 단위로
끝나고, 채팅에서 인용 안 목록을 쓰는 일은 드물다.

### 표 — 가로 스크롤로 감싼다

```
| 이름 | 값 |
|---|---|
| a | 1 |
```

채팅 폭이 좁아 열이 많으면 잘리는데, **잘린 채로 두면 내용을 볼 수 없다.**
표만 따로 가로 스크롤 컨테이너에 넣는다 — 메시지 전체가 가로로 밀리면 다른
줄까지 읽기 어려워진다.

정렬 행(`|:--|--:|`)은 파싱만 하고 **정렬은 적용하지 않는다.** 좁은 폭에서
정렬은 눈에 띄지 않고, 파서만 복잡해진다.

---

## 2. 두 층 파서

```
본문 ──▶ parseBlocks()  ──▶ [BlockNode]        (줄 단위)
                              └─ inline: [InlineNode]  ← parseInline()
```

**블록은 줄 단위, 인라인은 문자 단위.** 코드블록 안의 줄은 인라인 파서를 타지
않는다.

### 순수 함수다

파서는 위젯을 모른다. `String` 을 받아 노드 트리를 준다 — 그래야 **테스트가
화면 없이 돌고**, 같은 트리를 화면 · 평문화가 함께 쓴다.

### 흔한 경우를 빠르게 지나간다

메시지 목록은 스크롤할 때마다 다시 그린다. **서식 문자가 하나도 없는 본문은
파싱하지 않고 바로 텍스트 하나로 돌려준다** — 대부분의 채팅이 여기 해당한다.
기존 렌더러도 같은 최적화를 갖고 있었다(`mentions.isEmpty && !body.contains('@')`).

## 3. 저장 — 원문 그대로, 벗기는 것은 함수 하나

**서버는 지금처럼 원문을 저장한다.** 서버에서 HTML 로 바꿔 저장하면 렌더링
규칙을 바꿀 때 지난 메시지를 전부 다시 써야 하고, 원문이 사라져 편집도 못 한다.

그 대신 **`toPlainText(body)`** 를 둔다 — 서식 문자를 벗겨 한 줄로 만드는 순수
함수다. 쓰는 자리는 **한 줄로 줄여 보여주는 곳**뿐이다.

| 자리 | 왜 |
|---|---|
| 인용 요약(답장) | 본문 위에 접혀 한 줄로 보인다 |
| 대화 → 이슈의 제목 미리채움 | 제목에 `**` 가 들어가면 카드가 지저분해진다 |
| 알림 · 채널 목록 미리보기 | 앞으로 생길 자리 |

**검색은 원문으로 한다.** 사람이 검색어에 `**` 를 넣는 일은 없고, 벗긴 사본을
따로 저장하면 그것이 원문과 어긋나는 순간이 온다.

---

## 4. 렌더링

**위젯 하나를 셋이 함께 쓴다** — `MarkdownBody`. 채팅 · 이슈 본문 · 이슈 댓글이
같은 것을 부른다. 규칙이 갈라지면 "채팅에서는 되는데 이슈에서는 안 되는" 일이
생긴다.

```dart
MarkdownBody(
  body: message.body,
  mentions: message.mentions,
  fallbackNames: ...,   // 큐 · 인용 요약처럼 멘션 목록이 없는 자리
)
```

`shared/markdown/` 에 둔다 — `features/chat` 밑에 두면 이슈가 대화 기능에
의존하게 된다.

| 요소 | 어떻게 |
|---|---|
| 코드블록 | **1번에서 만든 `CodeLine` 을 재사용**한다. 언어 라벨을 위에 작게 |
| 인라인 코드 | 등폭 + 옅은 배경 |
| 인용 | 왼쪽 세로선 + 흐린 글자 |
| 목록 | 불릿 · 번호. 들여쓰기 한 단계 |
| 제목 | `#`~`###` 만. 채팅에서 `####` 는 본문과 구분이 안 된다 |
| 표 | 헤더 굵게 + 구분선. 가로 스크롤 |
| 스포일러 | **탭하면 드러난다.** 드러난 뒤에는 되돌리지 않는다 |
| 링크 | 액센트 색 + 탭하면 `url_launcher`. **`http`/`https` 만 연다** |

**링크 스킴을 제한하는 이유**는 `javascript:` 같은 것이 웹 빌드에서 실행될 수
있기 때문이다. 그 밖의 스킴은 평문으로 둔다.

**자동 링크 감지는 넣는다**(`https://…` 를 그냥 치면 링크가 된다). Discord 도
그렇고, 안 하면 사용자가 매번 `[]()` 를 써야 한다.

---

## 5. 입력 — 첫 조각은 렌더링만

툴바도 미리보기도 두지 않는다. **채팅은 짧고 즉시 보내는 글이라, 보내면 바로
렌더링된 것이 보이는 것 자체가 미리보기다.** 툴바는 모바일에서 입력창 위 한
줄을 영구히 먹는다.

**이슈 본문은 다르다** — 길고, 한 번 쓰고 오래 남고, 보내기 전에 확인하고
싶다. "쓰기 / 미리보기" 탭이 값을 하지만 **이 조각에는 넣지 않는다.**
렌더링이 자리를 잡은 뒤 붙인다.

`Ctrl+B` 같은 단축키도 뒤로 미룬다 — 데스크톱에서만 동작하고, 구현이 작아
나중에 얹기 쉽다.

## 6. 검증

**앱 테스트로 고정한다.** 서버는 바뀌지 않는다(원문을 그대로 저장한다).

| 갈래 | 케이스 |
|---|---|
| 회귀 | **기존 멘션 테스트 34개가 고치지 않고 통과** |
| 인라인 | 볼드 · 이탤릭 · 취소선 · 코드 · 스포일러 · 링크 · 중첩 |
| 코드 우선 | `` `**a**` `` 는 별표째로 남는다 |
| 멘션 결합 | `**<@id>**` 가 굵은 이름이 된다 · 코드 안의 `<@id>` 는 그대로 |
| 블록 | 코드블록 · 인용 · 목록 · 제목 · 표 |
| 닫히지 않음 | `**a` 는 별표째로 남는다(서식이 아니다) |
| 평문화 | 서식이 벗겨진다 · 코드블록은 한 줄로 접힌다 |
| 위젯 | 스포일러 탭 · 링크 스킴 제한 · 표 가로 스크롤 |

**"닫히지 않은 서식"이 특히 중요하다.** 사람이 `**` 를 하나만 치는 일이 흔한데,
그때 나머지 본문이 통째로 굵어지면 안 된다.

## 7. 범위에서 뺀 것

| 뺀 것 | 이유 |
|---|---|
| 이미지 | 첨부가 그 자리다. 추적 픽셀 통로가 된다(§1) |
| 블록 중첩 | 인용 안 목록 등. 파서가 크게 복잡해지고 쓰임이 드물다 |
| 표 정렬 | 좁은 폭에서 눈에 띄지 않는다(§1) |
| 입력 툴바 · 미리보기 · 단축키 | 렌더링이 먼저다(§5) |
| 서버 렌더링 · 정제 | 원문이 진실이다(§3) |
| 각주 · 정의 목록 · 수식 | 채팅에 쓰이지 않는다 |
