# 13-2 AI 패널 — 설계

> 2026-09-23. [13 AI 설계](2026-09-20-13-ai-design.md) 를 다시 연다.
> **13-1(고정 양식 요약)이 실제 Gemini 로 완주한 뒤**, 사용자가 쓸 수 있는
> AI 가 「정해진 세 항목 요약」 하나뿐이라 너무 좁다는 판단이 나왔다.
> 원래 스펙의 13-2(이슈 초안)와 13-3(코드 질의)을 **하나의 AI 패널**로 합친다.

이 문서가 원래 스펙의 **§7.2 · §7.3 · §9 · §11 을 대체한다.** 나머지(어댑터 ·
큐 · 캐시 · 실패 처리 · 소켓 · 전처리 — §1~§6 · §10)는 그대로 유효하고 이
문서는 거기에 기댄다.

---

## 0. 무엇이 바뀌나

| | 13-1 까지 | 13-2 |
|---|---|---|
| 요청 | 「요약」 하나. 지시문을 쓸 수 없다 | **자유 지시문**이 기본. 요약 · 이슈 초안은 프리셋 버튼 |
| 근거 | 고른 메시지 | 고른 메시지 · 채널 최근 대화 · **저장소 코드**(RAG) — 섞을 수 있다 |
| 진입 | 선택 모드 앱바 | 선택 모드 앱바 · 채널 헤더 · 저장소 화면 |
| 서버 경로 | `POST /ai/summarize` | **`POST /ai/ask` 하나** |

사용자가 원한 둘 — ① 양식에 묶이지 않은 요약 ② 코드·대화에 대한 질문 — 이
**같은 입력창 하나**로 된다. 「이 대화 영어로 세 줄 요약해」도 「이 대화에서
말한 버그가 코드 어디야?」도 지시문일 뿐이다.

### 정한 것

| # | 결정 | 이유 |
|---|---|---|
| D1 | **엔드포인트는 `POST /ai/ask` 하나.** `/ai/summarize` 는 지운다 | 컨텍스트 조합(대화만 · 코드만 · 둘 다)마다 경로를 늘리지 않는다. `summarize` 는 `main` 에 합쳐진 적이 없어 옛 클라이언트가 없다 — 별칭으로 남길 이유가 없다 |
| D2 | **프리셋은 서버의 프롬프트 템플릿이다.** 앱은 `preset` 이름만 보낸다 | 프롬프트가 클라이언트에 있으면 사용자가 서버 키로 임의 프롬프트를 쓰고 `promptHash` 규칙도 흔들린다 |
| D3 | 프리셋 둘 — `summary`(13-1 의 세 항목 요약) · `issue`(이슈 초안 JSON) | 자주 쓰는 요청을 타이핑하지 않게. 이슈 초안은 결과가 **이슈 생성 화면에 바로 채워지는** 가치가 있어 자유 질문으로 뭉개지 않는다 |
| D4 | `preset` 과 `instruction` 은 **둘 중 하나만** | 프리셋 + 덧붙인 지시는 그 자체로 자유 지시문이다. 둘을 섞는 규칙을 만들지 않는다 |
| D5 | 컨텍스트는 **최소 하나** 필요 | 패널은 늘 어떤 자리에서 열린다. 근거 없는 일반 질문은 이 제품의 AI 가 아니다 |
| D6 | 저장소 검색은 **요청 시점에** 하고 고른 청크 id 를 `input` 에 박는다 | 적재 때와 실행 때 검색 결과가 달라지면 캐시 키와 실제 프롬프트가 어긋난다. 인용도 이 청크에서만 나온다 |
| D7 | `search()` 가 **모델 불일치 · 미인덱싱이면 503** | 원래 스펙 §8 그대로. 이 단계가 「AI 가 검색을 부르는 모양」을 확정했으므로 CLAUDE.md §5 의 빚을 여기서 갚는다 |
| D8 | 이슈 초안은 **제목 · 본문만.** 라벨을 고르지 않는다 | 기존 생성 시트에 라벨 칸이 없다. 라벨 고르기는 생성 뒤 상세에서 이미 된다 |
| D9 | 멀티턴은 **이번에 만들지 않는다.** 대신 「다시 묻기」 가 같은 컨텍스트로 입력창을 되돌린다 | 사용자 결정(「단발로 시작, 멀티턴은 다음 단계」). `input` 이 자기완결이라 다음 단계는 `parentRunId` 하나를 더하면 된다 |
| D10 | `LLM_MAX_TOKENS` 기본값 **1024 → 2048** | 코드 질문 답은 코드 블록을 담는다. 1024 는 세 항목 요약에 맞춘 값이었다 |
| D11 | 5xx 재시도를 **60초 간격 3회 → 5초 · 10초 · … 간격 5회**로 (구현 중 추가) | 실제 태우기에서 Gemini 503 한 번이 답을 60~110초로 늘렸다. 사람이 패널 앞에서 기다리는 요청이라 인덱싱과 같은 간격일 이유가 없다. 네트워크 실패 · 헤더 없는 429 는 그대로 60초 |

## 1. API

```
POST /api/spaces/:spaceId/ai/ask
{
  instruction?: string,               // 1~2000자. preset 과 배타
  preset?: 'summary' | 'issue',       // instruction 과 배타
  context: {
    channelId?: string,               // 채널 대화
    messageIds?: string[],            // 1~200. channelId 필수
    repoId?: string,                  // 저장소 코드
  }
}
→ 201 { runId, state: 'queued' | 'done' }

GET /api/spaces/:spaceId/ai/runs/:runId      (13-1 그대로)
```

### 검증 — 전부 400

- `instruction` 과 `preset` 이 **둘 다 있거나 둘 다 없음**
- `instruction` 이 공백뿐이거나 2000자 초과
- `context` 에 `channelId` · `repoId` 가 **둘 다 없음**(D5)
- `messageIds` 가 있는데 `channelId` 가 없음
- `messageIds` 가 비었거나 200 초과(13-1 과 같은 상한)
- **`preset` 인데 대화 컨텍스트(`channelId`)가 없음** — 요약 · 이슈 초안은
  대화를 재료로 한다. 코드만으로 「이슈 초안」 을 만들면 지어낸다

DTO 는 class-validator 다. 배타 · 조건부 규칙은 데코레이터로 쓰기 어려워
**서비스에서 400 을 던진다** — 13-1 이 상한을 DTO 와 서비스 양쪽에서 본 것과
같은 자리다.

### 권한 — 13-1 규칙 그대로, 저장소가 하나 더

| 컨텍스트 | 확인 | 볼 수 없으면 |
|---|---|---|
| `channelId` | 공개이거나 `channel_members` 에 있다 | 404 |
| `messageIds` | 전부 그 채널 · 그 스페이스 것 | 404(일부만 요약하지 않는다 — 판단 #4) |
| `repoId` | 그 스페이스 것 | 404 |

`SpaceGuard` 만 건다. **`@MinRole` 없음**(판단 #9). 저장소 열람(10-3a)이
역할을 보지 않으므로 코드에 묻는 것도 보지 않는다.

### 503 이 셋

| 원인 | 언제 |
|---|---|
| LLM 미설정 | 13-1 과 같다. 다른 검증보다 먼저 |
| 임베딩 미설정 | `repoId` 가 있을 때만 |
| 저장소 인덱스가 현재 모델의 것이 아님 · 아직 없음 | `repoId` 가 있을 때만(D7, §4) |

## 2. 컨텍스트 조립

`input` 에 저장하는 모양 — **적재 시점에 확정된 것만 담는다**:

```ts
{
  instruction?: string,
  preset?: 'summary' | 'issue',
  channelId?: string,
  messageIds?: string[],      // 채널만 줬으면 서버가 고른 최근 메시지 id 가 여기 온다
  repoId?: string,
  chunkIds?: string[],        // 요청 시점 검색 결과(D6)
}
```

### 대화

- `messageIds` 가 있으면 그것(13-1 과 같다)
- **`channelId` 만 있으면 그 채널의 최근 최상위 메시지 50개**
  (`parentId IS NULL`, 채널 목록과 같은 기준). 고른 id 를 `input.messageIds`
  에 박는다 — 워커가 다시 「최근 50개」를 고르면 그사이 온 메시지 때문에
  프롬프트가 캐시 키와 달라진다
- 채널에 메시지가 하나도 없으면 400 — 빈 대화를 요약하게 하지 않는다

전처리는 13-1 의 `buildTranscript` 그대로다(멘션 치환 · 삭제 본문 없음 ·
첨부는 파일명만).

### 코드 (RAG)

```
검색어 → embed(query) → search(topK=8) → chunkIds 를 input 에
```

**검색어는 `instruction` 이다.** 프리셋은 대화 컨텍스트를 요구하므로(§1)
프리셋 + 저장소일 때 검색어는 **대화 원문의 마지막 2000자**다 — 대화가 무엇을
말하는지로 코드를 찾는다.

워커는 `chunkIds` 로 청크를 다시 읽는다. **하나라도 없으면 fatal** — 그사이
재인덱싱이 청크를 갈아 끼운 것이다. 조용히 빼고 답하면 인용이 빈다(판단
#4). 사용자는 같은 질문을 다시 누르면 새 검색으로 풀린다.

### 인용

결과의 `citations` 는 **LLM 이 아니라 우리가 채운다** — 원래 스펙 §7.3 그대로.
프롬프트에 청크를 `[1] 경로:시작-끝` 머리말로 번호를 붙여 넣고, 답에서
`[n]` 으로 가리키게 한다. 화면이 거는 링크는 우리가 넣은 청크뿐이라 LLM 이
지어낸 경로는 링크가 되지 않는다.

```ts
citations: Array<{ n: number, path: string, startLine: number, endLine: number, commitSha: string }>
```

## 3. 프롬프트

`prompts/` 에 셋. 전부 **순수 함수**다(결과가 곧 `promptHash` 의 입력이다).

| 파일 | 쓰는 곳 | 출력 |
|---|---|---|
| `summarize.ts` | `preset: 'summary'` | 13-1 그대로 — 세 항목 마크다운 |
| `issue.ts` | `preset: 'issue'` | JSON `{title, description}` |
| `ask.ts` | 자유 지시문 | 마크다운 |

`ask.ts` 의 system 은 짧게 규칙만 둔다: 한국어로(지시문이 다른 언어를
요구하면 그 언어로) · **주어진 자료만 근거로** · 자료에 없으면 없다고 말한다 ·
코드를 가리킬 때 `[n]` 을 붙인다. user 는 절 셋이다:

```
## 대화
[09:12] 앨리스: ...

## 코드
[1] lib/socket.dart:1-6
```dart
...
```

## 요청
<instruction>
```

없는 절은 싣지 않는다. 프리셋이 저장소를 함께 받으면 같은 `## 코드` 절이
프리셋 프롬프트의 user 에 덧붙는다.

**이슈 초안(`issue.ts`)**: `json: true`. 응답을 파싱해 `title` 이 비지 않은
문자열이고 `description` 이 문자열인지 본다. 아니면 **fatal**(원래 스펙 §5).
`title` 이 200자를 넘으면 200자로 자른다 — 사람이 생성 시트에서 확인하는
초안이고, 넘긴 채 두면 생성이 400 이 된다(판단 #4 의 「사람이 쓴 본문」
예외와 같은 성격).

온도는 셋 다 0.2 다. 자유 질문도 자료에 근거한 답이라 흔들 이유가 없다.

## 4. `search()` 가 엄격해진다 (D7)

원래 스펙 §8 을 그대로 구현한다.

| `repo.indexedEmbeddingModel` | `search()` |
|---|---|
| 현재 임베딩의 `modelId` 와 같음 | 정상 |
| 다름 | **503** 「임베딩 모델이 바뀌어 다시 인덱싱해야 합니다」 |
| `null` | **503** 「아직 인덱싱되지 않았습니다」 |

12단계의 `POST .../index/search` 도 같은 메서드라 함께 엄격해진다. 의도한
것이다. 이 판정은 청크 수와 상관없다 — 청크가 남아 있어도 모델이 다르면
그 벡터는 뜻이 없다.

## 5. 결과와 `kind`

`ai_runs.kind` 는 이미 있는 enum 셋을 그대로 쓴다 — **마이그레이션 없음.**

| 요청 | `kind` | `result` |
|---|---|---|
| `preset: 'summary'` | `summarize` | `{ markdown, citations }` |
| `preset: 'issue'` | `draft_issue` | `{ title, description, citations }` |
| `instruction` | `ask` | `{ markdown, citations }` |

`citations` 는 저장소 컨텍스트가 없으면 빈 배열이다(`null` 이 아니다 —
「인용이 없다」를 안다).

캐시는 13-1 그대로다(`spaceId` + `userId` + `promptHash` + `done`). 해시는
조립된 프롬프트 전문을 보므로 청크 내용 · 지시문 · 프리셋이 전부 섞인다.

## 6. 앱 — AI 패널

13-1 의 `ai_result_sheet.dart` 를 **`ai_panel.dart` 로 바꾼다.** 입력과 결과가
한 시트에 있다.

```
┌ AI ─────────────────────────────┐
│ [💬 메시지 12개 ×] [📦 nexus ×] [+ 저장소] │  ← 컨텍스트 칩
│ [요약] [이슈로 만들기]              │  ← 프리셋 (대화 칩이 있을 때만)
│ ┌───────────────────────────┐ │
│ │ 무엇이든 물어보세요            │ │  ← 지시문
│ └───────────────────────────┘ │
│                          [보내기] │
└─────────────────────────────────┘
      ↓ 보내면
  스피너 · 다시 확인 · 기다리지 않기      (13-1 그대로)
      ↓
  결과(마크다운) · 참고한 코드 [1] [2]…
  [채널에 붙이기] [복사] [다시 묻기]        자유 · 요약
  [이슈 만들기] [다시 묻기]               이슈 초안
```

### 진입 셋

| 자리 | 붙는 칩 |
|---|---|
| 채널 선택 모드 앱바의 **「AI」**(13-1 의 「요약」 을 바꾼다) | 메시지 n개 |
| 채널 헤더의 AI 아이콘 | #채널 최근 대화 |
| 저장소 들여다보기(`browse_screen`) 앱바의 AI 아이콘 | 저장소 |

- 칩은 **지울 수 있다.** 마지막 칩을 지우면 보내기가 꺼진다(D5, 판단 #7)
- **「+ 저장소」 는 채널에서 열었을 때만** 보인다 — 스페이스에 붙은 저장소
  목록(`spaceReposProvider`)에서 고른다. 저장소 화면에서 채널을 더하는 길은
  두지 않는다(저장소 화면은 셸 밖이라 「지금 채널」이 없다)
- 프리셋은 **대화 칩이 있을 때만** 눌린다(§1 의 400 을 화면이 먼저 막는다)

### 결과의 동작

- **「채널에 붙이기」** — 채널에서 열었을 때만. 13-1 그대로 평범한 메시지
  전송이다. 두 번 누름 방지도 그대로
- **「복사」** — 클립보드
- **「이슈 만들기」** — 기존 `showNewIssueSheet` 를 제목 · 본문을 채운 채로
  연다. 고른 메시지가 있으면 **첫 메시지를 `originMessageId`** 로 보낸다 —
  이슈에서 대화로 돌아오는 9-2b 의 링크가 그대로 산다. 시트에
  `initialTitle` · `initialDescription` 을 더한다
- **「다시 묻기」** — 같은 칩으로 입력 화면으로 돌아간다. 지시문은 비운다
- **참고한 코드** — `[n] 경로:시작-끝` 목록. 누르면 `browse` 를
  `?path=` 와 `?ref=<commitSha>` 로 연다 — 답이 근거로 삼은 **그 시점의**
  파일이다(10-3b 가 커밋 상세에서 같은 이유로 sha 를 넘겼다)

### 상태

`AiSummaryController` 를 **`AiController`** 로 일반화한다. 세대 토큰 · 소켓
완료 · 「다시 확인」 은 그대로이고, `run()` 이 `AiRequest`(지시문 · 프리셋 ·
컨텍스트)를 받는다. drift 에 넣지 않는 것도 그대로다(원래 스펙 §11).

`AiRun` 모델에 `title` · `description` · `citations` 를 더한다.

### 실패 문구

`aiMessageFor(failure, {hasRepo})`. `ApiFailure.server`(503 포함)이면서 저장소
칩이 있으면 「저장소 검색을 지금 쓸 수 없습니다. 인덱싱이 끝났는지 확인해
주세요.」 — 새 enum 을 만들지 않는다(13-1 의 판단 그대로). `badRequest` 는
「요청을 처리할 수 없습니다. 고른 범위를 확인해 주세요.」 로 일반화한다.

### `check:indexing` — 저장소 컨텍스트와 D7

코드 쪽은 가짜 GitHub 과 인덱싱된 저장소가 이미 있는 **`check:indexing` 에
넣는다.** `check:ai` 에 가짜 GitHub 을 또 띄우는 것보다 싸다. CI 는 이미
`LLM_PROVIDER=fake` 다.

| 케이스 |
|---|
| 인덱싱된 저장소에 자유 지시문 → 완주 · `citations` 가 비지 않고 **전부 그 저장소에 인덱싱된 경로** |
| 기록된 모델을 바꾼 상태에서 `index/search` 503 · `ai/ask`(repoId) 503 |
| 기록을 되돌리면 다시 200 |

기존 모델 변경 케이스(`check-indexing.mjs` «임베딩 모델이 바뀌면 전체로 떨어진다»)는
기록을 바꾼 뒤 검색을 부르지 않고 push 로 전체 재인덱싱만 확인한다 — 기대값이
바뀌지 않는다. 새 케이스는 그 절 **안에서**, 기록을 바꾼 직후 · push 전에 넣는다.

프롬프트 셋(순수 함수) · 이슈 JSON 파싱 · 요청 검증(배타 · 조건부) ·
`search()` 의 모델 판정.

### 앱

위젯 테스트 — 칩 지우기로 보내기가 꺼짐 · 대화 칩 없으면 프리셋 꺼짐 ·
결과의 인용 목록 · 이슈 결과에서 「이슈 만들기」 · 실패 문구가 서버 문구가

### 실제 태우기

**실제 Gemini 로 셋을 완주한다**: 자유 요약(「세 줄로」 같은 양식 밖 지시) ·
이슈 초안 JSON · 코드 질문. 코드 질문은 **가짜 GitHub 이 실제 소스 파일
몇 개를 서비스하고 임베딩은 `gemini` 로** 돈다 — 진짜 GitHub 저장소를 이
PC 에 다시 붙이지 않고도 「진짜 임베딩 + 진짜 LLM」 경로를 태울 수 있다.
확인할 것: 인용 번호가 실제로 맞는 청크를 가리키는지 · 응답 시간.
