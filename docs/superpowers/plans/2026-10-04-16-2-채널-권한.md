# 16-2 채널 수준 권한 · 스프린트 선택 기능 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱에서 채널을 만들고, 비공개 채널에 사람을 들이고 빼고, 역할별로 채널을 가리거나 읽기 전용으로 만들고, 스프린트를 스페이스마다 켜고 끈다.

**Architecture:** 판정은 `ChannelsService` 한 곳의 순수 함수 `channelAccess()` 로 모은다. 옛 `src/permissions/` 는 지우고 같은 자리에 권한 행을 읽고 쓰는 API 만 둔다. 출입 변경은 서버가 해당 소켓을 채널 룸에서 직접 뺀다(16-1 의 `evict`). 앱은 채널 목록의 `canSend` 를 drift 에 담아 입력창 · 메시지 동작을 가린다. 채널 설정 창은 16-1 의 스페이스 설정 창과 같은 틀(`SettingsFrame` · `SettingsNav`).

**Tech Stack:** NestJS · Prisma(마이그레이션 1) · Socket.IO / Flutter · Riverpod 3 · go_router · drift(schemaVersion 18)

**Spec:** [docs/superpowers/specs/2026-10-04-16-멤버-권한-design.md](../specs/2026-10-04-16-멤버-권한-design.md) — D15~D34 · §1 16-2 · §2 · §3 · §5

## Global Constraints

16-1 계획의 Global Constraints 를 그대로 따른다. 더해서:

- 마이그레이션은 `nexus-migration` 스킬 절차로 만들고 생성된 SQL 을 읽는다(HNSW 인덱스 `DROP` 금지 — `check:migrations`)
- 권한 행은 guest · member 두 역할만. 비공개 채널의 `canView=false` 는 400
- 읽기 전용 채널에서도 **리액션은 남긴다**(§3-9)
- drift 캐시 테이블을 고치므로 `schemaVersion` 17 → 18

### Task 2: 권한 API · 비공개 채널 멤버 API (`permissions` 재작성)

**Files:** Delete `server/src/permissions/**`; Create `server/src/permissions/{permissions.module,permissions.controller,permissions.service,channel-members.controller,channel-members.service}.ts` · `dto/{set-permission,add-channel-members}.dto.ts`; Modify `server/src/app.module.ts` · 두 `tsconfig*.json` 의 exclude

**Interfaces:**
- `GET/PUT/DELETE /api/spaces/:spaceId/channels/:channelId/permissions[/:role]` — admin+, `:role` ∈ guest|member(그 밖 400), 응답 `RolePermission[] = { role, canView, canSend, explicit }` 두 줄
- `GET/POST /api/spaces/:spaceId/channels/:channelId/members`, `DELETE …/members/:userId` — 설계 §1 16-2 표의 상태 코드 그대로
- 실시간: 권한 변경 → `canView=false` 가 되면 그 역할의 스페이스 멤버(채널 멤버 행이 있어도)를 채널 룸에서 `evict`, 그 뒤 스페이스에 `rooms:invalidate {reason:'channel.permissions'}`. 멤버 추가 → 대상마다 `rooms:invalidate {reason:'channel.members'}`. 제거 → 대상 `evict` + `rooms:invalidate`

- [ ] 판정은 `ChannelsService.assertCanView` 를 쓴다(볼 수 없으면 404). 멤버 추가는 member 이상(guest 403), 남 제거는 admin+, 마지막 한 명 409, 공개 채널 400
- [ ] 추가는 `createMany({ skipDuplicates: true })`(멱등). `userIds` 가 전부 스페이스 멤버인지 먼저 세고, 하나라도 아니면 404 로 아무도 넣지 않는다
- [ ] typecheck · lint · test

### Task 6: 읽기 전용 · 스프린트 가림(앱)

- 대화 화면 · 스레드 화면: `canSend == false` 면 입력창 자리에 「읽기 전용 채널입니다」. 메시지 동작 카드 · 호버 줄에서 답장 · 스레드로 답글 · 고정을 감춘다. 리액션 · 이슈로 만들기 · 여러 개 선택은 남긴다. AI 패널의 「채널에 붙이기」는 `onPost: null`
- 스프린트: 채널 판 갈래 · 보드 머리 줄 버튼 · 이슈 상세 스프린트 칸을 `space.sprintsEnabled` 로 가린다
- 「일반」 섹션에 「스프린트」 스위치(설명: 「이슈 보드에 스프린트 · 번다운을 보입니다. 꺼도 기록은 남습니다.」)
- 위젯 테스트: 읽기 전용 입력창 · 동작 카드 항목 · 스프린트 갈래 유무
