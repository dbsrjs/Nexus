# UI 리디자인 — 구현 계획

> **에이전트 작업자에게:** 이 계획은 `superpowers:subagent-driven-development`
> 또는 `superpowers:executing-plans` 로 task 단위로 실행한다. 단계는 체크박스
> (`- [ ]`)로 추적한다.

**Goal:** 디자인 언어를 토큰 층에 심고, 껍데기 둘을 하나로 합친다.

**Architecture:** 두 조각이다. **(가)** `tokens.css` · `theme.dart` 에 빠진
컴포넌트 테마 넷을 만들고 타이포·라운드를 고쳐 **화면 코드를 거의 건드리지
않고** 열 화면이 따라오게 한다. **(나)** `go_router` 의 `ShellRoute` 로
이슈 · 스프린트 · 파일 · 저장소를 셸 안으로 들이되, 스레드와 커밋은 원래
판단대로 덮어서 연다.

**Tech Stack:** Flutter 3.47 · go_router 17 · Material 3

**설계 문서:** [2026-08-22-UI-리디자인-design.md](../specs/2026-08-22-UI-리디자인-design.md)
**디자인 캔버스:** https://claude.ai/code/artifact/daaa8d16-8f3c-48f0-9b6c-419737f522e2

## Global Constraints

- **주석 · 커밋 메시지 · 문서는 전부 한국어.** 커밋에
  `Co-Authored-By: Claude` 를 넣지 않는다
- **색 값을 바꾸지 않는다.** `NexusColors` 의 어떤 상수도 건드리지 않는다.
  이번에 바꾸는 것은 타이포 · 라운드 · 컴포넌트 테마 · 구조뿐이다
- **`tokens.css` 가 원본이다.** `theme.dart` 는 그 이름을 그대로 따른다
  (그 파일 헤더의 약속). 둘을 **같이** 고친다
- **검증 플랫폼은 Windows 데스크톱.** 이 프로젝트에서 화면 계층은 실기기
  확인에만 기댄다 — 9-3 에서 서버만 만들고 화면을 빠뜨린 전례가 있다
- **회귀 관문**: `flutter analyze` **0건** · `flutter test` **218개** 유지
- **Flutter 3.47 의 테마 타입**: `cardTheme: CardThemeData` ·
  `chipTheme: ChipThemeData` · `listTileTheme: ListTileThemeData` ·
  `appBarTheme: AppBarThemeData` (SDK 에서 확인함)

### Task 3: `ShellRoute` 로 껍데기를 하나로

**Interfaces:**

- Produces: `AppShell({required Widget child})` — 본문을 라우터에서 받는다

- [ ] **Step 1: 지금 껍데기가 둘인 것을 확인한다**

```bash

```

나머지 라우트(`issues` · `sprints` · `files` · `repos*`)는 셸 없이 전체 화면이다.

- [ ] **Step 2: `AppShell` 이 본문을 받게 한다**

`app_shell.dart` 에서 `channelId` 로 본문을 스스로 고르던 것을 그만두고
`child` 를 받는다. **`_syncRoute()` 는 남긴다** — 스페이스·채널 id 를
컨트롤러에 싣는 일은 여전히 셸의 몫이다.

바꾸기 전:

```dart
class AppShell extends ConsumerStatefulWidget {
  const AppShell({super.key, required this.spaceId, this.channelId});

  final String spaceId;
  final String? channelId;
```

바꾼 뒤:

```dart
class AppShell extends ConsumerStatefulWidget {
  const AppShell({
    super.key,
    required this.spaceId,
    this.channelId,
    required this.child,
  });

  final String spaceId;
  final String? channelId;

  /// 본문. **무엇을 그릴지는 라우터가 정한다** — 셸이 탭으로 갈아 끼우면
  /// "라우트가 진실의 원천"이라는 이 셸의 전제가 깨진다.
  final Widget child;
```

`_DesktopShell` · `_CompactShell` 이 `child` 를 받아 `_Content()` 자리에
넣는다. `_Content` 위젯은 **지운다** — 채널이 없을 때의 안내는
`/s/:spaceId` 라우트가 그릴 화면으로 옮긴다(Step 3).

```dart
      Layout.desktop => _DesktopShell(child: widget.child),
      Layout.tablet => _CompactShell(showBottomTabs: false, child: widget.child),
      Layout.mobile => _CompactShell(
          showBottomTabs: true,
          tab: _tab,
          onTab: _onTab,
          child: widget.child,
        ),
```

- [ ] **Step 3: 라우터를 `ShellRoute` 로 바꾼다**

`/s/:spaceId` 아래를 통째로 감싼다. **`spaceId` 는 `state.pathParameters` 에서
읽고, `channelId` 는 대화 라우트일 때만 채워진다.**

```dart
      ShellRoute(
        builder: (context, state, child) {
          final spaceId = state.pathParameters['spaceId']!;
          return AppShell(
            spaceId: spaceId,
            // 대화 라우트에서만 채널이 열려 있다. 다른 갈래에서는 null 이라
            // 채널 목록의 선택 표시가 꺼진다.
            channelId: state.pathParameters['channelId'],
            child: child,
          );
        },
        routes: [
          GoRoute(
            path: '/s/:spaceId',
            builder: (_, _) => const ShellHome(),
            routes: [
              GoRoute(
                path: 'issues',
                builder: (_, state) =>
                    BoardScreen(spaceId: state.pathParameters['spaceId']!),
                routes: [
                  GoRoute(
                    path: ':issueKey',
                    builder: (_, state) => IssueDetailScreen(
                      spaceId: state.pathParameters['spaceId']!,
                      issueKey: state.pathParameters['issueKey']!,
                    ),
                  ),
                ],
              ),
              GoRoute(
                path: 'sprints',
                builder: (_, state) =>
                    SprintScreen(spaceId: state.pathParameters['spaceId']!),
              ),
              GoRoute(
                path: 'files',
                builder: (_, state) =>
                    FilesScreen(spaceId: state.pathParameters['spaceId']!),
              ),
              GoRoute(
                path: 'repos',
                builder: (_, state) =>
                    ReposScreen(spaceId: state.pathParameters['spaceId']!),
              ),
              GoRoute(
                path: 'repos/:repoId/browse',
                builder: (_, state) => BrowseScreen(
                  spaceId: state.pathParameters['spaceId']!,
                  repoId: state.pathParameters['repoId']!,
                  initialRef: state.uri.queryParameters['ref'],
                  initialPath: state.uri.queryParameters['path'],
                ),
              ),
              GoRoute(
                path: 'c/:channelId',
                builder: (_, _) => const ChatScreen(),
              ),
            ],
          ),
        ],
      ),
```

**`state.pathParameters['channelId']` 가 `ShellRoute` 빌더에서 채워지는지는
가정하지 말고 확인한다.** go_router 의 `ShellRoute` 빌더는 현재 매치의
`state` 를 받지만, 자식 라우트의 path 파라미터가 거기 실리는지는 버전에
따라 다를 수 있다. 아래 한 줄을 잠시 넣어 확인한다:

```dart
          debugPrint('셸 상태: path=${state.uri.path} params=${state.pathParameters}');
```

```dart

  /// 이전에는 보드만 `push` 로 덮어서 열었고, 나머지 둘(알림 · 내정보)은
  /// 아무 데도 가지 않아 눌러도 화면이 그대로였다.
  void _onTab(int index) {
    final base = '/s/${widget.spaceId}';
    switch (index) {
      case 0:
        // 마지막으로 보던 채널로. 없으면 셸 홈.
        final channelId = widget.channelId;
        context.go(channelId == null ? base : '$base/c/$channelId');
      case 1:
        context.go('$base/issues');
      case 2:
        context.go('$base/repos');
      case 3:
        context.go('$base/files');
    }
  }
```
