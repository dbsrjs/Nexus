# 13-2 AI 패널 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (이 세션 인라인 실행으로 정했다). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 고정 양식 요약 하나뿐이던 AI 를, 컨텍스트(메시지 · 채널 · 저장소)를 조합해 자유 지시문 또는 프리셋(요약 · 이슈 초안)으로 묻는 AI 패널로 넓힌다.

**Architecture:** 서버는 `POST /ai/ask` 하나가 요청을 검증 · 컨텍스트 조립(대화 transcript + 저장소 검색 청크) · 프롬프트 조립 후 13-1 의 `ai_runs` 큐 · 캐시 · 소켓에 그대로 태운다. 프롬프트 조립은 순수 함수 `buildAskPrompt()` 하나로 모아 적재와 워커가 같은 것을 부른다. 앱은 결과 시트를 입력+결과를 가진 `AiPanel` 로 바꾸고 세 자리에서 연다.

**Tech Stack:** NestJS · Prisma · class-validator · Jest / Flutter · Riverpod · freezed

**Spec:** `docs/superpowers/specs/2026-09-23-13-2-ai-패널-design.md` (옛 `2026-09-20-13-ai-design.md` §1~§6 · §10 이 여전히 유효)

## Global Constraints

- 모든 쿼리에 `spaceId`. 볼 수 없으면 404(403 아님). `@MinRole` 없음
- `instruction` 1~2000자 · `messageIds` 1~200 · 채널 최근 대화 50개(`parentId IS NULL`) · 검색 `topK=8`
- 프리셋 `summary` → kind `summarize`, `issue` → `draft_issue`, 지시문 → `ask`. **마이그레이션 없음**
- `citations` 는 검색 청크에서만. 저장소 컨텍스트가 없으면 `[]`
- 이슈 초안 JSON 파싱 실패 · 빈 제목은 fatal. 제목 200자 초과는 자른다
- `LLM_MAX_TOKENS` 기본 2048. 온도 0.2
- 커밋: 제목 명사형(`추가` · `수정` · `삭제`), 본문 개조식(~함), `Co-Authored-By` 금지, 저자 사용자
- 앱: 서버 오류 문구를 쓰지 않는다 · 새 `ApiFailure` enum 값을 만들지 않는다 · AI 상태는 drift 밖
- `\u0000` 을 Edit/Write 인자에 쓰지 않는다(실제 NUL 이 된다) — 커밋 전 NUL 0 확인

### Task 2: 요청 검증 `ask-request.ts` + DTO

**Interfaces — Produces:**
```ts
export type AskPreset = 'summary' | 'issue';
export interface AskRequest {
  instruction: string | null; preset: AskPreset | null;
  channelId: string | null; messageIds: string[] | null; repoId: string | null;
}
export const MAX_INSTRUCTION = 2000;
export function validateAskRequest(dto: AskDto): AskRequest  // BadRequestException
```

```ts
export interface Citation { n: number; path: string; startLine: number; endLine: number; commitSha: string }
```

- [ ] 실패 테스트: 절 생략 · 번호 · 펜스 길이 · 순수성(같은 입력 같은 출력) · kind 매핑 셋 · issue 는 json=true · `parseIssueDraft` — 정상 · 코드펜스로 감싼 JSON · 빈 제목 · 문자열 아님 · 201자 제목 자름

### Task 4: `AiService.ask()` + `loadPrompt()` + 러너 + 컨트롤러

**Interfaces — Consumes:** Task 1~3. **Produces:**
- `AiService.ask(spaceId, userId, dto: AskDto): Promise<StartResult>`
- `AiService.loadPrompt(spaceId, input): Promise<PreparedPrompt>` — `{ kind, messages, json, citations }`
- 저장되는 `input`: `{ instruction?, preset?, channelId?, messageIds?, repoId?, chunkIds? }`
- `POST /spaces/:spaceId/ai/ask`, `summarize` 경로 · DTO 삭제
- `AiModule` 의 `ReposModule` import 로 `IndexingService` 주입

흐름(`ask`): `requireLlm` → `validateAskRequest` → 채널이면 `requireChannel`(가시성) → 메시지(고른 것 or 최근 50, 없으면 400) → transcript → 저장소면 `indexing.search(spaceId, repoId, query, 8)`(query = instruction ?? transcript 끝 2000자) → `buildAskPrompt` → `start(kind, input, messages)`.
`loadPrompt`: input 에서 messageIds 로 메시지 재조회(개수 불일치 fatal 아님 — 13-1 과 같이 있는 대로), chunkIds 로 `chunksByIds`, 개수 다르면 `Error('참고한 코드가 다시 인덱싱되어 사라졌습니다')`(fatal).
러너: `complete(messages, {maxTokens, temperature, json})` → 빈 응답 fatal → `resultOf(kind, text, citations)`: issue 면 `parseIssueDraft` 로 `{title, description, citations}`, 그 밖 `{markdown, citations}`.
