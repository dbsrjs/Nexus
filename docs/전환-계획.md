# Nexus — 전환 계획

> 기존 "사내 통합 개발 환경" 코드에서 새 구조로 옮기기 위한 실행 목록.
> 방향은 [제품 기획서](./제품-기획.md), 설계는 [백엔드 설계](./백엔드-설계.md) · [앱 설계](./앱-설계.md).

## 0. 전제

- 커밋이 **초기 커밋 1개**뿐이고 운영 데이터가 없다. → 마이그레이션을 이어붙이지 않고 **리셋**하는 게 훨씬 싸다.
- 작업은 `main`에서 직접 하지 말고 `feat/pivot-nexus` 브랜치에서 진행한다.

## 2. 새 최상위 구조

```
nexus/
├─ app/            Flutter — 모바일 · 데스크톱 · 웹        ← 신규 (아직 없음)
├─ server/         NestJS 백엔드                          ← 개편
├─ design-system/  토큰 · 컴포넌트 · 화면 프리뷰 (HTML)
├─ docs/           기획 · 설계
│  └─ archive/     구 사내 UI 디자인 소스 (참고용)
└─ README.md
```

루트 `package.json`은 서버 개발 편의 스크립트만 남긴다. (Flutter 쪽은 `flutter` CLI를 직접 쓴다.)

### 3.4 기존 모듈 이관

> **미이관 모듈은 현재 빌드에서 빠져 있다.** 스키마를 재작성한 순간 이 모듈들은
> 사라진 모델·필드를 참조하게 되어 컴파일되지 않는다. 3단계 이후에 하나씩
> 고칠 것이므로 **소스는 `src/` 에 그대로 두고** `tsconfig.json` ·
> `tsconfig.build.json` 의 `exclude` 로 컴파일 대상에서만 뺐다.
> 대상: `channels` `messages` `realtime` `permissions` `notifications` `files`
> `issues` `gitlab` `ai`.
>
> 되살리는 절차 — ① 두 tsconfig 의 `exclude` 에서 경로 삭제 → ② `spaceId` 기준으로
> 코드 수정 → ③ `app.module.ts` 의 `imports` 에 다시 등록.

- [ ] 모든 컨트롤러 라우트를 `/spaces/:spaceId/…` 아래로
- [ ] 모든 서비스 메서드 시그니처에 `spaceId` 첫 인자 추가
- [ ] `channels` — 카테고리 · 읽음 마커 실제 저장

**2단계에서 함께 고친 것 (위 표에 없던 것)**

| 문제 | 조치 |
|---|---|
| `GET /api/users` 가 전역 사용자 목록을 반환 — 멀티테넌트에서 다른 스페이스 사용자까지 노출 | 엔드포인트 제거. 사람 목록은 `GET /api/spaces/:spaceId/members` 로만 |

| 전역 `Role` 이 JWT 페이로드에 박혀 있어 역할 변경이 토큰 만료 전까지 반영되지 않음 | 토큰에서 역할 제거. 매 요청 `SpaceGuard` 가 DB에서 읽는다 |
| `.env.example` 의 `change-me` 값이 그대로 복사돼 배포될 수 있음 | 필수 시크릿은 **빈 값**으로 두어 부팅이 실패하게 함 |

## 6. 실행 순서

전환은 아래 순서를 지킨다. 특히 **스페이스 도입(2단계)이 다른 모든 서버 작업의 선행 조건**이다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| ~~**1**~~ ✅ | 기존 자산 정리 (§1 삭제 · 아카이브), 루트 구조 재편 | 빈 슬레이트 |
| ~~**2**~~ ✅ | 스키마 재작성 + auth 개편 + `spaces` + `SpaceGuard` | 멀티테넌시 골격 |
| **3** | channels · messages 이관 + 스레드 · 리액션 · 멘션 | 채팅 API 완성 |
| **4** | realtime 개편 (§3.5의 2·3·4번 포함) | 실시간 완성 |
| **5** | Flutter 스캐폴드 → 인증 → 셸 → 채널 → 메시지 | **처음으로 눈에 보이는 앱** |
| **6** | drift 캐시 + 소켓 연동 + catch-up | 실사용 가능 (Phase 0 달성) |
| **7** | attachments · issues | |
| **8** | repos (웹훅) · ai | 차별점 완성 |
| **9** | 푸시 · 트레이 · 딥링크 · CI | Phase 1 준비 완료 |

**5단계에서 처음으로 실제 앱을 보게 된다.** 그 전까지는 서버만 쌓이므로, 중간에 확인이 필요하면 4단계 이후 서버 API를 먼저 검증하는 게 좋다.
